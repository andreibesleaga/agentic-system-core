# AGSC-11 — The node boundary: cross-origin access, federation, contribution, surfaces, visibility, retirement

**Status: NORMATIVE** (§8 of `docs/SPEC.md` applies; the chapter has been normative since `1.0.0-rc.6`, the first public version). This chapter governs everything that happens where a node meets another node, a browser, a stranger's URL, or a reader who may not see everything. That boundary is specified once, here, and cited from the other chapters rather than restated. Rules are `AGSC-11-nn`; vectors live in `tests/vectors/boundary/` (area `boundary`, ids `bnd-nnnn`); new codes are registered in §9.4 under their existing areas (`2` SCHEMA, `3` LINK, `4` LINT, `9` IO) — no new code area exists.

## 11.1 Scope, parameters and extensibility

- **AGSC-11-01** Every numeric or enumerated parameter of this chapter is carried in `agsc.config.json` under the OPTIONAL objects `federation{hop_limit, fan_out, max_requests, redirect_limit, timeout_ms, max_bytes}`, `chunks{max_bytes}`, `contribute[]{mode, target, channel}` and the OPTIONAL key `visibility`, each admitted by `config.schema.json` (AGSC-01-18). **The whole bound table, so that an implementer needs one rule and not four** (AGSC-11-06, AGSC-06-27 and AGSC-01-34 remain the homes of the prose that explains each):

  | key | minimum | default | maximum |
  |---|---|---|---|
  | `federation.hop_limit` | 0 | 3 | 5 |
  | `federation.fan_out` | 1 | 50 | 200 |
  | `federation.max_requests` | 1 | 500 | 2000 |
  | `federation.redirect_limit` | 0 | 3 | 5 |
  | `federation.timeout_ms` | 100 | 10000 | 60000 |
  | `federation.max_bytes` | 65536 | 33554432 | 268435456 |
  | `chunks.max_bytes` | 256 | 4096 | 65536 |
  | `attachments.max_bytes` | 1024 | 1048576 | 10485760 |
  | `budget.usd_month` | 0 | 10 | — (no maximum) |

  The default applies when the key is absent. A publisher MAY set any value from the minimum up to and including the maximum and MUST NOT exceed it; a MINOR `spec_version` MAY change a default or a maximum; `x-<vendor>-<key>` members are admitted on each of these objects exactly as on `channels[]` (AGSC-01-18). An out-of-range or malformed value is `AGSC-E209`. [PRD-019, PRD-057]
- **AGSC-11-02** Every enumerated value introduced by this chapter — `visibility`, `agsc-contribute-mode`, `agsc-surface`, `agsc-access` — tolerates reserved values per AGSC-00-15: a 1.x reader that meets a value it does not know MUST NOT fail and MUST treat the unknown as the **most restrictive** member of that list (`restricted`, "not contributable", "not served", `credential`). This tolerance governs a **reader of documents it did not author** — discovery documents, peer boards, files under `import` or `--peer`; a node's **own** configuration and frontmatter are validated closed by the schemas (`AGSC-E203`), because a publisher MUST NOT emit a value its declared `spec_version` does not define. New members arrive only by MINOR with a vector. [AGSC-00-14/15]

## 11.2 Cross-origin access

- **AGSC-11-03** When `visibility` is `public` (the default, AGSC-11-20) every public artefact — `/.well-known/knowledge-linkset`, `/graph.jsonld`, `/graph.ttl`, `/graph.nq`, `/ns/context.jsonld`, `/llms.txt`, `/llms-full.txt`, `/chunks.jsonl`, `/ledger.jsonl`, `/search.json` and its shards, `/pages/*.md`, `/pages/*.jsonld`, `/skills/**`, `/now.md`, `/boards/**`, `/attachments/**`, the `/ns/` files and `/graph/fragments/**` (every artefact of AGSC-06-01 other than HTML pages) — MUST be served with `Access-Control-Allow-Origin: *` and `Access-Control-Expose-Headers: Link, ETag, Content-Type`, and MUST NOT be served with `Access-Control-Allow-Credentials`. `_headers` (AGSC-06-17) carries these. A node MUST NOT require any request header outside the CORS-safelisted set to obtain any public artefact, so that a browser agent can read it with a simple request. [PRD-057]
- **AGSC-11-04** The RFC 6906 profile of the discovery document is carried primarily by the media-type `profile` parameter (AGSC-06-17) and secondarily by a `Link: …; rel="profile"` response header (AGSC-06-07); a consumer MUST accept either, and conformance MUST NOT differ between a client that can read response headers and one that cannot (a browser under CORS reads the media type in every case). [design]
- **AGSC-11-05** A Level ≥ 2 writer **SHOULD** emit on `/` the response header `Link: </.well-known/knowledge-linkset>; rel="describedby"; type="application/linkset+json"` (the registered relation of AGSC-06-25), and MAY emit it on any other page, as AGSC-06-25 says. *(Rationale: the header is a SHOULD and not a MUST because AGSC-11-04 requires conformance not to differ between a client that reads response headers and one that cannot, and a host that carries no header configuration must still be able to reach Level 2. The `<head>` element of AGSC-06-25 remains the MUST.)* It MUST send an `ETag` on every public artefact; where the writer sets the value, it is the artefact's lowercase-hex SHA-256 **enclosed in double quotes** (RFC 9110 §8.8.3), and a reader MUST NOT treat an `ETag` as an integrity statement — an intermediary may weaken or replace it, and the `digest` of AGSC-06-08 is that statement *(Rationale: a static host sets its own entity tags, and a CDN weakens a strong one when it recompresses.)*; `Cache-Control: public, max-age=31536000, immutable` is RESERVED for digest-named asset paths, which no 1.0 route of AGSC-06-01 has, so a 1.0 node emits it nowhere; and `Cache-Control: no-cache` on `/.well-known/knowledge-linkset`, `/now.md` and `/ledger.jsonl`. A Level-0 publisher SHOULD do the same. [PRD-062]

## 11.3 Federation — eight parts (F1, F2, F4–F9), all static, all client-side

*The label F3 is not used: it would name a node-side query endpoint, which AGSC-11-13 excludes — a node's query surface is its published dumps and a node MUST NOT expose an endpoint that fetches on a caller's behalf.*

*Principle, stated once and reused everywhere: the discovery document is the federation protocol; nodes never call nodes; the client federates. A build reads no peer (AGSC-04-03); only `verify --peer` (AGSC-10-12) and a consumer's client ever fetch across origins.*

- **AGSC-11-06** **F1/F2 — declaration and mutual conformance.** Peers are declared in `peers[]` (AGSC-01-18), published as `…/rel#peer` links (AGSC-06-10) and checked mutually by `validate-wellknown --peer` (AGSC-10-12). This rule names the two existing halves so that the remaining parts have a fixed referent, and is the single home of the federation parameters. Defaults for the walk of AGSC-11-10: `federation.hop_limit` **3** (maximum 5), `federation.fan_out` **50** (maximum 200), `federation.max_requests` **500** (maximum 2000), `federation.timeout_ms` **10000** (maximum 60000). [design]
- **AGSC-11-07** **F4 — transport.** Every peer fetch — by `verify --peer`, by a channel responder, by any client this specification describes — MUST use an absolute URL whose scheme is `https`. `http` is permitted **only** to a loopback address (`127.0.0.0/8`, `::1`) and only when the invocation carries `--dev`. Any other scheme (`file`, `ftp`, `data`, `javascript`, `gopher`, `ws`, …) or any relative reference is `AGSC-E905`. [PRD-057]
- **AGSC-11-08** **F4 — addresses.** Before connecting, the fetcher MUST resolve the host with the platform resolver and MUST refuse, with `AGSC-E905`, any resolved address in: any address in the following **closed normative list**, derived from the IANA IPv4 and IPv6 Special-Purpose Address Registries as read on 2026-09-17 — every prefix whose *Globally Reachable* value is not `True`, **plus every prefix that embeds an IPv4 address whatever its registry value** (an embedded address can be loopback) and the multicast ranges — a MINOR updates it when the registries change: IPv4 `0.0.0.0/8`, `10.0.0.0/8`, `100.64.0.0/10`, `127.0.0.0/8` (except under `--dev`), `169.254.0.0/16`, `172.16.0.0/12`, `192.0.0.0/24`, `192.0.2.0/24`, `192.88.99.0/24`, `192.168.0.0/16`, `198.18.0.0/15`, `198.51.100.0/24`, `203.0.113.0/24`, `224.0.0.0/4`, `240.0.0.0/4`, `255.255.255.255/32`; IPv6 `::/128`, `::1/128` (except under `--dev`), `::/96` (IPv4-compatible, checked as the embedded IPv4), `::ffff:0:0/96` (IPv4-mapped, checked as the mapped IPv4), `64:ff9b::/96` and `64:ff9b:1::/48` (NAT64, checked as the embedded IPv4), `100::/64`, `100:0:0:1::/64`, `2001::/32` (Teredo, checked as the embedded IPv4), `2001:2::/48`, `2001:10::/28`, `2001:db8::/32`, `2002::/16` (6to4, checked as the embedded IPv4), `3fff::/20`, `5f00::/16`, `fc00::/7`, `fe80::/10`, `fec0::/10`, `ff00::/8`. Address classification MUST use a well-tested library or the platform's classification; an implementation MUST NOT hand-parse address literals. A host that resolves to several addresses is refused if **any** is in the list. **The fetcher MUST connect to one of the addresses it classified** — never re-resolve between check and connect — and MUST re-verify the socket's remote address against the same list once the connection is established, closing it with `AGSC-E905` on a mismatch (the DNS-rebinding guard). [design]
- **AGSC-11-09** **F4 — redirects.** A fetcher MUST follow at most `federation.redirect_limit` redirects (default **3**, maximum 5, AGSC-11-06), MUST re-apply AGSC-11-07 and AGSC-11-08 to every hop, MUST NOT follow a redirect to a non-`https` URL except the `--dev` loopback case, and MUST report `AGSC-E905` when any hop fails. The final URL of a redirected peer fetch is NOT substituted for the declared peer URL in any mutual check. [design]
- **AGSC-11-10** **F4 — the walk.** A client that traverses peers from a starting node MUST: (a) bound depth by `federation.hop_limit`, the starting node being depth 0; (b) consider at most `federation.fan_out` `rel#peer` links per discovery document, in document order, ignoring the rest; (c) issue at most `federation.max_requests` requests per walk, counting every request including redirects; (d) keep a visited set keyed by the canonical well-known URL and never fetch a member twice — the cross-origin cycle guard; (e) treat a peer whose fetch times out after `federation.timeout_ms`, returns a non-2xx status, exceeds 1 MiB (the input cap of AGSC-01-16 applies to a fetched discovery document), or yields a document that fails AGSC-06-08 as **unreachable**: record `AGSC-E907` for that peer, skip it, and never retry it within the walk. A walk that ends because (a) the hop limit is reached while unvisited peer links remain, or (b) links beyond `fan_out` were ignored in any document, or (c) the request budget is spent, reports `AGSC-E906` and `partial: true` with the peers visited; a walk that completes without touching any of the three caps reports `partial: false` and no code. The number of requests is therefore bounded by `min(max_requests, Σ_{i≤hop_limit} fan_out^i)`; and **(f)** apply the same caps to **every** cross-origin fetch this specification describes, not only to a discovery document: at most `federation.timeout_ms` per response, at most 1 MiB for a discovery document and at most `federation.max_bytes` (AGSC-11-01) for any other artefact — a `rel#graph`, `rel#ledger`, `rel#context` or `agsc-surface` target among them — measured on the **decoded** stream, so that a compressed response cannot expand past the bound, and aborted at the bound with `AGSC-E907`. *(Rationale: without these caps a hostile peer could serve a 50 GB `graph.nq` or a compression bomb and the walk would never return.)* [PRD-057]
- **AGSC-11-11** **F5 — trust across nodes.** Every result derived from a peer's artefacts — a search hit, a read, a chunk, a cited answer — MUST carry `trust: "untrusted"` and an `origin` member equal to the peer's Bundle IRI (AGSC-05-03) in the AGSC-08-18 envelope, end to end, through every surface of §9 and every export of §06. A node MUST NOT copy peer prose into its own items except through a Proposal (§08), which marks it `prov.origin: imported` with the peer IRI in `sources[]`. [design]
- **AGSC-11-12** **F6 — cross-node citation, never a cross-node Link.** A Link key value is a slug (AGSC-03-02); a value that parses as an absolute URL is `AGSC-E311` and the file is invalid. Cross-node reference is by citation through the item's one citation array, `sources[]` (AGSC-02-10; the `references[].url` of PRD-057 denotes `sources[].resource` — there is no second array): when a `sources[].resource` value begins with the **base of a declared peer**, which is derived syntactically from the `peers[]` entry by removing the trailing `.well-known/knowledge-linkset` (so that no fetch is needed at build, AGSC-04-03), the graph exports MUST emit `<item-IRI> rdfs:seeAlso <normalised-url>` and `<item-IRI> asc:peerOrigin <peer-Bundle-IRI>`. The object IRI MUST be normalised exactly as: the host converted to its A-label form under IDNA 2008 with UTS #46 **non-transitional** processing (a host containing a code point unassigned in Unicode 16.0.0 is `AGSC-E312` — the repertoire, not a table version, is what a port can check), `UseSTD3ASCIIRules=false`, and the Unicode tables of AGSC-04-22, the scheme and host lower-cased, existing percent-escapes preserved byte-for-byte and never re-encoded, no path or fragment removed; a value that cannot be parsed as an IRI after that step, or that contains a character N-Quads cannot carry unescaped in an IRIREF (`<`, `>`, `"`, `{`, `}`, `|`, `^`, a backtick, `\`, a space or any other character at or below U+0020 — none of which is a legal IRI character, RFC 3987 §2.2), is `AGSC-E312` (a lint error; the reference is omitted from the graph, and AGSC-05-32 never has to escape an IRI). Closure, hiding, exclusion and warnings (§07) are computed over one Bundle; a `seeAlso` edge takes part in none of them. The Link key name **`peer-ref`** is RESERVED for a future MINOR and, if authored at 1.x, is reported as an unknown link key (`AGSC-E304`) and preserved. [design]
- **AGSC-11-13** **F7 — federated query.** A node's query surface is its published dumps (`/graph.nq`, `/graph.ttl`, `/graph.jsonld`, `/chunks.jsonl`, `/search.json`) and, where emitted, the static fragments of §06; a consumer federates **client-side** over several nodes' dumps. A node MUST NOT fetch another node during `build` and MUST NOT expose any endpoint that fetches on a caller's behalf at Level ≤ 3. *(Non-normative: this places every node at the data-dump end of the Linked Data Fragments spectrum by design; the implementer's guide carries one SPARQL 1.1 example over two dumps.)* [design]
- **AGSC-11-14** **F8 — contribution from anyone.** When `contribute[]` is configured, the discovery document MUST carry one `…/rel#contribute` link per entry, whose target is the entry's `target` (an `https:` URL for `pr` and `form`, a `mailto:` URI or an `urn:agsc:channel:<name>` for `channel`) and whose target attribute `agsc-contribute-mode` is a one-element array `["pr"]`, `["channel"]` or `["form"]`. A `propose` implementation (AGSC-09-13, AGSC-09-16) directed at a foreign node MUST read that node's discovery document and use the first `contribute` link whose mode it supports; with none, it MUST return the Proposal payload to the caller and perform no network write. A `channel` target MUST be backed by a `channels[]` entry whose `publish` is `hitl`; `auto` is NOT permitted for a contribute channel, and every AGSC-01-30 guard (`allow[]`, `rate{per_hour}`, the five-open-Proposals cap, injection lints at error severity) applies unchanged. For a `mailto:` target, `channels[].allow[]` MUST NOT be treated as an authorisation control unless the adapter verifies DKIM or SPF alignment of the `From:` domain (an unverified sender is handled as anonymous), and the de-duplication `source_id` (AGSC-01-33) MUST be derived by the adapter from the message envelope (a digest of `Message-ID` and `From:`), never taken from message content. A malformed `contribute[]` entry is `AGSC-E209`. [PRD-058]
- **AGSC-11-15** **F9 — federated boards.** The project-mode export (§10) is per node; a client merging boards MUST key tasks by item IRI and boards by Bundle IRI and MUST NOT rename either. [design]

## 11.4 The plugin contract — every agent surface is a declared plugin

- **AGSC-11-16** **DECLARE.** The discovery document MUST carry one `…/rel#surface` link per agent surface the node serves, and no link for a surface it does not serve. The target is the surface's entry: `/llms.txt` for `llms-txt`, `/chunks.jsonl` for `chunks`, `/compose/` for `webmcp`, the local server's documentation route `/specs/mcp/` for `mcp`, the card URL for `a2a-card`, the pod URL for `solid`, the remote transport URL for `responder`. Target attributes: `agsc-surface` (one value from `llms-txt`, `chunks`, `mcp`, `webmcp`, `a2a-card`, `solid`, `responder`, or an extension `x-<vendor>-<name>`), `agsc-surface-version` (REQUIRED for `mcp`, `webmcp`, `a2a-card`, `solid` and `responder`, absent for `llms-txt` and `chunks`; one value: the external revision the node targets — for `mcp`, the revision the node's transport actually speaks, in the protocol's `YYYY-MM-DD` form, revision `2026-07-28` being the target and not a pin (a transport that speaks an earlier revision, such as `2025-11-25`, declares that revision); for `webmcp`, the `YYYY-MM-DD` date of the Draft Community Group Report the node targets, and **any** such date is conforming, no rule and no vector pinning a particular one (the draft moves on every Community Group publication); the protocol version for `a2a-card`, the Solid Protocol version for `solid`), `agsc-access` (one value: `none`, `consent`, `credential`). The declaration is **derived at build from what the writer actually emits** — the only configuration is the OPTIONAL `surfaces[]{surface, target, version, access}` object of `agsc.config.json` (AGSC-01-18) for the declaration-only surfaces `responder`, `solid` and `a2a-card`, whose target, version and access class cannot be derived from emitted bytes; the built-in surfaces take fixed access classes — `llms-txt` and `chunks` `none`, `webmcp` and `mcp` `consent`; a surface whose target does not resolve, or whose manifest disagrees with the declaration, is `AGSC-E210` from `validate-wellknown`. [design]
- **AGSC-11-17** **PIN.** A surface MUST NOT be declared unless every byte it emits is pinned by a rule of this specification and proved by a `required` vector. The four built-in surfaces and their proofs are: `llms-txt` by the layout rule AGSC-06-13a and `disc-0013`/`disc-0014`; `chunks` by the chunk rules AGSC-06-26…31 and the `chunks/` vectors; `webmcp` and `mcp` by AGSC-09-13/09-16 and `cli-0003`. `a2a-card`, `solid` and a `responder` whose protocol is not MCP are declaration-only at 1.0, and a remote MCP `responder` is served as AGSC-11-21 states (AGSC-11-21; `a2a-card`'s bytes are pinned by A2A 1.0 — JCS then optional JWS — and AGSC-06-34 states its emission precondition): their bytes are pinned by the external specification named in `agsc-surface-version`, and a validator checks only the declaration shape. [design]
- **AGSC-11-18** **INHERIT.** A surface never restates the security floor; it inherits it: writes are human-gated (AGSC-08-04/08-27, AGSC-09-16 local-only), returned prose is `untrusted` (AGSC-08-18) and peer-derived prose names its origin (AGSC-11-11), content terms travel with exported bytes (AGSC-06-18), consent precedes invocation. Where the external surface has a vocabulary for the floor the node MUST use it: on `webmcp`, `readOnlyHint: true` on `search`, `read`, `links`, `compose`, `ask`; `consequentialHint: true` on `propose` and `remember`; `untrustedContentHint: true` on every tool whose result carries prose. On `mcp`, the floor's vocabulary is narrower than WebMCP's: the node MUST set `readOnlyHint` — `true` on `search`, `read`, `links`, `compose` and `ask`, `false` on `propose` and `remember` — and MUST NOT rely on `untrustedContentHint` or `consequentialHint`, which that protocol does not define and a conforming client discards, the untrusted mark travelling in the AGSC-08-18 envelope's `trust` member that every result carries. On `mcp`, the node MUST advertise the extension identifier `com.agenticsystemcore/knowledge` in the `extensions` map of the capabilities it reports — under revision 2026-07-28 in its `server/discover` result and in the capabilities carried per request, there being **no initialization handshake** in that revision, and under an earlier revision its transport speaks (AGSC-11-16) in its `initialize` result — per MCP SEP-2133, naming this profile; the seven tools remain core MCP tools. The settings object of that identifier has exactly one member, `linkset`, whose value is the absolute `https` URL of the node's `/.well-known/knowledge-linkset` (AGSC-06-07); a node MUST emit that member and MUST emit no other, and `bnd-0035` pins the advertised object while `bnd-0036` pins the map as it is carried in the `server/discover` result. *(MCP, "Versioning and Compatibility" for revision 2026-07-28, read 2026-09-19: "There is no negotiation handshake."; "**Legacy**: protocol versions that establish a session with an `initialize` handshake (`2025-11-25` and earlier)"; "Extensions are advertised in the `extensions` field of capabilities, which is a map of extension identifiers to per-extension settings objects."; "Servers MUST implement `server/discover`.")* *(Non-normative: the protocol's skills extension, `io.modelcontextprotocol/skills`, is the alignment path for the skill packs of AGSC-06-01 and §07; at 1.x skill packs are files, and nothing here forecloses serving them through the protocol at a later MINOR. The protocol's task extension, `io.modelcontextprotocol/tasks`, is a non-goal at 1.x: a static node has nothing long-running to poll. The Multi Round-Trip Requests pattern that replaced server-initiated elicitation at revision 2026-07-28 is likewise a non-goal, because every write this node offers returns prepared text rather than asking for more input.)* [design]
- **AGSC-11-19** **PROVE.** A conformance claim (AGSC-09-01) MUST list every surface the node declares, and for each the vector ids or the validator run that proves it; `validate-wellknown` MUST compare the declared surfaces against the emitted artefacts and report `AGSC-E210` for any declaration without an implementation and the warning `AGSC-E211` for any emitted surface without a declaration. [design]

## 11.5 Visibility hooks (specified now, built later)

- **AGSC-11-20** `visibility` is `public` (default) or `restricted`, carried as the one-value target attribute `agsc-visibility` on the anchor's `describedby` link, emitted only when the value is `restricted` (a public node carries no `agsc-visibility` attribute). The discovery document itself MUST remain publicly readable at both values — `restricted` means "this node exists; its content is gated", never "this node is invisible". A `restricted` node MUST still serve `/.well-known/knowledge-linkset` with `Access-Control-Allow-Origin: *` (it carries no content and is what "publicly readable" means for a browser agent), MUST NOT apply AGSC-11-03's wildcard to any other artefact, MUST carry exactly one `…/rel#access` link whose target names where a reader obtains credentials, and asserts conformance against its **unauthenticated** view (the discovery document, `/llms.txt` and `/graph.jsonld` at Level 0). A `restricted` node MUST omit `agsc-counts`, `agsc-bundle-hash`, `agsc-bundle-version` and `agsc-ledger-head`, MUST NOT carry the `…/rel#ledger` link, whose target is commit history, and MUST omit every `digest` whose target it does not serve unauthenticated — an integrity attribute over a gated artefact is a confirmation-of-content oracle, and per-type population and commit activity are content facts. *(`agsc-bundle-version` is in that list because its untagged forms carry the commit count and the commit hash of the content branch, which is commit activity by another name.)* It MUST still carry `agsc-spec-version` and `agsc-generated-at`, which say only that the node exists and is current; `validate-wellknown` accepts those absences and reports their presence as `AGSC-E210` (AGSC-09-93). *(Rationale: AGSC-06-08a makes Level, not visibility, the discriminator for those attributes, so without these omissions a gated node would publish the whole bundle-fact set to anyone; threat row T18 of `docs/SECURITY-CONSIDERATIONS.md`.)* Credential formats, encrypted-at-rest Bundles and per-item visibility are NOT defined at 1.0; the profile name `agsc-profile-encrypted` is RESERVED for them. [design]

## 11.6 Dynamic-profile hooks (specified now, built later)

- **AGSC-11-21** A node MAY declare a `responder` surface (AGSC-11-16) whose target is a remote transport URL; a responder serves the same seven tools as AGSC-09-13 under the same floor (AGSC-11-18) and the same envelopes. A node MAY likewise declare a `solid` surface whose target is a Solid pod holding a copy of the Bundle, `agsc-surface-version` naming the Solid Protocol version the pod implements; `solid` is declaration-only at 1.0, and so is a responder whose protocol is not MCP. A remote MCP responder is in 1.0 scope: it serves exactly the seven tools of AGSC-09-13, with the envelopes of AGSC-08-18 and AGSC-09-13a and the floor of AGSC-11-18, over its remote transport, so every byte it emits is already pinned by those rules and proved by the vectors of the `mcp` surface (`cli-0003`, `cli-0004`, `cli-0007`), and nothing new is defined for it. A responder's protocol is named by its `agsc-surface-version`: `mcp:<revision>` for a remote MCP responder serving the seven tools, `a2a:<version>` for an Agent2Agent server (a live board, AGSC-10-14) — a validator checks the prefix. Nothing further is defined at 1.0: a 1.0 validator checks the declaration shape and the `agsc-access` value only, and a node declaring `responder` MUST also serve the static surfaces it declares, so that a static reader never depends on the responder. [design]

## 11.7 Retirement and tombstones

- **AGSC-11-22** An item's `status` gains the value `retired` (AGSC-02-23; the transition is legal from any state and back, un-retirement being a warning like un-deprecation). A retired item keeps its page, which MUST carry a visible retirement notice and MUST keep its canonical IRI; it MUST be excluded from `search.json`, `/chunks.jsonl`, `/llms.txt`, skill packs and every composition selection (a selection naming it is `AGSC-E802`), and MUST remain in the graph exports with `asc:retiredAt` — an `xsd:dateTime` instant derived from `modified` by the midnight convention of AGSC-05-14, from `date` when `modified` is absent, and omitted when both are absent. Any Link whose target is retired is reported as `AGSC-E411` (warning); `supersedes` MAY name a retired item without warning. [design]
- **AGSC-11-23** A node that stops publishing MUST keep `/.well-known/knowledge-linkset` serving a valid link set whose anchor `describedby` link carries `agsc-tombstone` = one AGSC-04-10 instant, MAY carry an `alternate` link to a successor node's discovery document, and MAY omit every other artefact link. A client MUST NOT treat a successor named by `alternate` as the same node: it MUST establish mutuality with the successor afresh (AGSC-10-12) before following it, and everything derived from the successor carries the successor's own Bundle IRI as `origin` (AGSC-11-11). A peer check (AGSC-10-12) treats a tombstoned peer as *resolved, not mutual* — a distinct outcome from `AGSC-E907` — and a walk (AGSC-11-10) does not descend into it. [design]

## 11.8 Security considerations (informative pointer)
