# AGSC-05 — Graph: IRIs, RDF views, SKOS, PROV

## 5.1 Identifiers

- **AGSC-05-01** An item IRI MUST be `<site.base>/<type-plural>/<slug>/` — an HTTPS site URL with a trailing slash. [design]
- **AGSC-05-02** Vocabulary IRIs MUST use the persistent hash namespace `https://w3id.org/agentic-system-core/ns#`. The site domain MUST NOT appear in a vocabulary IRI. The namespace is a **constant of this specification and is not configurable**: `ns{base,version}` in `agsc.config.json` (AGSC-01-18) is retained for forward compatibility only, no conforming tool reads a value other than the default, and a Bundle MUST NOT vary it. [design]
- **AGSC-05-03** The Bundle IRI is `<site.base>/`. Cluster IRIs follow AGSC-05-01 with `<type-plural>` = `clusters`. [design]
- **AGSC-05-04** `memory://<bundle>/<slug>` is a documented alias of the item IRI. An implementation MUST NOT emit it as an RDF subject and MUST NOT dereference it over the network; it is resolved locally, and only for this Bundle's own `bundle.id`, exactly as AGSC-05-04b specifies. No node is ever required to emit or render `memory://` (AGSC-05-04a); an implementation at Level 2 or above MUST resolve it as AGSC-05-04b says (`graph-0005`; the tool server: `cli-0015`). *(Amended 2026-10-02 for 1.0.0: until `1.0.0-rc.6` this rule said that an implementer at any Level "may skip AGSC-05-04a, AGSC-05-04b and AGSC-10-08 without affecting a claim", while two required cases tested the resolution; the cases decide.)* [PRD-027]
- **AGSC-05-04a** The HTTPS item IRI (AGSC-05-01) is the canonical identifier and MAY always be used instead of `memory://` — wherever an implementation documents or accepts `memory://<bundle>/<slug>` — exports, foreign-node mappings, prose and rendered output — the `https://` form MUST be equally accepted and the two MUST be treated as the same identifier. Link values remain slugs (AGSC-03-02), and neither form is ever written as one; a tool or command-line argument that names an item accepts both forms and resolves them to the slug before any other rule runs, as AGSC-05-04b says (AGSC-08-18). Emitting or rendering `memory://` is optional, never a requirement. *(Amended 2026-10-02 for 1.0.0: until `1.0.0-rc.6` this rule said neither form "is ever accepted as an argument, only ever rendered", against AGSC-05-04b.)* *(Amended 2026-10-10 for 1.0.0: a word that is not a key word is written in lower case)* [PRD-027]
- **AGSC-05-04b** `agsc mcp` tools and the CLI MUST **resolve** `memory://<bundle-id>/<slug>` to the item when `<bundle-id>` equals this Bundle's `bundle.id`: the alias is accepted wherever a slug argument is accepted, normalized to the slug before any other rule runs, and never dereferenced over the network (AGSC-05-04 still forbids emitting it as an RDF subject). When `<bundle-id>` names another Bundle the argument MUST be refused with `AGSC-E309` — "foreign bundle: use the `https://` IRI" — because a node has no registry of other nodes' ids. Frontmatter Link values remain slugs (AGSC-03-02). [PRD-027, AGSC-05-04a]
- **AGSC-05-05** If an item carries `id`, it MUST equal the slug (AGSC-01-11); if it carries `iri`, it MUST equal the computed IRI; either mismatch is `AGSC-E204`. *(Amended 2026-10-10 for 1.0.0: the requirement on `id` stood only in the key table of §2.2, without a rule id)* [design]

## 5.2 The four RDF views

- **AGSC-05-06** A writer MUST emit `graph.jsonld`, `graph.nq`, `graph.ttl` and per-item `pages/<slug>.{jsonld,md}`; `graph.rdf` (RDF/XML) is NOT emitted at 1.x and `build.rdfxml` is RESERVED (one blank-node-free graph needs no fourth syntax). All views express the same triples. [PRD-022]
- **AGSC-05-07** `pages/<slug>.md` MUST be a byte-identical copy of the lint-normalized source file, with one derived change: a Link target naming an item AGSC-06-30 excludes is removed from the frontmatter array and a key emptied by that removal is omitted, as AGSC-06-29 does for a chunk record *(Rationale: a held-back item is on no public surface, and this page is one; `export --markdown`, the publisher's own byte-preserving copy under AGSC-01-26, is not)*. [design]
- **AGSC-05-08** The RDF dataset MUST be **blank-node-free**: every node has an IRI. Blank nodes in an export are error `AGSC-E605`. [design]
- **AGSC-05-09** `graph.jsonld` MUST carry as its `@context` the **specification's persistent versioned context URL** — `https://w3id.org/agentic-system-core/ns/<context-version>/context.jsonld`, `<context-version>` being the **context version**, which is `1.0.0` at every version 1.x of this specification and is not the ontology version of AGSC-05-25 (`1.0.0-draft.1` until `spec_version` reached `1.0.0`) — and sort nodes by `@id` and properties per AGSC-04-05. The context file that URL names declares `"@version": 1.1` and `"@protected": true`, so every term it defines is protected; `graph.jsonld` itself carries neither member, its two members being those of the shape below. The URL is a constant of this specification, resolvable by every reader at every Level, so a **Level-0** `graph.jsonld` is expandable without the node serving a context of its own; a Level ≥ 2 writer additionally serves a byte-identical copy at `/ns/context.jsonld` and at `/ns/<context-version>/context.jsonld` (AGSC-06-32, AGSC-06-06) and MAY name either of those instead. Released context files are immutable; new terms require a new file. **The context version and the ontology version are separate.** The ontology version (`owl:versionIRI`, AGSC-05-25) moves whenever the vocabulary file changes; the context version moves only when a later MINOR releases a new context file and says so here, and 1.1.0 releases none. A term the vocabulary gains after the context file was released (`asc:warrant`, AGSC-05-40) is not in that file, and a member for it is named, as for any predicate the context has no term for, by the compact IRI `<prefix>:<local>` where the context defines the prefix of the predicate's namespace (`asc:warrant`, `schema:additionalType`, `dcterms:isPartOf`) and otherwise by the full predicate IRI, so every `graph.jsonld` that a 1.0.0 writer produced keeps its bytes. **Shape of the file.** *(Amended 2026-10-02 for 1.0.0: the shape below is what conforming writers emit; it was not written down, so two writers could differ and both claim this rule.)* The document is a JSON object with exactly two members: `@context`, one string, the URL above; and `@graph`, an array holding one node object per subject of the dataset of `graph.nq` (AGSC-05-06), in code-point order of `@id`. A node object has `@id`; `@type`, the context's term name for the node's class (one string — every node has one class, AGSC-05-12, except the item that carries a domain type, AGSC-05-39, whose `@type` is an array of its two classes in code-point order of their IRIs, the site class written as its IRI); and one member per other predicate of that subject, named by the context's term for the predicate, or, where the context has none, by the compact IRI where the context defines the prefix of the predicate's namespace and otherwise by the predicate IRI. Each value takes the most compact form its term definition allows: an IRI is a bare string where the term's `@type` is `@id`, otherwise `{"@id": …}`; a language-tagged literal is `{"@language": …, "@value": …}`; a literal whose datatype is the term's `@type`, or `xsd:string` where the term has no `@type`, is its bare lexical form; any other literal is `{"@type": …, "@value": …}` (AGSC-05-31 gives each property one datatype, so an `xsd:string` literal never meets a term that declares another). A member's values are ordered by the code points of their IRI or lexical form, without repeats, and a member with one value carries that value, never a one-element array. At Level 2 and above the bytes are JCS (AGSC-04-04) followed by one LF. **The per-item file** `/pages/<slug>.jsonld` (AGSC-06-02) has the same shape and the same `@context`, and holds exactly the Bundle node, the item's node and the item's own `#source-<n>`, `#review-<n>` and `#attachment-<n>` nodes, each identical to its node in `graph.jsonld` — so every triple whose subject is the item is present, its Links, their computed inverses and its mentions included (AGSC-05-06); a triple whose subject is another node, such as a cluster's `skos:member`, is in that node's file only. Test case `graph-0028` states both files whole, and `graph-0043` pins the context address against an ontology version other than `1.0.0`. *(This shape is this rule's own, fixed here so that two writers agree; it is not defined as the output of a JSON-LD processor's compaction algorithm, whose result for the same dataset can differ — for a dataset of one node, for example, compaction drops `@graph`.)* *(Amended 2026-10-10 for 1.0.0: `"@version"` and `"@protected"` were asked of `graph.jsonld`, which only a context file can carry; the bare form of an `xsd:string` literal is limited to a term with no `@type`, which is what JSON-LD 1.1 reads back as a string; the sentence on compaction is added. No emitted byte changes)* *(Amended 2026-10-29 for 1.1.0: the address names a context version that is a constant `1.0.0`, no longer the ontology version, so that raising the ontology version does not change a byte of any `graph.jsonld`; the array `@type` of a node with a domain type is added, and only a node that uses the domain layer emits it)* [design]
- **AGSC-05-10** `graph.ttl` MUST follow the stable-Turtle profile, every byte of which is fixed here *(Rationale: AGSC-04-24 claims cross-implementation byte-identity for this file.)*:

  (a) **The `@prefix` block** is exactly, in this order, one line each and nothing else:

  ```
  @prefix asc: <https://w3id.org/agentic-system-core/ns#> .
  @prefix dcterms: <http://purl.org/dc/terms/> .
  @prefix prov: <http://www.w3.org/ns/prov#> .
  @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
  @prefix schema: <https://schema.org/> .
  @prefix skos: <http://www.w3.org/2004/02/skos/core#> .
  @prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
  ```

  written `@prefix <pfx>: <IRI> .` with exactly one space after each token, the prefixes in code-point order of the prefix name. A prefix whose vocabulary the graph does not use **is still emitted**, so the block is a constant of this specification; `owl:` and `rdf:` are never declared (no triple this specification emits needs either — `rdf:type` is written `a`).

  (b) **Layout.** Exactly one blank line separates the prefix block from the first subject block, and each subject block from the next. The file ends with exactly one LF (AGSC-04-07) and carries no other blank line, no comment, no `@base` and no `PREFIX`/`BASE` (SPARQL-style) directive.

  (c) **Order.** Subject blocks are ordered by subject IRI code points; within a block, predicates by predicate IRI code points — the **IRI**, never its prefixed name, so `skos:prefLabel` (`http://…`) precedes `asc:status` (`https://…`); within a predicate, objects by the code points of their written Turtle form.

  (d) **Serialisation.** A subject block is `<subject-form> <clause>` for the first predicate, then one further line per predicate, each indented by exactly four spaces; clauses are separated by ` ;` followed by a single LF, and the block ends with ` .`. Several objects of one predicate are written on that predicate's clause, separated by ` , `. `a` is written for `rdf:type`; every other predicate and every IRI whose namespace is in (a) and whose local part is a legal `PN_LOCAL` is written as a prefixed name, and every other IRI between `<` and `>`.

  (e) **Literals.** Explicit datatypes except `xsd:string` and language-tagged literals, per AGSC-05-31; lexical forms and escaping per AGSC-05-32.

  `graph.ttl` MUST be isomorphic to `graph.nq`. Vector `graph-0026` pins a complete file. [design]
- **AGSC-05-11** Emission is one-way. An implementation MUST NOT claim to be a JSON-LD processor, an RDF parser or a SHACL engine on the strength of these outputs. [design]

## 5.3 Class and property mapping

- **AGSC-05-12** Items MUST be typed per `ontology/agsc.ttl`: `concept` → `asc:Concept` (⊑ `skos:Concept`), `lesson` → `asc:Lesson` (⊑ `asc:Concept`), `episode` → `asc:Episode` (⊑ `prov:Activity`), `procedure` → `asc:Procedure` (⊑ `prov:Plan`), `cluster` → `asc:Cluster` (⊑ `skos:Collection`), `gate` → `asc:Gate` (⊑ `prov:Plan`). The Bundle is `asc:Bundle` (⊑ `skos:ConceptScheme`). [design]
- **AGSC-05-13** There is no common superclass for items; an `asc:Item` class MUST NOT be emitted. An Activity is not an Entity, and the union would fail OntoClean while answering no competency question. [design]
- **AGSC-05-14** Each `sources[]` entry MUST be instantiated as an `asc:Source` (⊑ `prov:Entity`) whose IRI is `<item-IRI>#source-<n>`, `<n>` being the 1-based index of the entry in authored `sources[]` order — a fragment IRI, exactly like a Review (AGSC-05-15), so that no URL-to-IRI escaping question arises and a `urn:agsc:channel:…` resource works unchanged. It carries `dcterms:source` = the `resource` string, `dcterms:title`, `dcterms:creator` and `dcterms:date` from `title`, `author` and `year` where present, plus `asc:verifiedOn` and `asc:grade` where present; `dcterms:bibliographicCitation` is NOT emitted, because no composition rule for it could be reproduced by a port. `asc:verifiedOn` is `xsd:dateTime` (the OWL 2 datatype map has no `xsd:date`, AGSC-05-22): a `verified` date `YYYY-MM-DD` MUST be rendered as the midnight instant `YYYY-MM-DDT00:00:00Z`. The item MUST additionally carry `<item> asc:source <item-IRI>#source-<n>` for each entry, so the Source is reachable from its item (AGSC-05-23: relied-upon relations are materialized, never entailed). [design]
- **AGSC-05-15** `verified[]` MUST be instantiated as an `asc:Review` (⊑ `prov:Activity`) whose IRI is `<item-IRI>#review-<n>`, `<n>` being the 1-based index of the entry in authored `verified[]` order — Reviews therefore have IRIs and never become blank nodes (AGSC-05-08). The actor and instant MUST be emitted as the datatype properties `asc:verifiedBy` (the `by` string) and `asc:verifiedAt` (the `at` instant); `prov:wasAssociatedWith` MUST NOT be used, because `by` is an actor string and not an IRI, and `prov:wasAssociatedWith` is an object property whose range is `prov:Agent`. The item MUST additionally carry `<item> asc:review <item-IRI>#review-<n>` for each entry (AGSC-05-23). Proposals come only from the derived git log, and a Proposal's IRI is the forge pull-request URL. [design]
- **AGSC-05-16** The fourteen Link keys MUST map exactly as tabulated in §03 — the nine core keys to SKOS, DCTerms, PROV and `asc:` as listed there, and the five Mode-2 keys to `asc:implements`, `asc:verifies`, `asc:covers`, `asc:blockedBy` and `asc:decidedBy` with the computed inverses `asc:implementedBy`, `asc:isVerifiedBy`, `asc:coveredBy`, `asc:blocks` and `asc:decides` (`asc:isVerifiedBy` is the Link inverse; the datatype property `asc:verifiedBy` of AGSC-05-15 is a Review actor and unrelated). Inline links map to `asc:mentions`. [design]

## 5.4 SKOS integrity

- **AGSC-05-17** Every Concept MUST carry `skos:inScheme` the Bundle, exactly one `skos:prefLabel` per language tag, and `skos:altLabel` for each alias. [SKOS S14]
- **AGSC-05-18** Cluster membership MUST be emitted as `<cluster> skos:member <item>` from the item's `clusters[]`. [design]
- **AGSC-05-19** **Cluster nesting rule.** `broader` on a `type: cluster` file is a nesting statement and MUST be exported as `<parent> skos:member <child>` — a nested `skos:Collection`. `skos:broader` on a Collection is forbidden: its domain and range are `skos:Concept` (S19/S20), which is disjoint with `skos:Collection` (S37), so the triple would entail a contradiction and fail every SKOS validator. [design]
- **AGSC-05-20** `broader`/`narrower` between Concepts MUST be exported as `skos:broader`/`skos:narrower`. A Collection MUST NOT appear in any semantic relation (`skos:broader`, `skos:narrower`, `skos:related`). [design]
- **AGSC-05-21** The machine-checkable qSKOS subset MUST be linted: cyclic hierarchies, overlapping labels, orphan concepts, missing in-links, missing definitions, undefined resources. Overlapping labels — two published items of one `type` (compared inside one context group on a node that declares contexts, AGSC-08-32) where a `title` or an alias of one is equal, after NFC and Unicode simple case folding, to a `title` or an alias of the other — are the warning `AGSC-E416`: taking the items in code-point order of their repository-relative paths, each item that shares a label with an earlier one carries one finding, naming the earliest such item, and an item's own `title` equal to one of its own aliases is not an overlap; the other five checks take the codes their own rules name. *(Amended 2026-10-29 for 1.1.0: the check compared titles only and now compares titles and aliases; the code is unchanged, so a node whose items overlap only by alias gains warnings it did not have, and a node with only equal titles gets the findings it had)* [design]

## 5.5 Profile and reasoning

- **AGSC-05-22** `ontology/agsc.ttl` MUST stay inside OWL 2 RL. Constructs outside RL MUST be rejected by the ontology check `tools/validate-ontology` (AGSC-09-90), the lint that applies to this file of the specification, with `AGSC-E203`; `agsc lint` reads a Bundle, not the vocabulary. *(This rule and AGSC-05-28 govern the vocabulary terms the ontology declares, and not the annotation properties on the ontology node itself that AGSC-05-25 requires.)* *(Amended 2026-10-10 for 1.0.0: the rule named "lint" without saying which check rejects the file or with which code)* [design]
- **AGSC-05-23** No reasoner runs at build. Relied-upon entailments — inverses and cluster nesting — MUST be materialized explicitly; integrity comes from JSON Schema and generated SHACL shapes. *(Amended 2026-10-29 for 1.1.0: the bracketed sentence that said no shapes are generated at 1.x is replaced, because the lane of AGSC-05-24 now exists; the engine's own checks stay the normative ones. Derived readings are computed by plain code and each carries its reasons, AGSC-05-33; a reasoner still does not run at build, and the consequences of the graph are a separate command, AGSC-05-37.)* The computed inverse `derivation-of` of `derived-from` (§3.1) is the one inverse with no RDF property: AGSC-05-16 maps only the authored direction, `prov:wasDerivedFrom`, and AGSC-05-27 closes the list of object properties, so no triple carries it; it exists only as a computed edge, which the `links` tool reports (AGSC-09-13). *(Amended 2026-10-10 for 1.0.0: the rule asked for every inverse to be materialized without saying that `derivation-of` has no property)* [design]
- **AGSC-05-24** SHACL shapes MUST be generated from `schema/item.schema.json`, never hand-edited, and run in a development lane; without that lane the "validated by SHACL" claim MUST be dropped. *(This distribution has no such lane at 1.x, so the claim is dropped — no document of it says "validated by SHACL" — and the lane is a 1.1 item, AGSC-00-20; the first sentence binds whoever builds it.)* *(Amended 2026-10-29 for 1.1.0: the lane exists. AGSC-05-11 stands. The shapes a node writes for itself are a different file, hand-written, and governed by AGSC-05-41.)* [design]
- **AGSC-05-25** The ontology MUST declare `owl:versionIRI` per release and MUST mark retired terms `owl:deprecated true` with `dcterms:isReplacedBy` instead of deleting them. Until `spec_version` reaches `1.0.0`, and while the vocabulary's terms are those published with specification `1.0.0-rc.6`, `owl:versionIRI` MUST name the pre-release path (`https://w3id.org/agentic-system-core/ns/1.0.0-draft.1`) and `owl:versionInfo` MUST equal that string; the `.htaccess` version rule already accepts a SemVer pre-release suffix. The vocabulary version `1.0.0-draft.1` is frozen as published with specification `1.0.0-rc.6`: its versioned copy under `/ns/1.0.0-draft.1/` — the ontology and its JSON-LD context — is immutable like every versioned copy (AGSC-06-06) and stays served after `1.0.0`, and a term added or changed later goes into the file of a new version, never into this copy. **From `spec_version` `1.0.0` on**, the vocabulary version is `1.0.0` — `owl:versionIRI` `https://w3id.org/agentic-system-core/ns/1.0.0`, `owl:versionInfo` `"1.0.0"`, its immutable copy under `/ns/1.0.0/` — and it changes only when a term is added or changed, to the version of the specification that ships that change; a later specification version that changes no term keeps it, and AGSC-05-09 then names the same context URL. *(Amended 2026-10-02 for 1.0.0: the rule said what the version is before `1.0.0` and not after.)* A changed annotation is a changed file: a change to a term's `rdfs:label` or `rdfs:comment`, or to a value on the ontology node, changes the bytes of the immutable copy, so it takes a new vocabulary version exactly as an added or changed term does, the version of the specification that ships it; a specification version that ships no change of the file keeps the vocabulary version. The ontology node MUST also carry the metadata a vocabulary registry indexes: `rdf:type` `voaf:Vocabulary` beside `owl:Ontology`, `vann:preferredNamespacePrefix` `"asc"`, `vann:preferredNamespaceUri` `<https://w3id.org/agentic-system-core/ns#>`, the namespace every `asc:` term is in, `dcterms:creator`, `dcterms:publisher`, and `dcterms:issued` and `dcterms:modified` as `xsd:date` values — `issued` the date of the first published tagged release that carried the vocabulary and `modified` the date of the release that first ships this version of the file, both derived from the release and never read from a clock. The two prefixes they need are declared in `ontology/agsc.ttl` alone, which no rule's fixed prefix block pins — AGSC-05-10 pins the prefix block of the emitted `graph.ttl`, a different file — so they change no emitted byte.)* *(Amended 2026-10-10 for 1.0.0: `issued` is the date of the first published tagged release, and `modified` that of the release that first ships the version of the file; a changed annotation is stated to take a new vocabulary version; the annotation properties and the classes of other vocabularies the file uses are declared in it, which an OWL 2 profile checker needs to find the file inside OWL 2 RL.)* *(Amended 2026-10-29 for 1.1.0: the ontology version is separate from the context version of AGSC-05-09. These are changes to the file, so by the sentence before this note the release that ships them sets `owl:versionIRI` to `https://w3id.org/agentic-system-core/ns/1.1.0` and `owl:versionInfo` to `"1.1.0"`, and the copy under `/ns/1.0.0/` stays as released. Until that release the file keeps the 1.0.0 values. The context address does not follow: AGSC-05-09 names `1.0.0` throughout 1.x.)* [design]

## 5.6 Frontmatter → property mapping

- **AGSC-05-26** Every datatype property this specification emits — every `asc:` property, and the DCTerms and schema.org literal properties named in the table — MUST be emitted from exactly the frontmatter or configuration key named here, on exactly the subject named here, with exactly this datatype — so that `graph.ttl`, `graph.nq` and the per-item JSON-LD are reproducible from `spec/` plus the Bundle alone (AGSC-00-01, NFR-02). A key absent from an item emits no triple, and no property is ever inferred or invented — including `status`: the default `stable` of AGSC-02-23 is a reading default, and `asc:status` is emitted only when `status` is authored, so an adopted file adds no triple it did not write. `prov.agent` and `prov.agreement` are deliberately not exported: `agent` is a build-time severity and merge-guard discriminator (AGSC-08-13, AGSC-08-26(d)) rather than a published fact, and `agreement` is a contribution-agreement identifier carried by the DCO-Plus trailer (AGSC-08-06). Adding `asc:agent` would require a property no §5.3/§5.6 rule emits, which AGSC-05-28 forbids. `schema:license` and `schema:usageInfo` are the two properties this specification emits from configuration rather than from an item key: both are constants of the build, both are literals (a `LicenseRef-` or SPDX identifier is text, not an IRI), and both appear on the Bundle node and on every item node so that `pages/<slug>.jsonld` and the `export --jsonl` line of AGSC-01-27 carry the licence without a second fetch. *(Amended 2026-10-29 for 1.1.0: the mapping is also published as a Dublin Core Tabular Application Profile (DCTAP, DCMI, https://www.dublincore.org/specifications/dctap/, page dated 2023-02-10, which states no status) in `schema/dctap.csv`, generated by `tools/gen-dc-profile` from `schema/item.schema.json` and this table, and informative: the table decides, and a documentation check keeps the file current. Three rows are added for the optional domain layer, `domain_role`, `warrant.source` and `warrant.type`, each emitted only where the item carries the key, AGSC-05-39 and AGSC-05-40; only `asc:warrant` is a new term.)* [design]

## 5.8 Literal datatypes and N-Quads escaping (the two pins that make `--peer` meaningful)

- **AGSC-05-31** **Literal form.** Every literal this specification emits takes exactly one of three forms and no other: (a) a **language-tagged** literal, used only for `skos:prefLabel`, `skos:altLabel` and `skos:definition`, whose tag is the item's `lang` (default `i18n.default`, else `en`, AGSC-01-13) lower-cased, and which MUST NOT also carry a datatype; (b) a **typed** literal carrying the datatype named for that property in the AGSC-05-26 table or in AGSC-05-30; (c) a **plain** literal, which is `xsd:string` — every property whose AGSC-05-26/05-30 datatype is `xsd:string` takes this form and never form (b); every DCTerms, PROV and schema.org literal this specification emits takes form (c) — `schema:license` and `schema:usageInfo` among them (AGSC-05-26) — except `dcterms:created`/`dcterms:modified`, which take form (b) with the `xsd:dateTime` the AGSC-05-26 table names for `date`/`modified` — and MUST be written **without** an explicit `^^xsd:string` in Turtle and **with** `^^<http://www.w3.org/2001/XMLSchema#string>` in N-Quads, per the RDF 1.1 rule that a plain literal is an `xsd:string`. A producer MUST NOT invent a datatype, MUST NOT emit `rdf:langString` explicitly, and MUST NOT emit an empty language tag. Booleans are `xsd:boolean` `true`/`false`; integers are `xsd:integer` with no leading `+`, no leading zeros and no exponent; instants are `xsd:dateTime` rendered by AGSC-04-10. *(Amended 2026-10-10 for 1.0.0: the default language tag is `i18n.default`, else `en`, as AGSC-01-13 and the reference engine already had it)* [AGSC-10-12]
- **AGSC-05-32** **N-Quads escaping.** In `graph.nq` a literal's lexical form is written with exactly these escapes and no others: `\\` for U+005C, `\"` for U+0022, `\n` for U+000A, `\r` for U+000D, `\t` for U+0009, and `\u00XX` (four lowercase hex digits) for every other character below U+0020. Every character at or above U+0020, other than `"` and `\`, is written **as itself in UTF-8** — `\uXXXX` and `\UXXXXXXXX` MUST NOT be used for characters a producer could write directly, so that two producers emit the same bytes. IRIs are written between `<` and `>` with the same control-character escaping and no percent-re-encoding (AGSC-11-12). Lines end with ` .` and a single LF and are sorted by their serialized bytes (AGSC-04-13). `graph.ttl` uses the same lexical forms inside its own syntax. Vector `graph-0012`. [design]

## 5.9 Readings, questions, suggestions, views and consequences

- **AGSC-05-33** A pure function derives **readings** of the Link graph and never stores them. A reading is `{source, key, target, because}`, and `because` is a non-empty list of steps `{rule, from}`, where `rule` is exactly one of `inverse`, `symmetric`, `transitive` or `closure` and `from` is a list of the edges `[source, key, target]` the step used. The function covers four kinds: (a) the computed inverse of each authored edge (`rule` `inverse`, one edge in `from`); (b) the other direction of each authored edge of `related`, `excludes` or `contradicts` (`symmetric`, one edge); (c) for each key whose Transitive reading cell in AGSC-03-01 is `yes`, except `requires`, and for its computed inverse, each pair `(a, c)` of two different items joined by a chain of two or more edges of that one key (`transitive`, the chain in `from`, in order); (d) the same for `requires` and its inverse (`closure`). The chain of (c) and (d) is the first one a breadth-first walk from `a` meets, expanding each frontier in code-point slug order, as AGSC-07-04 does, and keeping for each item the predecessor from which the walk first reached it, so it is a shortest chain and the same in every implementation. A reading from (c) or (d) has exactly one step in `because`, whose `from` is the chain. A pair that already holds an edge of the key, authored or computed, is not a reading. Readings are ordered by `source`, then `key`, then `target`, by code point. The edges of (a) and (b) are materialized in the graph files as AGSC-05-23 requires and are unchanged; **nothing of (c) or (d) is written to `graph.jsonld`, `graph.nq`, `graph.ttl` or `pages/<slug>.jsonld`**, and no reading changes a composition (AGSC-03-18, AGSC-07-10). No reasoner runs (AGSC-05-23). *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: so that every relation the Link graph holds without being authored can be explained)* [AGSC-03-01]

## 5.10 The domain layer: a site's own vocabulary, warrants, invariants and questions

A Bundle with no `domain` object (AGSC-01-41) is a Bundle of 1.0, and every file this chapter describes is byte-identical to the one 1.0 writes for it. The rules below name the files that change when the layer is used.

- **AGSC-05-38** A node MAY ship one **site vocabulary**, a Turtle file at the path of `domain.vocabulary` (AGSC-01-41), and the file MUST (a) be UTF-8, LF, NFC and blank-node-free (AGSC-05-08), and declare exactly one `owl:Ontology`, whose IRI, which MUST NOT end in `#` or `/`, followed by `#` is the **site namespace**; - **AGSC-05-40** A **warrant** states why a term belongs to the vocabulary: what grounds it and the kind of ground. The key `warrant` of AGSC-02-25 is an object with the members `source`, a non-empty single-line string, and `type`, exactly one of `literary`, `user` and `organisational`. These are the three warrants that ANSI/NISO Z39.19-2005 (R2010) names for the choice of terms: a **literary** warrant is use of the term in the published literature of the field, a **user** warrant is use of the term by the people who search for or ask about the subject, and an **organisational** warrant is the requirement of the organisation that keeps the vocabulary. The standard names the three kinds of warrant; the token `organisational` is the British spelling of its "organizational warrant" and is this specification's spelling, so there is no fourth kind. A `warrant` without a `source`, or without a `type`, or with another `type`, is the error `AGSC-E512`. An item that carries a valid `warrant` adds two triples on the item: `<item> dcterms:source "<source>"` and `<item> asc:warrant "<type>"`, both `xsd:string`. `asc:warrant` is a datatype property of the vocabulary file from 1.1.0 (AGSC-05-25, AGSC-05-26) and the only term that the domain layer adds to it; `graph-0045` states a complete file. A warrant is not an entry of `sources[]`, evidence (AGSC-02-12) or a review, and it changes none of them. *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: the key `warrant` is new in 1.1.0 and optional)* [design]
- **AGSC-05-41** A node MAY state **invariants** and **competency questions** of its own, in the files at `domain.shapes` and `domain.questions` (AGSC-01-41), and `verify` and `ci` check them (AGSC-09-20). Both are evaluated over one data graph, the published projection (AGSC-06-30) as `graph.nq` holds it together with the closure of AGSC-05-37. **Invariants** are SHACL (SHACL 1.0, W3C Recommendation, 20 July 2017, https://www.w3.org/TR/shacl/, read 29 October 2026), not a language of this specification, and the engine evaluates exactly this **SHACL Core subset** and nothing else: the classes `sh:NodeShape` and `sh:PropertyShape`, the property `sh:path`, the severities `sh:Violation`, `sh:Warning` and `sh:Info` and the node kinds `sh:IRI`, `sh:Literal`, `sh:BlankNode` and their unions; node shapes named by IRI, and property shapes that are the object of `sh:property` and MAY be blank nodes (an RDF list that is the value of `sh:in` is not a shape); the targets `sh:targetClass`, `sh:targetNode`, `sh:targetSubjectsOf` and `sh:targetObjectsOf`; a property path that is a predicate IRI or `sh:inversePath` of one; and the constraint components `sh:class`, `sh:datatype`, `sh:nodeKind`, `sh:minCount`, `sh:maxCount`, `sh:hasValue`, `sh:in`, `sh:pattern` (without `sh:flags`), `sh:minLength`, `sh:maxLength`, `sh:node` and `sh:property`, with `sh:severity` and `sh:message`. A shapes file that uses any other term of the `sh:` namespace, or names a node shape by a blank node, is the error `AGSC-E420`. Each result of the validation is one finding `AGSC-E421`, an error where the severity is `sh:Violation` and a warning for `sh:Warning` and `sh:Info`, naming the focus node, the source shape and the message; the findings are ordered by focus node, source shape and path by code point. A **competency question** is an object of the JSON array in `domain.questions` with the members `expected`, `id` (a slug), `query` and `question` (the sentence for people). `query` is SPARQL 1.1 Query (W3C Recommendation, 21 March 2013, https://www.w3.org/TR/sparql11-query/, read 29 October 2026) of the form `SELECT` or `ASK`, limited to this subset: basic graph patterns; the property-path operators `/`, `^`, `+` and `*`; `FILTER` with comparison, `&&`, `||`, `!` and `NOT EXISTS`; `DISTINCT`, `ORDER BY` and `LIMIT`; a query outside it is `AGSC-E420`. `expected` is for `ASK` a boolean and for `SELECT` an object `{"rows": [[...]]}` whose cells are the terms in N-Triples form (an unbound variable is the JSON `null`), rows in the order of `ORDER BY` where the query has one and otherwise sorted cell by cell, each cell as its N-Triples string, by code point. A questions file that is not a JSON array of such objects, or that repeats an `id`, is `AGSC-E420`. An answer that differs is the error `AGSC-E422`, naming the `id`. The ten questions of AGSC-05-34 are the engine's and are not in this file. A node that declares neither file runs neither check. *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: for the optional domain layer)* [design]
