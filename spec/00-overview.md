# AGSC-00 — Overview, terms, conformance model

`spec_version: "1.0.0-rc.6"` (draft of 2026-09-22; rc.3, rc.4 and rc.5 are frozen at their tags, rc.6 applies the items recorded against the frozen text since the rc.5 tag). The key words MUST, MUST NOT, REQUIRED, SHALL, SHOULD, SHOULD NOT, MAY are to be interpreted as described in BCP 14 (RFC 2119, RFC 8174) when, and only when, they appear in capitals. Each rule has a stable id `AGSC-<section>-<nn>`; ids are never reused or renumbered. Trailing brackets cite the requirement each rule serves: a requirement id of the product requirements (`PRD-nnn`, `NFR-nn`, `ADR-nnn`), an external standard, or a related rule; a bracket that reads `[design]` marks a rule settled in design review with no single listed requirement.

## 0.1 Scope

- **AGSC-00-01** (amended at rc.3) This specification — `spec/00`…`spec/11`, `schema/{item,bundle,config}.schema.json`, `ontology/agsc.ttl` and `tests/vectors/**`, checkable by the `tools/` validators of AGSC-09-90 as they ship (all nine ship with the 1.0.0 distribution; two, `validate-wellknown` and `validate-vectors`, were already in the `1.0.0-rc.5` tag and the other seven were added to the reference distribution on 2026-09-21 — corrected 2026-09-18, again 2026-09-19 after the rc.4 tag moved onto the reference-engine commit, and again at rc.6, when the seven shipped) — is the definition of AgenticSystemCore. An implementation MUST NOT rely on behaviour that these files do not pin, and any behaviour observable only in a particular engine is a defect of that engine, not of this specification. [NFR-02]
- **AGSC-00-02** This specification defines a file format, a graph projection, a set of published surfaces, a governance contract and a CLI contract. It does not define a network protocol, a server, a database or a reasoner. [design]
- **AGSC-00-03** Where a rule and a `tests/vectors/**` entry disagree, the rule is normative and the vector MUST be corrected by the procedure of AGSC-00-16 (new versioned file; the wrong file republished as `withdrawn`). [NFR-02]

## 0.2 Terms

- **AGSC-00-04** **Bundle** — one directory tree of Markdown items plus exactly one `agsc.config.json`; the unit of publication and of conformance. [design]
- **AGSC-00-05** **Item** — one `.md` file with YAML frontmatter whose `type` is one of `concept`, `episode`, `procedure`, `lesson`, `cluster`, `gate`. "Item" is a term of this specification only; no common superclass exists in the ontology (§05). [design]
- **AGSC-00-06** **Concept** (with a `kind` qualifier), **Episode**, **Procedure**, **Lesson**, **Cluster**, **Gate** are the six item types. **Link**, **Source**, **Proposal**, **Review**, **Bundle**, **Harness** complete the ubiquitous language; Proposal and Review have no file (they are a forge pull request and its `verified[]` evidence), Source is an inline `sources[]` entry, and a Harness is generated output only. [design]
- **AGSC-00-07** **NOW** is generated context, never an item and never hand-edited. [design]
- **AGSC-00-08** **Card**, **page**, **deck** and **note** are UI or import vocabulary; they MUST NOT appear as a `type`, a schema key or an ontology term. [design]
- **AGSC-00-19** (added at rc.4) **Agent lane** and **live board** complete the language for Mode 5. An **agent lane** is the OPTIONAL, configured capability by which a model-driven or programmatic agent creates, edits, reviews and updates items non-deterministically — always as Proposals, never as writes (AGSC-01-36, AGSC-08-28…30). A **live board** is a Bundle used as the shared working memory and pull-based task board of people and agents, local or remote: work is pulled by whoever claims a task, at most `max_claims` at a time, until the board is done (AGSC-10-16…18). The name says what it is — a board that is live, shared and always current; its operating discipline is Kanban's pull with a work-in-progress limit, and the blackboard architectural pattern (Hayes-Roth 1985, Nii 1986 — `docs/RELATED-WORK.md`) is its lineage (named *Blackboard* on 2026-09-17 and *Kanban* on 2026-09-18; **live board** on 2026-09-18). Neither adds a `type`, an item key or an ontology term; both are realised entirely with the objects §0.2 already names. [design]
- **AGSC-00-20** (added at rc.4) **Declared scope by version.** The whole of this specification's scope is named here with the version at which each part becomes normative, so that a reader of any version sees the whole and a conforming tool never claims more than its version specifies. **1.0** (normative in this document): the Bundle and the six item types (§1, §2), the fourteen Links (§3), canonical forms (§4), the graph (§5), the surfaces (§6), composition and the Harness (§7), governance with the agent lane (§8), conformance (§9), Levels 0–3, project mode and Mode 5 (§10), the boundary with federation, the plugin contract, visibility, the declaration-only surfaces `solid` and `a2a-card`, the `responder` surface served by an MCP transport (AGSC-11-21), retirement and tombstones (§11). **1.1** (MINOR, AGSC-00-14 — keys, values and vectors added, nothing removed): the `memory://` resolver (AGSC-05-04a), `build.rdfxml` (AGSC-01-18), `build.feed` together with the pinned bytes of `/feed.xml` (AGSC-06-01; both reserved at rc.5, because no 1.0 rule pins a feed's bytes), a registry for extension keys in place of the `x-<vendor>-<key>` namespace (`docs/SPEC.md` §8(2)), an order for a Level's vector-area set (AGSC-10-15), the `.diagram` source grammar together with the compiled bytes it produces (AGSC-01-07, implementation-defined at 1.x and added to this list at rc.5), a per-chunk `abstract` and a tabular chunk index (AGSC-06-29), the typed cross-node Link `peer-ref`, `contribute[].repository` and `contribute[].branch` so that a node states where its source files live instead of a writer inferring it from a contribution endpoint (AGSC-11-14, added to this list at rc.6, 2026-09-22), **weighted Links** through the reserved item key `weights`, **model-routing declarations** through the reserved configuration name `routing`, and an **executable Harness** through the reserved `compose --emit` target `executable` together with the optimisation step that produces it, which runs after Step 5 and is verdict-neutral (all three reserved at rc.6 and stated in full in AGSC-00-25), a registered short relation if IANA grants one, the `agsc-profile-encrypted` and signatures profiles, the incremental build and the memory pack, language variants — `<slug>.<lang>.md` files beside a primary, the route `/<type-plural>/<slug>/<lang>/`, `hreflang` alternates and the shared-Links check (AGSC-01-13, AGSC-01-13a; moved here from 1.0 at rc.6, 2026-09-24: no implementation served a variant, and the one vector that claimed to prove the pair, `bundle-0002`, exercised no engine and was withdrawn the same day), the benchmark kit, the red-team suite and the public conformance page, and — added to this list at rc.6, 2026-09-23 — path-scoped steer targets that write one file per Gate item (AGSC-01-28's registry is one target to one path), an optional minimum-sources lint with its configuration key, a pinned first block for a steer bundle, steer-target size budgets as a configuration input rather than a frozen table, `sources[].license` with a licence-compatibility lint, the `DataCatalog` and `DataDownload` members of the home page's structured data (AGSC-06-19), a JSON-LD context `Link` header in the `_headers` profile (AGSC-06-17), and the SHACL generation lane (AGSC-05-23, AGSC-05-24), and an `https:` IRI as the target of a `blocked-by` or `decided-by` Link, so that a task can name a peer's task directly (AGSC-01-22 describes the imported-copy route 1.x uses instead; added to this list at rc.6, 2026-09-24), identity and media-provenance surfaces — a signed discovery document, a `did.json`, a Web Bot Auth signature and C2PA manifests on attachments — which a node MAY declare as `x-` surfaces (AGSC-11-16) until a rule pins their bytes, the optional signature link of AGSC-06-10 being the 1.x hook (added to this list at rc.6, 2026-09-24), and the runtime renderings of the six `compose --emit` targets beyond their registry rows together with forge shims for forges other than GitHub (AGSC-07-18, AGSC-08-12; added to this list at rc.6, 2026-09-24: at 1.0 the names are registered and a rendering the distribution does not ship is refused with the registry's code). **2.0** (MAJOR): servers — a hosted responder, live Agent2Agent boards (AGSC-10-14), a forge application for browser proposals — the Solid pod written by the node rather than only declared (AGSC-11-21), IPFS snapshots and ActivityPub delivery as further declared surfaces (`x-` extensions until then), CRDT live sync, a SPARQL endpoint, hosted multi-tenant nodes. A 1.0 tool MUST accept every declaration a 1.0 rule already admits for these (the `surfaces[]` entries of AGSC-11-16, the `memory://` alias), MUST NOT emit or claim what a later version specifies, and MUST report an unknown key as `AGSC-E004` as today. *(amended at rc.5: the earlier sentence said a 1.0 tool "MUST accept … `build.rdfxml`", which AGSC-01-18's closed configuration and AGSC-05-06's reservation make impossible.)* A 1.0 tool MUST **recognise** `build.rdfxml` and `build.feed` as names reserved to 1.1 and MUST reject either in a configuration file with `AGSC-E004`, so that a 1.1 configuration fails loudly rather than silently on a 1.0 tool. `docs/PLAN.md` carries the same list with dates and is informative. [PRD-065, AGSC-00-14]

## 0.3 Conformance classes

- **AGSC-00-09** A **reader** MUST implement §01–§03 and §05 read-side: locate items, parse the frontmatter subset, validate against `schema/item.schema.json`, resolve the fourteen Link keys — nine core + five Mode-2, only the core nine driving composition — and compute their inverses. A reader MUST pass every `required` vector in the areas `frontmatter/`, `slug/`, `links/`. [PRD-002, PRD-003]
- **AGSC-00-10** A **writer** MUST implement §04, §05 and §06: canonical JSON, the four RDF views, the route set and the discovery files. A writer MUST pass every `required` vector in `jcs/`, `graph/` and `discovery/`, and MUST be a conforming reader. [PRD-004, PRD-022, PRD-024]
- **AGSC-00-11** A **full engine** MUST additionally implement §07 (composition), §08 (governance) and §09 (CLI contract) and MUST pass every `required` vector in every area. [PRD-036, PRD-042, PRD-001]
- **AGSC-00-12** An implementation claiming conformance MUST state its Level (AGSC-10-01 maps the class names of AGSC-00-09…11 to Levels 0–3, once), its `spec_version` and the vector set it passed. It MUST NOT claim a class whose vectors it does not pass. [PRD-010]
- **AGSC-00-13** Optional vectors (`"level": "optional"`) MAY fail without losing conformance; they cover SHOULD-level rules. A `withdrawn` vector (AGSC-00-16) is excluded from every class's required set and MUST NOT be run for a conformance claim. [design]

## 0.4 Versioning

- **AGSC-00-14** `spec_version` is SemVer 2.0.0. MAJOR means a file valid under the previous MAJOR MAY fail validation; MINOR adds optional keys, enum values, link semantics or vectors; PATCH clarifies text or adds vectors that conforming implementations already pass. [design]
- **AGSC-00-15** A reader MUST accept any Bundle whose `spec_version` MAJOR equals its own, MUST tolerate unknown keys and unknown link keys, and MUST NOT reject a file for them. *(amended at rc.5: the scope of that tolerance is now stated, because `agsc.config.json` is part of a Bundle and AGSC-01-18 closes it.)* This key tolerance governs **item frontmatter** (AGSC-02-05) and documents a reader did not author — a received discovery document, a peer board, a file under `import` or `--peer` (AGSC-11-02). `agsc.config.json` is deliberately closed (AGSC-01-18) and is the one asymmetry of `docs/SPEC.md` §6(10): a MINOR that adds a configuration key therefore also raises the MINOR a tool must claim in order to read that Bundle's configuration, and a 1.0 tool reports `AGSC-E004` — loudly, by design (AGSC-00-20). §0.6 states this tolerance in full, construct by construct, together with what survives a round trip and what a tool may never originate (AGSC-00-21…23, added at rc.6). [OKF v0.2]
- **AGSC-00-16** Released spec sections, JSON-LD context files and vector files are immutable; a change creates a new versioned file. A vector that AGSC-00-03 shows to be wrong MUST NOT be edited in place: the corrected case ships as a new versioned vector file and the superseded file is retained with its `level` republished as `withdrawn` (excluded from every claim, AGSC-00-13). Editing, at an rc bump or at the release, the specification-version string a released vector carries — `options.spec_version`, and the same string wherever the case's `input` or `expected` states the version an implementation reports or emits — or re-pointing its `rule` to the rule that absorbed a retired one, is not a change to the case and is done in place *(widened at rc.6, 2026-09-24: 24 vectors carry the version string inside `input` or `expected` — a configuration value, the JSON envelope, an `asc:specVersion` literal — and 15 released ones were edited there at rc.6, which the earlier wording did not admit)*. Ontology terms are never deleted — they are marked `owl:deprecated true` with `dcterms:isReplacedBy`. [design]
- **AGSC-00-17** `spec_version` MUST appear in the Bundle root `content/index.md` and in `agsc.config.json`; it MAY appear per item and, when present, MUST have the same MAJOR. An item whose `spec_version` carries another MAJOR is `AGSC-E204` — the value fails the MAJOR the Bundle root fixes, which is a pattern constraint on that key *(code named 2026-09-24: the sentence stated the obligation and no code, so a reference engine accepted `2.0.0` on an item in silence)*. [design]

> **rc.3 amendment (2026-09-16):** AGSC-00-01 reads `spec/00`…`spec/11` — `spec/11-boundary.md` (the node boundary: cross-origin access, federation, contribution, surfaces, visibility, retirement) is part of the definition from `1.0.0-rc.3`. Its vector area is `boundary` (`bnd-nnnn`).

## 0.5 Requirement traceability for artefact-level requirements (added at rc.3, 2026-09-16)

- **AGSC-00-18** Seven product requirements are served by the shape of the artefacts rather than by a single rule sentence, so they are cited here and a validator checks the citation exists (AGSC-09-91's trace-tag check). **NFR-01** (as superseded on 2026-09-18: maintained libraries at exact pins, no network and no clock at run time — the citation read "zero runtime dependencies" until 2026-09-24) is served by AGSC-06-16, whose prebuilt inverted index is required to need no runtime dependency, and by AGSC-05-23, which forbids a build-time reasoner. **NFR-09** (unattended operation) is served by AGSC-04-03, which removes every interactive and ambient input from a build, and by AGSC-08-20, whose ledger is derived rather than maintained. **NFR-13** (offline and cross-platform) is served by AGSC-04-01 (byte-identical on every operating system and runtime), AGSC-04-24 (which artefacts that covers) and AGSC-10-12 (a peer check that MUST accept two local files). **PRD-008** (version and changelog agreement) is served by AGSC-00-17, which requires `spec_version` in both the Bundle root document and the configuration with matching MAJOR. **PRD-009** (scaffold on initialisation) is served by AGSC-02-94, which requires `init` to synthesize files that validate against their own schemas. **PRD-012** (fully functional with no model key) is served by AGSC-07-01, which forbids a composition from requiring a network, a key or a server, and by AGSC-08-27, which makes the review lane lint-only with any model review opt-in and non-gating. **PRD-016** (failure knowledge as items, not an error-book file) is served by the `lesson` item type of AGSC-00-05 and its heading contract in AGSC-02-21; no rule emits an error-book artefact and none may be added at 1.x. [design]

## 0.6 Compatibility, extension points and reserved names (added at rc.6, 2026-09-22)

This section is the one place a reader and a writer are told what to do with something this specification does not define. It grants no tolerance that §0.4 and the chapters did not already grant: it states the whole of it once, names the rule that owns each clause, and closes the three questions that had no home — what survives a round trip, what a tool may never originate, and which extension points exist at all.

- **AGSC-00-21** **Ignore and preserve: reading a document of another version.** A tool whose `spec_version` MAJOR equals the document's (AGSC-00-15) MUST NOT fail on a construct it does not know, in a document it did not author — a received discovery document, a peer board, a file under `import` or `--peer`, an item written by another node. Reading an *older* MINOR asks nothing of it, because a MINOR only adds (AGSC-00-14); reading a *newer* one is fixed per construct, each row being the behaviour of the rule named beside it and not a new one:

  | construct | what a 1.x reader does | owning rule |
  |---|---|---|
  | an unknown item frontmatter key | preserve verbatim; report the warning `AGSC-E207` | AGSC-02-05 |
  | a key matching `x-<vendor>-<key>` | preserve verbatim; never interpret; no diagnostic | AGSC-02-05a |
  | an unknown link-shaped frontmatter key | preserve verbatim; report the warning `AGSC-E304`; never treat it as one of the fourteen | AGSC-03-03 |
  | an unknown item `type` under `import` | map it to `concept` with a warning | AGSC-01-22 |
  | an unknown value of `visibility`, `agsc-contribute-mode`, `agsc-surface` or `agsc-access` | treat it as the most restrictive member of that list | AGSC-11-02 |
  | an unknown relation name in a received discovery document — a registered one this specification does not itself emit, or a `…/rel#<name>` a later MINOR added | ignore the link; it affects no digest, no claim and no walk, which follows `rel#peer` only | AGSC-06-35, AGSC-11-10 |
  | an unknown `agsc-`-prefixed target attribute in a received discovery document | ignore it; only the attributes AGSC-06-08 names are read, and only from the links it names | AGSC-06-08, AGSC-06-10 |
  | an unknown member of a ledger entry, or a `kind` reserved to a later MINOR | tolerate it and hash the entry as it stands | AGSC-08-21 |
  | an unknown member of a trace record | preserve it under `x-<vendor>-<key>` | AGSC-09-94 |
  | any of the above in the tool's **own** Bundle — a `type` outside the six, a value outside a closed list, a key its schema does not hold | reject it: a node's own configuration and frontmatter are validated closed, because a publisher may not emit what its declared version does not define (`AGSC-E203`) | AGSC-11-02, AGSC-00-23 |

  `agsc.config.json` is the single deliberate exception and the one asymmetry of this specification: it is closed (AGSC-01-18), so a key a tool does not know is `AGSC-E004` and a 1.1 configuration fails loudly on a 1.0 tool instead of running with half its settings ignored (AGSC-00-15, AGSC-00-20). [PRD-002, NFR-02, AGSC-00-14, AGSC-00-15]
- **AGSC-00-22** **Round trip.** Everything AGSC-00-21 preserves MUST survive a round trip unchanged — the same member name and the same value, in the same file. `lint --fix` MUST NOT add, remove or infer a key and MUST reproduce every preserved member (AGSC-04-19, AGSC-04-20); `export --markdown` and `export --okf` MUST carry every authored frontmatter key, the preserved and the vendor ones included (AGSC-01-26); a memory adapter MUST be lossless in both directions for every key it claims and MUST carry the rest through unread (AGSC-01-26a); and `import` MUST write what it read (AGSC-01-22, AGSC-01-23). The only normalisation admitted anywhere on this path is the encoding and key-ordering profile of AGSC-04-19, which moves a key and never changes a value. A tool that cannot preserve a member MUST refuse the operation rather than drop it, because a silent drop is the one failure a consumer of a round trip cannot detect. Vector `lint-0027`. [PRD-026, NFR-02, AGSC-04-19]
- **AGSC-00-23** **A tool originates only what its declared version specifies.** A tool MUST NOT emit, and MUST NOT write into a Bundle it authors, a key, value, relation, surface, route, attribute or file that this specification reserves to a later version (AGSC-00-20, AGSC-00-25); carrying one through that arrived from elsewhere under AGSC-00-21 and AGSC-00-22 is not originating it. The fault takes the code its construct already carries and no code is minted for it: in `agsc.config.json` it is `AGSC-E004`, fatal, because configuration is closed and is the node's own declaration (AGSC-01-18); in item frontmatter it is the warning `AGSC-E207`, or `AGSC-E304` for a link-shaped key, and the member is preserved, because an item may have been authored on another node and this specification never destroys an author's bytes; in a value of a closed operator list — an `export --steer` target (AGSC-01-28), a `compose --emit` target (AGSC-07-18), a `run.allow[]` program (AGSC-09-94) — it is `AGSC-E203`; and where a node's own published bytes carry a member of a version its discovery document does not declare, `validate-wellknown` reports `AGSC-E210`, which already names emitted bytes that disagree with their declaration (AGSC-11-19, AGSC-09-93). [PRD-010, AGSC-00-20, AGSC-09-15]
- **AGSC-00-24** **Extension points: the closed list of plugin kinds.** Everything this specification admits as a replaceable part is one of the eight kinds below, and no other extension point exists at 1.x: a capability that is none of them is a change to this specification, not a plugin. Three obligations bind every kind, whatever else its own rule says. **(i)** A plugin reaches the network only where its kind's row grants it, and no row grants it during `build`, `lint`, `verify` or `ci` (AGSC-04-03, AGSC-08-30). **(ii)** A plugin writes only the outputs its row names, never inside `content/` (AGSC-08-02), never outside the Bundle root and never through a link (AGSC-01-16, AGSC-01-35). **(iii)** A plugin never changes the canonical bytes of a 1.0 surface: the artefacts of AGSC-04-24 and the route set of AGSC-06-01 are fixed by this specification and are not a plugin's to alter.

  | kind | selected by | may read | may emit | may never |
  |---|---|---|---|---|
  | memory adapter | `export --to <adapter>`, `import --from <adapter>` (AGSC-01-26a) | the Bundle; the foreign corpus named on the command line | a foreign format; on import, items under `content/<type-plural>/` | reach the network; be selected by a configuration key; emit an executable, a symlink or an `allowed-tools` declaration (AGSC-07-15); lose a key it claims (AGSC-00-22) |
  | channel adapter | `channels[].adapter` (AGSC-01-30) | its own channel's messages from `since` | `messages[]`, and one conforming item per message, always as a Proposal | write to the content branch; ingest past `allow[]`, `rate{per_hour}` or the five-open-Proposals cap; take `source_id` from message content |
  | forge shim | a `gate` item's `enforce[]` (AGSC-08-12) | the Bundle's gate and governance configuration | the four files under `dist/forge/` | write into `build.out` or `content/`; overwrite a differing file the repository already carries (`AGSC-E707`); put the ingest identity on a ruleset as a bypass actor (AGSC-08-26(f)) |
  | deployment profile | the writer's own target, stated in its conformance claim (AGSC-06-01, AGSC-09-01) | the emitted route set | its host's configuration, beside that route set (`_headers` and `_redirects` for Cloudflare Pages, AGSC-06-17) or, for configuration the host does not read from the served directory — a server block, a proxy header table, a gateway manifest, a ledger anchor record — under `dist/` (the second place admitted 2026-09-24) | change a route, a served byte, or the header and redirect set of AGSC-06-17, AGSC-11-03 and AGSC-11-05, which are the normative content the file format only carries |
  | surface | derived from what the writer emits, or declared in `surfaces[]` (AGSC-11-16) | the published projection and nothing else (AGSC-06-30, AGSC-09-16) | its declaration link, and for a built-in surface the bytes its own rule pins | be declared without a rule pinning its bytes and a `required` vector proving them (AGSC-11-17); restate, narrow or weaken the security floor (AGSC-11-18) |
  | page tool | `document.modelContext.registerTool()` on a published page (AGSC-09-16) | what the node published, through the page | a result equal as a value to the local tool server's for the same input and Bundle | require a network call, a key or a server; perform a network write; read or honour `channels[].publish` |
  | composition emitter | `compose --emit <target>` (AGSC-07-18) | the seven file kinds of AGSC-07-12 | one target rendering, written outside `dist/harness/<name>/` | change the seven files; add a file inside the Harness directory; be more than one template plus a registry row |
  | checker | its own name among the nine of AGSC-09-90 | the normative artefacts its own contract names, and for `validate-wellknown` a URL or a file given on the command line (AGSC-09-93) | the AGSC-09-11 envelope with `verb` set to its own name, and nothing else on stdout | import `src/`; report `pass` over an absent or empty input (`AGSC-E901`); invent a diagnostic shape or an unregistered code |

  A kind's own rule governs everything else about it, and where that rule and this table differ the kind's rule wins. No plugin of any kind is required for conformance at any Level; a Level requires the artefacts its own rule names and never a particular plugin (AGSC-10-01…06, AGSC-01-26a, AGSC-09-14a). [PRD-055, AGSC-11-16, AGSC-01-26a]
- **AGSC-00-25** **Reserved names.** Three names are reserved now, so that a 1.0 tool meets one without failing or guessing and a 1.1 tool may give it meaning; AGSC-00-20's 1.1 list carries the same three.

  - **`weights`** — an item frontmatter key, reserved to 1.1 for **weighted Links**: an object whose member names are Link keys and whose values map a target slug to a number. It is reserved as a sibling key and not as a member inside a Link value, because AGSC-03-02 fixes a Link value to a slug string, so a 1.0 reader meeting an object there would have to fail where this section requires it to ignore. At 1.x it is preserved verbatim and reported as the unknown-key warning `AGSC-E207` (AGSC-02-05, AGSC-00-21), and a 1.0 tool MUST NOT originate it (AGSC-00-23).
  - **`routing`** — a configuration name, reserved to 1.1 for **model-routing declarations**, both at the top level of `agsc.config.json` and inside each `agents[]` entry. Configuration is closed, so a 1.0 tool MUST recognise the name and reject it with `AGSC-E004`, exactly as it rejects `build.rdfxml` and `build.feed` (AGSC-01-18, AGSC-00-20): a 1.1 configuration then fails loudly instead of routing silently to nothing.
  - **`executable`** — a `compose --emit` target name, reserved to 1.1 for an **executable Harness**, together with the **optimisation step** that produces it, which will run after Step 5 of AGSC-07-08 and be verdict-neutral as Step 5 is. At 1.x the emitter registry of AGSC-07-18 is closed and the step set of AGSC-07-08 is exactly five, so `compose --emit executable` is `AGSC-E203` and no sixth step runs.

  A reserved name is not an `x-<vendor>-<key>`: the vendor namespace is open, never interpreted and never given a meaning by this specification (AGSC-02-05a), while a reserved name is this specification's own and will acquire one.
