# AGSC-02 — Item: frontmatter contract per type

## 2.1 Frontmatter syntax

- **AGSC-02-01** A file MUST begin on line 1 with `---`, contain YAML, and close with a line `---`. A file with no such opening line is `AGSC-E101`; an opening line whose block is never closed by a later `---` is `AGSC-E102`. No `...` terminator and no second document (`AGSC-E107`). [design]
- **AGSC-02-02** The YAML subset is: block mappings, block sequences, flow sequences of scalars, single/double-quoted and plain scalars, `|` and `>` block scalars. Anchors, aliases, tags, merge keys, complex keys, flow mappings and duplicate keys MUST be rejected, each under its own code: an anchor or an alias is `AGSC-E103`, a tag or a merge key is `AGSC-E104`, a flow mapping or a complex key is `AGSC-E105`, and a duplicate key is `AGSC-E106`. [design]
- **AGSC-02-03** A reader MUST parse with the YAML **failsafe** schema — every scalar is a string — and MUST apply types from `schema/item.schema.json`. `yes`, `no`, `on`, `off`, `~`, `1e3`, `0x1F` and bare dates are strings. [design]
- **AGSC-02-04** Booleans MUST be written `true`/`false`; numbers MUST be plain decimal; dates and instants MUST be quoted strings. [design]
- **AGSC-02-05** Key names MUST match `^[a-z][a-z0-9_-]*$`. Unknown keys MUST be preserved and reported as warnings (`AGSC-E207`), never as errors. A key name that does not match this pattern is `AGSC-E204` (a pattern violation), distinct from an *unknown but well-formed* key, which is the `AGSC-E207` warning; the schema does not enforce the pattern, because `propertyNames` would turn the warning into an error. [OKF]
- **AGSC-02-05a** A key matching `^x-[a-z0-9]+(-[a-z0-9]+)+$` is a **reserved vendor extension** (the `x-` namespace of `docs/SPEC.md` §8(2)). A conforming tool MUST preserve it verbatim in every lossless export (AGSC-01-26), MUST NOT interpret it, MUST NOT normalise it beyond the key ordering of AGSC-04-19, and MUST NOT report `AGSC-E207` for it. Every other unknown key still warns under AGSC-02-05. The same namespace is admitted in `agsc.config.json` by AGSC-01-18. [design]
- **AGSC-02-06** Dates use `YYYY-MM-DD`. Instants (`stale_after`, `generated.at`, `verified[].at`, `started`, `ended`) MUST be `YYYY-MM-DDTHH:MM:SSZ` — a datetime with an explicit UTC offset, seconds precision, never a bare date. [OKF 2026-08-21]

## 2.2 Keys common to every type

| Key | Required | Value |
|---|---|---|
| `type` | yes | `concept\|episode\|procedure\|lesson\|cluster\|gate` |
| `title` | yes | 3–120 characters, any Unicode NFC |
| `description` | lint-required for `concept`, `cluster` (`AGSC-E408` warning); schema-optional so adoption passes (AGSC-02-92) | 40–200 characters when present |
| `status` | no (default `stable`) | `draft\|stable\|deprecated\|retired` |
| `release` | no | slug; see AGSC-01-20 |
| `tags` | recommended | 2–5 values from `tags.allowed` |
| `aliases` | no | strings |
| `clusters` | recommended on `concept` | cluster slugs; first is primary |
| `lang` | no (default `en`) | BCP 47, compared case-insensitively and emitted lower-cased (AGSC-01-13) |
| `date`, `modified` | recommended | `YYYY-MM-DD` |
| `sources[]` | recommended | `{resource*, title, author, year, verified, grade?}`, `grade ∈ primary\|secondary\|tertiary` |
| `prov` | yes | `{origin*, agent?, model?, operator*, agreement?}` |
| `generated`, `verified[]`, `stale_after` | no | OKF verbatim |
| fourteen Link keys (nine core + five Mode-2) | no | §03 |
| `id`, `iri` | no | if present MUST equal the slug / the computed IRI |

- **AGSC-02-07** `prov.origin` MUST be one of `human`, `ai-assisted`, `ai-generated`, `imported`; `prov.operator` MUST be present and MUST be a `human:<id>` actor string — accountability is always a person, so `process:<id>` and `<producer>/<version>` are NOT accepted here even though AGSC-02-09 admits them elsewhere (this is what makes the `Assisted-by:` trailer of AGSC-08-07 always satisfiable). Absence of `prov` is error `AGSC-E501`. [PRD-042]
- **AGSC-02-08** *(reserved: the same proposition in reversed order, stated by AGSC-08-02; the id is never reused, AGSC-00-16.)*
- **AGSC-02-09** Actor strings MUST be `human:<id>`, `process:<id>` or `<producer>/<version>`. [OKF]
- **AGSC-02-10** `sources[].resource` is REQUIRED in every `sources[]` entry and is either an `http(s)` URL or the channel form `urn:agsc:channel:<name>:<source_id>`; `sources[].id` is the OPTIONAL stable identifier that makes re-ingest idempotent (AGSC-01-33). [design]
- **AGSC-02-11** An item is **stale** when `stale_after` is earlier than the build instant (§04). Staleness MUST be computed by comparison only — no decay function, no activation score, no access log. [PRD-017]

## 2.3 Type-specific keys

- **AGSC-02-12** `concept` MUST carry `kind` ∈ `pattern|taxonomy|explainer|principle|decision|spec|task|term|architecture`. Optional facets: `evidence` (`explicit|structural|single-source`), `maturity` (`established|emerging|research`), `mapping` (`explicit|author`), `signature` (boolean), `signature_elements[]`, `owasp_ids[]`, `domains[]`, `modality[]`, `deployment[]`, `implementations[]{label,url}`, `diagram{file*,alt*,caption}`. [PRD-028, design]
- **AGSC-02-13** `diagram.file` MUST be `<slug>.svg`, compiled from `content/diagrams/<slug>.diagram` (AGSC-01-07); `diagram.alt` is REQUIRED. A writer MUST place the compiled SVG **inline in that item's page**, as an `<svg>` element whose accessible name is `diagram.alt` (AGSC-06-20), and MUST NOT emit it at a route: the value is a file name, not a URL, and AGSC-06-01's route set carries no diagram route. The inlined element MUST satisfy every SVG constraint AGSC-02-98 places on an SVG attachment — no `DOCTYPE` or entity declaration, no embedded raster, none of the forbidden elements, no `on*` or `style` attribute, no processing instruction, and only same-document-fragment references — and its bytes count towards the 100 KB page budget of AGSC-06-21. `diagram.caption`, where present, is the figure's visible caption and never a substitute for `alt`. [PRD-013]
- **AGSC-02-14** `episode` MUST carry `started`, `actor` and `outcome` ∈ `success|partial|failure`; MAY carry `ended`, `refs[]` and `usage{model, tokens_in, tokens_out, cost_usd, estimate}` (the optional token accounting rolled up by AGSC-08-25). [NFR-11]
- **AGSC-02-15** `procedure` MAY carry `when` (one line, ≤1024 characters, saying when the procedure applies; a skills import fills it from a foreign skill's `description`, AGSC-01-22) and `inputs[]` *(a published skill pack takes its Cluster's `description`, not `when`: packs are one per Cluster, AGSC-07-19)*. [PRD-032]
- **AGSC-02-16** `lesson` MUST carry `severity` ∈ `info|warn|block` and SHOULD carry `derived-from` naming an Episode. [design]
- **AGSC-02-17** `cluster` MAY carry `broader` (at most one cluster slug), `order` (integer) and `family` (free text). `ordered` is not defined at 1.x. [design]
- **AGSC-02-18** `gate` MUST carry `level` ∈ `L1|L2`; `checks[]`, when present, MUST equal the set `level` implies under AGSC-08-09 (`L1` → `schema`, `links`; `L2` adds `provenance`, `determinism`, `review`) and a disagreement is `AGSC-E203`; `enforce[]` ⊆ `status-check|hook|codeowner|ruleset`, each compiled per AGSC-08-12. [design]
- **AGSC-02-19** Cluster membership MUST be authored on the item (`clusters[]`), never on the cluster file. [design]

## 2.4 Body

- **AGSC-02-20** The body MUST be CommonMark 0.31.2 plus GFM tables. Footnotes, raw HTML and unescaped `{`/`<` outside code SHOULD NOT be used; an unsupported construct MUST be a lint finding (`AGSC-E109`), never a silent rendering difference. The unsupported constructs are raw HTML blocks and inline HTML, footnote references and definitions, and every GFM extension other than tables (task-list markers, strikethrough, autolink literals); each occurrence outside a code span or a fenced block is one `AGSC-E109` warning. [design]
- **AGSC-02-21** Body sections are not schema-enforced. A lint MUST warn (`AGSC-E406`) when `kind: pattern` lacks `## Intent`, `## Context & Forces`, `## Structure`, `## Consequences & Trade-offs`, `## Related Patterns`; `procedure` uses `## When`, `## Steps`, `## Checks`; `episode` uses `## What happened`, `## Outcome`, `## Next`; `lesson` uses `## Lesson`, `## Evidence`, `## Check before`. A `concept` or `cluster` carrying no `description` is likewise a warning, `AGSC-E408`, never an error, because the schema leaves `description` optional so that an adopted file validates (AGSC-02-92). *(The kinds this rule enumerates are the whole of the check; a heading set for `taxonomy` and `explainer` is a 1.1 addition if one is wanted.)* [design]
- **AGSC-02-22** Fenced blocks with info string `turtle`, `jsonld`, `sparql`, `shacl`, `mermaid`, `structurizr`, `gherkin` or `diagram` are rendering hints only at 1.x; the word `export` on such a block is RESERVED — extraction into the graph (subjects, vocabulary, blank nodes, merge order, a vector) is specified by a future MINOR, and at 1.x a block carrying `export` MUST NOT be extracted and is the lint warning `AGSC-E415` (it would be the only unpinned input to `graph.nq` and `bundle.hash`). `run` and `expect` are the only executable info strings; they are permitted on `procedure` items only and have effect only under the opt-in `run` verb of AGSC-09-94. [design]

## 2.5 Status transitions and length units

- **AGSC-02-23** An item with no `status` starts `stable` (the default of the §2.2 common-key table), and every transition between `draft`, `stable`, `deprecated` and `retired` (AGSC-11-22) is legal in both directions — including `deprecated` → `stable` (un-deprecation) and `retired` → any state (un-retirement), which a lint MUST report as a warning (`AGSC-E409`) and MUST NOT reject. `supersedes`/`superseded-by` is orthogonal to `status` and changes neither. [PRD-018]
- **AGSC-02-24** Every length bound in this specification — `title` 3–120, `description` 40–200, `when` ≤1024, `alt` ≥1 (`diagram.alt` and `attachments[].alt` alike), port names ≤64 — counts **Unicode code points**, which is how JSON Schema 2020-12 defines `minLength`/`maxLength` (the length of a string instance is the number of its characters as defined by RFC 8259) and how every language counts a decoded string. No bound counts UTF-16 code units, grapheme clusters or bytes. The schemas enforce these bounds with `minLength`/`maxLength` and never with a regular-expression quantifier, whose unit depends on whether the engine is in Unicode mode; the port-name grammar of AGSC-02-96 additionally bounds its own length by construction, and the normative bound there is the `maxLength: 64` the schema carries beside the pattern, never the pattern's quantifier. **The JSON-Schema keyword subset** the three item-facing schemas use is fixed here and nowhere else: `$schema`, `$id`, `$ref`, `$defs`, `title`, `description`, `type`, `enum`, `const`, `properties`, `required`, `additionalProperties`, `patternProperties`, `items`, `oneOf`, `not`, `pattern`, `minLength`, `maxLength`, `minItems`, `maxItems`, `uniqueItems`, `default` — and no other, so that AGSC-08-01 can reason about what a schema cannot express (a conditional such as "`agent` is REQUIRED when `origin` is `ai-*`" is outside it and is therefore a lint check). `schema/config.schema.json` MAY use more — `if`, `then`, `allOf`, `minimum`, `maximum` and `format` (annotation only) among them — because the engine validates it and no Bundle reader ever reads it. *This is deliberately different from AGSC-04-05's UTF-16 rule, which governs JSON member-name **ordering** only and comes from RFC 8785; ordering and length are separate questions with separate units.* **Authored single-line strings**: every authored string a writer interpolates into a **line-oriented text surface** — `title`, `description`, each `aliases[]` and `tags[]` value, `when`, `family`, `inputs[]`, `signature_elements[]`, `domains[]`, `modality[]`, `deployment[]`, `implementations[].label`, `diagram.alt`, `diagram.caption`, `attachments[].alt`, `attachments[].license`, `sources[].id`, `sources[].title`, `sources[].author`, `prov.agent`, `prov.model`, `prov.agreement`, `usage.model`, the Bundle root's `title` and `license` (AGSC-01-04) and the configuration's `site.title`, `site.tagline`, `site.author`, `bundle.license_prose` and `bundle.license_schema` (AGSC-01-18) — MUST NOT contain a C0 control (U+0000–U+001F), U+007F, U+0085, U+2028 or U+2029. A violation is `AGSC-E204`, which §9.4's precedence paragraph already assigns to every pattern violation; no new code is minted. The reason is structural: `/llms.txt`, `/llms-full.txt`, `/now.md`, `/pages/<slug>.md`, the Harness files of AGSC-07-12 including `SKILL.md`, an additive memory export such as `llms-ctx.txt` (AGSC-01-26a), `robots.txt`, `/.well-known/security.txt` and the deployment-profile files `_headers` and `_redirects` are line-oriented dialects in which a line break inside an interpolated value creates a NEW line — a forged `## ` heading, a forged link entry, a forged response header — and AGSC-01-29 fences the item BODY as data but not the title that the layout of AGSC-06-13a puts on a line of its own. The **Bundle root's `description` is deliberately exempt**: AGSC-06-13a block (3) emits it with newlines replaced by one space, so a multi-line value there is conforming. The schemas enforce the bound with a `pattern` on each member — one negated character class, no lookahead, no back-reference and no quantifier-based bound, so it is the ECMA-262 dialect JSON Schema 2020-12 names and transliterates mechanically to the `\x{…}` escape form of RE2, Go and Rust (the portability bar of AGSC-01-10 and AGSC-01-35). A writer MUST **also** neutralise these code points when it interpolates any such string into a line-oriented surface, replacing each one with a single U+0020: validation is not always in the path — an imported Bundle (AGSC-01-22, which AGSC-08-11 requires be accepted), a channel contribution (AGSC-01-30…33) and an agent-lane Proposal (AGSC-08-28) all reach a writer from outside — and the neutralisation is the identity on every conforming string, so no emitted byte of a conforming Bundle moves. Vector `fm-0010`. [PRD-002, AGSC-04-05]

## 2.9 Adoption of bare Markdown

- **AGSC-02-90** `init` MUST adopt a `.md` file that carries no frontmatter block by prepending, in the schema order of AGSC-04-19 (top-level `properties` order, then the matching `oneOf` branch's `properties` order — so `kind` comes last), exactly `type: concept`, `title`, `aliases` (whenever AGSC-02-93 moved or renamed the file — which is every file adopted from outside `content/`), `prov: {origin: human, operator: …}` and `kind: explainer` — nothing else, in that order. The body MUST be byte-identical after adoption. The two derived values are **total functions**, so adoption never errors:
  - **`operator`** — the first source that exists: (1) `bundle.operator` in `agsc.config.json` (AGSC-01-25); (2) the local part of git `user.email`, NFC-normalized, ASCII-lower-cased, every character outside `[a-z0-9._-]` replaced by `-`, runs of `-` collapsed, leading and trailing `-` trimmed, then leading characters outside `[a-z0-9]` trimmed, prefixed `human:`, and rejected in favour of the next source if nothing remains; (3) the literal `human:unknown`. Sources (2) and (3) MUST emit warning `AGSC-E506`.
  - **`title`** — the text of the first ATX `#` heading if the file has one, else the filename stem; NFC-normalized and trimmed. Longer than 120 Unicode code points it MUST be clipped to 120 code points (warning `AGSC-E506`); shorter than 3 it MUST be replaced by the item slug, and if that is still shorter than 3 by `note-<slug>`.

  `README.md`, `index.md` and `_index.md` MUST NOT be adopted (AGSC-01-05): they are skipped with warning `AGSC-E506`, not turned into items, however common they are in a bare folder. [PRD-053]
- **AGSC-02-91** Adoption MUST be idempotent: it MUST NOT modify a file that already carries a **closed** frontmatter block (a `---` first line whose block is terminated by a later `---` line, AGSC-02-01); a file merely *beginning* with a thematic break is adopted like any other bare file. The slug is the slugified filename stem — NFC, ASCII-lower-cased, characters outside `[a-z0-9]` replaced by `-`, runs collapsed, leading and trailing `-` trimmed, clipped to 64 and any resulting trailing `-` trimmed, empty result becoming `note` — and the file MUST be renamed to `<slug>.md` under `content/concepts/`; when the slug differs from the original stem a warning `AGSC-E506` MUST be emitted. The original repository-relative path is recorded in `aliases[]` by AGSC-02-93 — one alias rule, not two. A slug already taken MUST be suffixed `-2`, `-3`, … in discovery order, the convention of AGSC-01-23 (the anchor suffixes of AGSC-03-13 govern anchors only), re-checking after each suffix. Headings never determine a slug. [PRD-053, AGSC-01-23]
- **AGSC-02-92** Adopted items pass lint with warnings (no `description` — `AGSC-E408` by AGSC-02-21 — no `sources[]`, plus any `AGSC-E506` above) but MUST NOT error: the drop-in path is a first-class conformance scenario — its transformations at Level 2 (AGSC-10-04) and its run through `init` and `ci` at Level 3 (`adopt-0007`, `adopt-0008`, AGSC-10-15). *(Amended 2026-10-02 for 1.0.0: "class: full engine" became the two Levels.)* Totality is complete, not partial: AGSC-02-90 and AGSC-02-91 are total functions, `description` is schema-optional in every branch, and AGSC-02-93 puts the file where AGSC-01-02/03 require it — so **no** adopted file can produce `AGSC-E201`, `AGSC-E202`, `AGSC-E204`, `AGSC-E205` or `AGSC-E206`, and `ci` on a folder of bare notes passes offline once the publisher has added the two things only a publisher can state — the security contact of AGSC-06-36 and, where the Content Use Terms are adopted, `site.tdm_crawlers` (AGSC-06-18); `init` prints both as its "before you build" steps. [PRD-053]
- **AGSC-02-93** `init` in adoption mode MUST create `content/concepts/` and MOVE each adopted file to `content/concepts/<slug>.md`, preserving body bytes; the original repository-relative path MUST be recorded in `aliases[]`; a file already under `content/<type-plural>/` MUST NOT be moved. Nested source directories are flattened (`notes/agents.md` → `content/concepts/agents.md`); collisions follow AGSC-01-23. Without this move a build discovers nothing under `content/**` or reports `AGSC-E205`, and the three-command promise of PRD-053 does not close. [PRD-053, AGSC-01-01/02]

- **AGSC-02-94** In adoption mode `init` MUST also synthesize, when absent, files that **validate against their own schemas**, so that `ci` exits 0 once the publisher has added the one file only a publisher can author — the security contact of AGSC-06-36 (the P0 flow: `init`, then `.well-known/security.txt` with a `Contact:` field, then `ci`; without that file `ci` reports `AGSC-E901` and exits 1, as AGSC-02-92 says): (a) `agsc.config.json` with `spec_version` (current), `site.base = "http://localhost/"` — the development placeholder AGSC-01-19 admits, warned as `AGSC-E506` — `site.title` = the title of (b), `bundle.id` = the directory name through the slug rule of AGSC-02-91, `bundle.operator` = the resolved actor (AGSC-02-90), `build.out = "www/"` — and, because that configuration names no other prose licence and so adopts the Content Use Terms (AGSC-06-18), `site.tdm_crawlers[]` written with the implementation's starting list of crawler tokens, which the publisher then maintains as their own list (the reference engine writes six and says so on standard error) *(Rationale: a reservation naming no crawler fails the build)*; (b) `content/index.md` with `spec_version` (current), `okf_version: "0.2"`, `title` = the directory name through the **title** rule of AGSC-02-90 (so the 3–120 bound always holds), `description` = `"Adopted from <n> Markdown files by agsc init on <SOURCE_DATE_EPOCH date>."` (≥40 Unicode code points by construction) and `base` = `site.base`. Existing files are never overwritten, and every synthesized value is schema-valid by construction — `adopt-0007` proves that `init`, the security contact and `ci` exit 0 on a bare folder, and `adopt-0008` that `ci` exits 1 with `AGSC-E901` when the security contact is missing. *(Amended 2026-10-02 for 1.0.0: until `1.0.0-rc.6` this rule said that `ci` exits 0 "immediately after `init`" and that `adopt-0006` proved it; the reference engine, AGSC-02-92 and AGSC-06-36 all require the security contact first, and `adopt-0006` passed only because its runner replaced `ci` by a schema check. `adopt-0006` is withdrawn; `adopt-0007` and `adopt-0008` run the real verbs. Nothing `init` writes changes.)* [PRD-053, AGSC-01-04, AGSC-01-19]

- **AGSC-02-95** After the relocation of AGSC-02-93, `init`, when it adopts (AGSC-02-90), MUST report every relative Markdown link or image reference in an adopted body that no longer resolves from `content/concepts/` as warning **`AGSC-E507`**, naming the original path, the new path and the reference; and it MUST copy each referenced local file whose path resolves **under the adoption root** to `content/assets/<original-relative-path>`, byte for byte. Body bytes MUST NOT be rewritten — AGSC-02-90's byte-identity guarantee is absolute, so the warning and the copied asset, never a rewritten reference, are what close the gap the flattening opens. A reference that is an absolute URL, a fragment-only target, a `mailto:` or a path resolving outside the adoption root is left alone and MUST NOT be reported. `AGSC-E507` is a warning; the unresolved reference it names is also `AGSC-E310` (AGSC-03-11) until the publisher repairs it, so an adopted Bundle with broken references does not pass `ci`. [PRD-053, AGSC-02-90/02]

## 2.10 Ports, architectures, attachments, task state

- **AGSC-02-96** A `concept` MAY carry `produces[]` and `consumes[]`: arrays of **port type names** matching `^[a-z][a-z0-9-]{0,63}$`, unique within each array, retained in author order in the file and sorted by code point in derived artefacts (AGSC-04-14). Port names are free strings at 1.x, matched by exact equality in §07 Step 5; they are NOT Link keys and the fourteen-key list is unchanged (AGSC-03-01). A lint MUST warn (`AGSC-E804`) when, over the whole Bundle, a `consumes` name has no producer or a `produces` name has no consumer. [PRD-057]
- **AGSC-02-97** A `concept` with `kind: architecture` is a **saved composition**. Its body MUST contain exactly one fenced block with info string `yaml agsc-selection` whose content is a YAML block sequence of slugs (the selection, in author order) in the same failsafe subset as frontmatter (AGSC-02-02/02-03); a second such block is the schema-class error `AGSC-E201`; the block MUST be extracted by `compose --from <slug>` (AGSC-07-24) and MUST NOT be rendered as prose. The item MAY carry `verdict_digest` — the SHA-256 of the JCS verdict last computed; when present and stale, lint warns `AGSC-E805`. On a `concept` whose `kind` is not `architecture`, an `agsc-selection` block and a `verdict_digest` key are the warning `AGSC-E207` and are ignored by every derived artefact. Every slug in the block MUST resolve (`AGSC-E301` otherwise). The architecture item's own Links follow the ordinary rules. [design]
- **AGSC-02-98** Any item MAY carry `attachments[]`, each `{file, media_type, alt, license}`: `file` a path relative to `content/attachments/<slug>/` (no parent-directory segment, no leading slash, AGSC-01-35), `media_type` an RFC 6838 type, `alt` REQUIRED non-empty text, `license` OPTIONAL — an SPDX or `LicenseRef-` identifier defaulting to `bundle.license_prose`. **For a `concept` of `kind: pattern` an image attachment MUST be `image/svg+xml`; any other `image/*` on a pattern is `AGSC-E412` (error).** Every SVG attachment MUST be well-formed XML with **no `DOCTYPE` and no entity declaration**, MUST NOT embed raster data (`data:` URIs of any kind), MUST NOT contain a `script`, `foreignObject`, `use`, `a`, `animate`, `animateColor`, `animateMotion`, `animateTransform`, `set`, `discard`, `handler`, `style`, `cursor`, `color-profile`, `font-face`, `font-face-format`, `font-face-name`, `font-face-src`, `font-face-uri`, `missing-glyph`, `hatch`, `hatchpath`, `mesh`, `meshgradient`, `meshpatch`, `meshrow`, `solidcolor` or `unknown` element (the DOMPurify `svgDisallowed` set as read on 2026-09-17, plus `a`, `animate*`, `handler` and `style`, which this specification bans deliberately), MUST NOT carry any attribute whose name begins with `on`, MUST NOT carry a `style` attribute or any processing instruction, and every `href`/`xlink:href` it carries MUST be a same-document fragment (`#id`) or a relative path inside the same attachments directory (AGSC-01-35) — never an absolute URL, a `javascript:` or `data:` value; a violation is `AGSC-E412`. A writer MUST NOT emit an attachment, or a page naming it, that fails this rule or the path grammar of AGSC-01-35 (`AGSC-E902`): `build` reports the code and emits nothing (AGSC-09-08), whether or not `lint` ran first. Attachment text is an `injection-scan` input (AGSC-08-13) because it enters the chunk export verbatim (AGSC-06-30). `diagram` (AGSC-02-13) is SVG by construction; that rule subjects the inlined compiled SVG to the constraints of this one, so one allow-list governs every SVG a page carries. [PRD-059]
- **AGSC-02-99** A `concept` with `kind: task` MAY carry `task_state`, one of the nine Agent2Agent 1.0 task states verbatim: `TASK_STATE_UNSPECIFIED` (default), `TASK_STATE_SUBMITTED`, `TASK_STATE_WORKING`, `TASK_STATE_INPUT_REQUIRED`, `TASK_STATE_AUTH_REQUIRED`, `TASK_STATE_COMPLETED`, `TASK_STATE_FAILED`, `TASK_STATE_CANCELED`, `TASK_STATE_REJECTED`; in a board a reader did not author, an unknown value is read as `TASK_STATE_UNSPECIFIED` (AGSC-11-02); in the node's own frontmatter an unknown value is `AGSC-E203`. `status` is orthogonal: it governs publication, `task_state` governs the board (AGSC-10-13). On a `concept` whose `kind` is not `task`, `task_state` is the warning `AGSC-E207` and is ignored by every derived artefact — it is not a board entry and does not make its cluster a board. [design]
