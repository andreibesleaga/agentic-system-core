# AGSC-06 — Published surfaces: routes, discovery files, llms.txt

## 6.1 Route set

- **AGSC-06-01** A writer MUST emit exactly this route set into `build.out` (default `www/`): `/`; `/concepts/` and `/concepts/<slug>/`, plus `/<type-plural>/<slug>/<lang>/` for every language variant (AGSC-01-13); `/procedures/`, `/lessons/`, `/episodes/`, `/gates/` with their item pages; `/clusters/` and `/clusters/<slug>/`; `/tags/<tag>/`; `/search/` with `/search.json`, plus `/search-<nn>.json` shards and `/<route>/page-<n>/` index pages above the bounds of AGSC-06-21; `/now/` and `/now.md`; `/compose/`; `/skills/`, `/skills/index.json`, `/skills/<cluster>/SKILL.md`; `/specs/` and `/specs/agentic-knowledge/` (the published specification of the AGSC-06-07 profile URI, the 303 target of the w3id `profile/agentic-knowledge` rule, which MUST carry an anchor `#link-relations` and one `#rel-<name>` anchor per AGSC-06-10 extension relation so that every extension relation URI dereferences to its documentation, RFC 8288 §2.1.2); `/ns/` and its vocabulary files; `/about/`; `/legal/`; `/changelog/`; `/graph.jsonld`, `/graph.ttl`, `/graph.nq` and optionally `/graph.rdf`; `/pages/<slug>.md` and `/pages/<slug>.jsonld`; `/llms.txt` and `/llms-full.txt`; `/sitemap.xml`; `/robots.txt`; `/.well-known/tdmrep.json`; `/feed.xml`; `/ledger.jsonl`; `/.well-known/knowledge-linkset`; `/.well-known/security.txt`; `/404.html`; `_headers`; `_redirects`.

  `/ledger.jsonl` is the derived ledger of §08, published so that a reader can recompute the chain offline (AGSC-08-23) and so that the `rel#ledger` link of AGSC-06-10 has a target. `/search/` and `/search.json` are unconditional (AGSC-06-16 MUSTs the index); `/feed.xml` is emitted only when `build.feed` is true (default `true`) and `/graph.rdf` only when `build.rdfxml` is true (default `false`) — those are the only two conditional routes.

  `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CITATION.cff`, `CONTRIBUTING.md`, `GOVERNANCE.md` and the REUSE layout are repository files, not routes (PRD-047); only `security.txt` is published, at its RFC 9116 location above. [PRD-011 ← R36, audit/D §5, V2-05/06/07]
- **AGSC-06-02** Item pages MUST link their own `/pages/<slug>.md` and `.jsonld`. An empty type folder MUST be omitted from navigation but MUST still resolve. [audit/D §5]
- **AGSC-06-03** The site identity is software plus registry. A reading order, a "start here" sequence, chapter structure or companion framing MUST NOT be emitted. [R23, Art. XIII]
- **AGSC-06-04** `/404.html`, `_headers` and `_redirects` MUST be generated, never hand-maintained; a renamed or superseded slug MUST produce a `_redirects` entry. [PRD-018, PRD-020]
- **AGSC-06-05** Pages MUST NOT reference a third-party origin, load a font, script or image from another host, set a cookie, use `localStorage`, or emit a beacon. [PRD-046 ← R52, N4]
- **AGSC-06-06** `/ns/` conneg is done by the w3id `.htaccess`, mapping `Accept` to a fixed table of same-origin static targets (`text/turtle` → `/ns/agsc.ttl`, `application/ld+json` → `/ns/context.jsonld`, `application/rdf+xml` → `/ns/agsc.rdf`, else the HTML index) — plus the legacy `Accept` aliases `application/x-turtle` (→ Turtle) and `application/json` (→ JSON-LD), which a node MAY accept and no node need send — plus one path rule that sends `/ns/<major>.<minor>.<patch>(/…)?` to the immutable versioned copy of that release before any term rule can capture it (`owl:versionIRI` must resolve). No project-owned server code exists; `/ns/<version>/…` copies are immutable. [D41, D47, ADR-005]

## 6.2 The well-known file

- **AGSC-06-07** There MUST be exactly one discovery file, `/.well-known/knowledge-linkset`, served as `application/linkset+json` carrying the RFC 9264 §5 profile parameter `profile="https://w3id.org/agentic-system-core/profile/agentic-knowledge"`. Where the hosting platform cannot carry a parameter on `Content-Type`, the node MUST instead send the response header `Link: <https://w3id.org/agentic-system-core/profile/agentic-knowledge>; rel="profile"` (RFC 6906); at least one of the two MUST be present, and a reader MUST accept either. No vendor media type is defined, registered or served (D55 amends D21-final/D41/D47-note(c)). Separate manifests MUST NOT be emitted; a release MAY carry a copy named `knowledge-linkset.json`. `agent-card.json` MUST NOT be published while no A2A endpoint exists. The well-known suffix `knowledge-linkset` (D60 supersedes D56's ordering) is distinct from the registered link relation `agentic-knowledge` (AGSC-06-25), which is unchanged. [PRD-024 ← D55, D56, D60, RFC 9264, RFC 9727 §7.3, RFC 6906]
- **AGSC-06-08** The document is a JSON object — JCS-canonical at Level ≥2 (AGSC-04-04), valid I-JSON at Level 0 (AGSC-06-08a, AGSC-10-02) — whose **sole** top-level member is `linkset` (RFC 9264 §4.2.1); no other top-level member may be present. Integrity and bundle facts ride on the links as extension target attributes (RFC 9264 §4.2.4.3), whose values are ALWAYS arrays of strings. Every artefact link MUST carry `digest`, a Dictionary with a single member whose key is the RFC 9530 algorithm name `sha-256` and whose value is an RFC 9651 §3.3.5 **Byte Sequence**, serialised per RFC 9651 §4.1 as `sha-256=:<base64>:` and carried as one string in the attribute's array, over the canonical bytes of the target. Bundle-level facts ride on the anchor's `describedby` link to `graph.jsonld` and nowhere else: `agsc-spec-version` (one value), `agsc-generated-at` (one value, an AGSC-04-10 instant derived from `SOURCE_DATE_EPOCH`), `agsc-counts` (one `"<type-plural>=<n>"` string per item type, in code-point order of the type name), and `agsc-bundle-hash` (the AGSC-04 bundle hash, RFC 9530 syntax). The ledger is the link `https://w3id.org/agentic-system-core/rel#ledger`, carrying `digest` and `agsc-ledger-head` (one value, the lowercase hex head of the derived ledger of §08). [PRD-024 ← D55, RFC 9264, RFC 9530, RFC 9651 ← V5-3 S3-04, S3-08]

Example — the document served at `/.well-known/knowledge-linkset`:

```json
{
  "linkset": [
    {
      "alternate": [ { "digest": ["sha-256=:47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU=:"], "href": "https://example.org/llms.txt", "type": "text/plain" } ],
      "anchor": "https://example.org/",
      "describedby": [ { "agsc-bundle-hash": ["sha-256=:47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU=:"], "agsc-counts": ["clusters=0","concepts=0","episodes=0","gates=0","lessons=0","procedures=0"], "agsc-generated-at": ["2026-01-01T00:00:00Z"], "agsc-spec-version": ["1.0.0-rc.2"], "digest": ["sha-256=:47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU=:"], "href": "https://example.org/graph.jsonld", "type": "application/ld+json" } ],
      "https://w3id.org/agentic-system-core/rel#graph": [ { "digest": ["sha-256=:…:"], "href": "https://example.org/graph.ttl", "type": "text/turtle" } ],
      "https://w3id.org/agentic-system-core/rel#ledger": [ { "agsc-ledger-head": ["bee9ba6593162f59dae28f42ba25fa04ea3fd65ae4f80685fb1c4ede151189ac"], "digest": ["sha-256=:…:"], "href": "https://example.org/ledger.jsonl", "type": "application/jsonl" } ],
      "license": [ { "href": "https://example.org/legal/" } ],
      "service-doc": [ { "href": "https://example.org/specs/" } ]
    }
  ]
}
```

The example is shown pretty-printed for review; the served bytes are JCS-canonical with exactly one trailing LF (AGSC-04-04).

- **AGSC-06-08a** At **Level 0** (AGSC-10-02) the document is the **same** link set with every `digest` and every `agsc-*` extension target attribute omitted — a CMS export has no ledger, no `graph.nq` and no build instant, and Level 0 does not ask for one. At Level 2 and above every `digest` REQUIRED by AGSC-06-08, and every `agsc-*` attribute on the `describedby` and `rel#ledger` links, MUST be present. There is no structural difference between the two: `linkset` is the sole member at every Level. [PRD-055 ← D52(3), D55, V3-03]
- **AGSC-06-09** The `linkset` member MUST conform to RFC 9264: an array of link-context objects, each with `anchor` and relation-keyed arrays of objects carrying `href` and optionally `type`. [PRD-024, RFC 9264]
- **AGSC-06-10** Relation names MUST be either IANA-registered short names (`describedby`, `alternate`, `license`, `service-doc`, `author`) or extension URIs of the form `https://w3id.org/agentic-system-core/rel#<name>` with `<name>` ∈ `graph`, `ontology`, `context`, `now`, `skills`, `ledger`, `peer` — every one of which has a route in AGSC-06-01, `peer` naming another node's well-known URL for the mutual-conformance test of AGSC-10-12. `shapes` is NOT a 1.x relation: SHACL shapes stay in the development lane (AGSC-05-24), so no `/ns/shapes.ttl` is published and a relation with no target would be a dangling promise. Unregistered short names MUST NOT be used. Extension **target attributes** (RFC 9264 §4.2.4.3) MUST use the prefix `agsc-` (`agsc-spec-version`, `agsc-generated-at`, `agsc-counts`, `agsc-bundle-hash`, `agsc-ledger-head`) so that they can never collide with an RFC 8288 registered target attribute; `digest` is the RFC 9530 attribute and is the only unprefixed extension attribute used. Every attribute value is an array of strings. `type` values are advisory hints (RFC 9264 §4.2.2); `application/jsonl` is used for `/ledger.jsonl` and is deliberately unregistered — a reader MUST NOT depend on it. [audit/G §1 RFC 9264 row, RFC 8288, RFC 9530, V2-05, D55]
- **AGSC-06-11** Every `digest` value MUST be the RFC 9530 Structured-Field byte sequence `sha-256=:<base64 of the SHA-256>:` over the canonical bytes of the link target, and `agsc-ledger-head` MUST be the lowercase hex `hash` of the last entry of the derived ledger of §08 — the head that `verify --ledger` recomputes and compares. A ledger always has at least the trailing `build` entry (AGSC-08-20a), so the head is never undefined where the attribute is required; a Level-0 node publishes no `rel#ledger` link and therefore no head (AGSC-06-08a). `agsc-generated-at` MUST derive from `SOURCE_DATE_EPOCH`. [PRD-005, PRD-024, D44(h) as amended by D48(1) and D55]
- **AGSC-06-12** VoID (`/.well-known/void`, registered 2011) is prior art for dataset discovery and MUST be cited as complementary wherever this discovery layer is described. This specification **emits no VoID description**: `graph.jsonld` on the `describedby` link already carries the bundle-level facts (AGSC-06-08), AGSC-06-01's route set is closed, and a SHOULD-emit with no route would be unimplementable. A node that publishes a VoID description independently SHOULD link it from the link set with the registered relation `describedby`. [audit/G §1 VoID row ← V5-3 S3-09]

## 6.3 llms.txt

- **AGSC-06-13** `/llms.txt` MUST begin with a single H1 (the Bundle title), followed by one blockquote summary, then H2 sections whose bodies are link lists `- [title](url): one-line description`. An `Optional` H2 section MAY hold lower-priority links. [audit/G §1 llms.txt row]
- **AGSC-06-14** Every published item MUST be reachable from `/llms.txt`, directly or through a listed cluster section. `/llms-full.txt` carries the same index plus item bodies. [PRD-025 ← R33]
- **AGSC-06-15** Both files MUST open with the fixed provenance header naming the Bundle IRI, the licence `LicenseRef-AgenticSystemCore-Content-Use-1.0` and the build instant, and MUST fence every quoted body as ```` ```text agsc-content ```` so prose is presented as data, not instruction. [NFR-07 ← N9, ADR-001]

## 6.4 Machine surfaces and headers

- **AGSC-06-16** `search.json` MUST be a prebuilt inverted index `{terms:{token:[docIndex…]}, docs:[{slug,title,description,cluster}]}` requiring no runtime dependency. `docs[]` MUST be ordered by slug, each posting list MUST be ascending `docIndex` values without repetition, and the `terms` member names MUST be ordered as JSON member names per AGSC-04-05. Tokens are produced by AGSC-06-23 and by nothing else. An item with no `clusters[]` omits the `cluster` member, and an item with no `description` omits `description`; a member is never emitted as the empty string, so `search.json` stays a function of the authored keys. [PRD-014 ← D19, G15, D48(3)]
- **AGSC-06-23** **Tokenizer (normative).** For each item the tokenizer input is, in this order, `title`, `description`, every `tags` value and the body with fenced code blocks removed. The input MUST be NFC-normalized, then ASCII-lower-cased (only U+0041–U+005A are mapped; no locale casing, no case folding of non-ASCII), then split at every run of characters that are **not** token characters. A token character is `[a-z0-9]` or a character whose Unicode General_Category is `L*` (any letter), `Nd` (decimal digit) or `M*` (combining mark, so Devanagari and Thai words are not split); every other character — including `No`/`Nl` forms such as `²` and `Ⅷ`, and `Lo`-adjacent symbols — is a boundary. Non-ASCII letters and digits are kept code-point-wise and never transliterated. The General_Category table is that of **Unicode 15.1**; a port using another version MUST state it, since that is the only remaining source of divergence. A token shorter than 2 UTF-16 code units MUST be dropped. There is no stemming, no stop-word list, no synonym expansion and no n-gram: two conforming engines therefore emit byte-identical `search.json`. [PRD-014, NFR-04 ← D48(4)]
- **AGSC-06-17** `_headers` MUST set `Content-Type: text/markdown; charset=utf-8; variant=GFM` for `/pages/*.md`, `Content-Type: application/linkset+json; profile="https://w3id.org/agentic-system-core/profile/agentic-knowledge"` for `/.well-known/knowledge-linkset` — or, where the platform cannot carry the parameter, `application/linkset+json` plus `Link: <https://w3id.org/agentic-system-core/profile/agentic-knowledge>; rel="profile"` (AGSC-06-07) — and a `default-src 'none'` policy with `script-src 'self'`. `_redirects` MUST carry `/.well-known/agentic-knowledge` → 301 → `/.well-known/knowledge-linkset` (D60), and this alias MUST be present until the last 0.0.x consumer is retired. [PRD-020, D40, D60, audit/G §1 RFC 7763 row]
- **AGSC-06-18** One licence policy is expressed in exactly **three** machine-readable dialects at 1.x, and no more: the AI-usage signals of `robots.txt` (RFC 9309); the TDMRep policy at `/.well-known/tdmrep.json` (the TDM Reservation Protocol well-known location, and the **only** route that carries it — the duplicate copy at `/tdmrep.json` is not emitted); and the `schema:license`/`schema:usageInfo` members of the JSON-LD views together with `llms.txt`. `rsl.xml` and the aipref `Content-Usage` field are **not** emitted at 1.x, and no rule, route or claim may assert them. A policy divergence between any two of the three dialects MUST fail the build. Every prose-carrying export MUST embed the Content Use Terms, and a build omitting them MUST fail. [PRD-019 ← R39, D06, D39 ← V5-3 S3-10, S3-37]
- **AGSC-06-19** `sitemap.xml` MUST list every published route with `lastmod` from the build instant, ordered by URL. Schema.org JSON-LD (`TechArticle`, `DefinedTerm`, `Dataset`) MUST be embedded in item and index pages. [PRD-020 ← R41, R42]
- **AGSC-06-20** Generated HTML MUST meet WCAG 2.2 AA — semantics, keyboard operability, contrast, and `alt` text from the diagram's `alt` key. [NFR-08 ← N10]
- **AGSC-06-21** Budgets are normative and MUST fail the build when exceeded: ≤100 KB per HTML page; ≤1 KB of `search.json` per published item and ≤500 KB absolute at or below 500 items; ≤60 s build **per 500 items**; zero external page requests. Above 500 items a writer MUST shard the index as `/search-<nn>.json` (`<nn>` zero-padded from `01`, in slug order) with `/search.json` as the manifest `{shards:[…], docs_total}`, and MUST paginate any index route carrying more than 500 entries as `/<route>/page-<n>/` (`<n>` from `2`; page 1 is the route itself). The budgets are therefore per-scale, not absolute, and a 5,000-item Bundle conforms. Exceeding a budget that no sharding rule relieves MUST fail the build. [NFR-06 ← N8, V5-3 S3-05/S3-30]
- **AGSC-06-22** `/now/` and `/now.md` MUST be generated from stored state only — counts, last build, stale items, open Lessons, monthly spend — never hand-edited. A section whose input is absent MUST be omitted, not guessed. [PRD-015 ← R29, D44(a), G16]

- **AGSC-06-24** `/about/` MUST include a "Quickstart" section with one ≤10-line path per persona P0–P11 (P0 first: the three commands), generated from a template so it cannot drift from the verb set. `/about/` and the Internet-Draft's Security Considerations MUST both carry the AGSC-08-19 honest-limit statement verbatim. [PRD-052 ← D32(6), R56, V4-A A-73]
- **AGSC-06-25** A writer (Level 2 and above) MUST emit, in the `<head>` of every generated HTML page, `<link rel="agentic-knowledge" href="/.well-known/knowledge-linkset">`, and MAY additionally send the equivalent `Link: </.well-known/knowledge-linkset>; rel="agentic-knowledge"` response header. A Level-0 publisher SHOULD do the same, so that a CMS or wiki export that cannot inject a `<head>` element still claims Level 0 (AGSC-10-02). The relation name is the registered short name `agentic-knowledge` (D56) — unchanged by D60, which renames only the well-known suffix; where that registration is refused, the extension URI `https://w3id.org/agentic-system-core/rel#agentic-knowledge` MUST be used in its place and nothing else in this specification changes: the fallback uses the same hash form and the same authority as every other extension relation (AGSC-06-10, SPEC §6 decision 4), so a refused registration changes one string and no IRI ever depends on the site domain (D02). [PRD-024 ← D55, D56, D60, audit/TP TP-06]

> **rc.3 amendment (2026-09-16):** relation names gain `surface`, `contribute` and `access` under the same extension-URI form (AGSC-11-14/16/20); `_headers` additionally carries AGSC-11-03 and AGSC-11-05.
