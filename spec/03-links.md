# AGSC-03 — Links: the fourteen keys, inverses, combiner semantics

## 3.1 The closed vocabulary

- **AGSC-03-01** Typed Links MUST be frontmatter arrays whose key is one of exactly **fourteen** names — the **nine core** keys `related`, `broader`, `narrower`, `uses`, `requires`, `excludes`, `derived-from`, `contradicts`, `supersedes`, plus the **five Mode-2** keys `implements`, `verifies`, `covers`, `blocked-by`, `decided-by`. Of the core nine, `uses`, `requires`, `excludes`, `contradicts` and `supersedes` carry composition semantics (§3.5, §07), and `related`, `broader`, `narrower` and `derived-from` are navigational or provenance edges that never change a composition (AGSC-03-18); the Mode-2 five are navigational and provenance edges whose combiner semantics is `none`. No fifteenth key exists at `spec_version` 1.x; new keys arrive only through a registry a future MINOR defines *(Amended 2026-10-02 for 1.0.0: the sentence pointed to a document outside the specification for that registry)*. *(Amended 2026-10-10 for 1.0.0: the rule said that all of the core nine carry composition semantics, while AGSC-03-18 says that four of them never change a composition)* *(Amended 2026-10-29 for 1.1.0: the table gains four columns, Transitive reading, Self-link, Expected target kinds and Meaning, and the paragraph after the table says what each column means; no key, inverse, property or combiner changes, and the registry the previous sentence promises is the site vocabulary of AGSC-05-38, whose keys are the domain links of AGSC-03-27 under the one front-matter key `domain_links`, so the fourteen keys stay the closed list of Link keys)* [PRD-002]
- **AGSC-03-02** Each value MUST be a slug, optionally `<slug>#<anchor>`. Targets MUST resolve by exact slug — no suffix search, no case folding, no path guessing. An unresolved target is `AGSC-E301`. This holds for all fourteen keys: the Lint column of the table below names only the check a key adds to this one, so a cell reading "—" means no further check, and "target must exist" restates this rule for the keys that AGSC-03-09 and AGSC-03-20 name again. *(Amended 2026-10-10 for 1.0.0: the table's Lint column read as if four keys could keep an unresolved target)* [design]
- **AGSC-03-03** An unknown link-shaped key MUST be preserved and reported as a warning (`AGSC-E304`); it MUST NOT be treated as one of the fourteen. A key is **link-shaped** when its name is `peer-ref` (reserved to a later version, AGSC-00-20), `mentions` (AGSC-03-11) or one of the foreign relation names AGSC-03-19 and AGSC-03-20 list; every other unknown key is the warning `AGSC-E207` of AGSC-02-05, so that one key never carries two codes. *(Amended 2026-10-02 for 1.0.0: "link-shaped" was used and never defined.)* [design]

The four columns added at 1.1.0 read as follows. **Transitive reading**: `yes` means that a chain of the key, and of its computed inverse, may be read as one longer relation; the reading is computed (AGSC-05-33), is never written into the graph files, and never changes a composition (AGSC-03-18, AGSC-07-10). **Self-link**: what an item gets whose value for the key names the item itself (AGSC-03-23). **Expected target kinds**: advice that the warning of AGSC-03-25 checks; it is a validation shape and never an OWL domain or range (AGSC-05-26a); "same family" means the same `type`, with `concept` and `lesson` counted as one family. **Meaning**: one plain sentence for each key, written for the reader of an item; pages, legends and tool answers show it, and the vocabulary file repeats it as the `skos:definition` of the eight `asc:` properties of the keys `uses`, `excludes`, `contradicts`, `implements`, `verifies`, `covers`, `blocked-by` and `decided-by` (AGSC-05-16, AGSC-05-38).

## 3.2 Inverses

- **AGSC-03-04** Inverses MUST be computed at build and MUST NOT be authored. A file carrying an inverse name (`narrower` is authored; `used-by`, `required-by`, `derivation-of`, `superseded-by`, `implemented-by`, `verified-by`, `covered-by`, `blocks`, `decides` are not) as a key MUST be reported (`AGSC-E306`). [PRD-002]
- **AGSC-03-05** For symmetric keys (`related`, `excludes`, `contradicts`) the engine MUST materialize the edge in both directions even when only one side authored it. [design]
- **AGSC-03-06** `broader` and `narrower` are mutual inverses; asserting both directions between the same pair MUST be idempotent, not duplicated. [design]

## 3.3 Cycles and integrity

- **AGSC-03-07** `requires` MUST be acyclic. A cycle is error `AGSC-E302` and MUST name every slug on the cycle in discovery order. [PRD-036]
- **AGSC-03-08** `broader`/`narrower` MUST be acyclic (`AGSC-E303`). A cluster MUST have at most one `broader`; the mono-parent tree it forms MUST be at most 3 levels deep (family › deck › sub-deck). Neither bound follows from the other, so both are checked separately, after the acyclicity check: nesting deeper than 3 levels (a chain of `broader` ancestors longer than 2) is error `AGSC-E307` naming the chain root-first; more than one `broader` value is error `AGSC-E308` naming every parent slug in code-point order, and the schema enforces this second bound as `maxItems: 1` on the cluster branch. Both bounds count the `broader` values authored on cluster files: a cluster's parent is the one its own `broader` names, and a `narrower` on another cluster that names it adds an edge to the acyclicity check (`AGSC-E303`) but neither a second parent nor a level. *(Amended 2026-10-10 for 1.0.0: the rule did not say whether the bounds count authored values or computed edges)* [design]
- **AGSC-03-09** `derived-from` and `supersedes` targets MUST exist; a dangling target is `AGSC-E301`, not a warning. [design]
- **AGSC-03-10** An item with no inbound Link and no `clusters[]` entry MUST be reported as an orphan warning (`AGSC-E305`). A `clusters[]` entry **is** an inbound reference to the cluster it names, so a cluster that at least one item lists is never an orphan. An inbound Link is any Link edge whose target is the item, authored or computed (AGSC-03-04, AGSC-03-05): an item that authors a Link to an existing item receives the computed inverse or symmetric edge and is therefore not an orphan, while an inline link, which is an `asc:mentions` edge and not a Link (AGSC-03-11), does not count. *(Amended 2026-10-10 for 1.0.0: the rule did not say whether computed inverse and symmetric edges count as inbound)* [design]
- **AGSC-03-22** *(reserved: stated by AGSC-03-08, which gives both bounds and their codes; the id is never reused, AGSC-00-16.)*

The four checks below are warnings, because every input they judge is valid under 1.0 and a MINOR adds without refusing (AGSC-00-14). Each is carried by one item, named below, so that two implementations place the finding on the same item; each finding names the key and the other item.

- **AGSC-03-23** An item that lists itself, as `<own-slug>` or `<own-slug>#<anchor>`, in the array of a Link key other than `requires`, `broader` and `narrower` MUST be reported once per key as the warning `AGSC-E313`, carried by that item. An anchor does not change the verdict: the target is the item. A self-`requires` is the cycle error `AGSC-E302` (AGSC-03-07) and a self-`broader` or self-`narrower` the cycle error `AGSC-E303` (AGSC-03-08), and neither also raises `AGSC-E313`. The edge itself is still built and still follows AGSC-03-05 and AGSC-03-06. *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: so that an item that links to itself is told so)* [AGSC-03-01]
- **AGSC-03-24** A **pair** is an ordered pair of two different items `(A, B)`, read over the edges after AGSC-03-05 has made `excludes` and `contradicts` run both ways. The pair carries one of four combinations when `A` holds both keys toward `B`: `requires` with `excludes`; `requires` with `supersedes`; `requires` with `contradicts`; `uses` with `excludes`. Each combination of each pair MUST be reported once as the warning `AGSC-E314`, carried by `A`, the item that authors the `requires`, `supersedes` or `uses`, and naming `B` and both keys. Different combinations on one pair give different findings. Example: `a` has `requires: [b]` and `excludes: [b]`, which gives one `AGSC-E314` on `a` naming `b`, `requires` and `excludes`; `b` has `excludes: [a]` and no `requires`, which gives none on `b`. `requires` with `uses`, and keys held by `A` toward two different items, are not combinations. Composition fails or warns on these pairs anyway (AGSC-07-05a, AGSC-07-06, AGSC-07-07); the finding only tells the author earlier. *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: so that two relations that cannot both hold are caught when the author writes them, not when someone composes)* [AGSC-03-01]
- **AGSC-03-25** A resolved target that does not match the **Expected target kinds** cell of the row of its key in AGSC-03-01 MUST be reported as the warning `AGSC-E315`, carried by the item that authors the key, once per key and target. A cell reading `any` never warns. For `derived-from` the cell binds only when the item is a `lesson`; for `broader` and `narrower` both items must belong to one family (defined in the paragraph after the table of AGSC-03-01), and `concept` and `lesson` are one family; for `supersedes` both items must have the same `type`. An unresolved target is reported by AGSC-03-02 and is not also judged here. The check is a validation shape for the shapes lane of AGSC-05-24; it is never an OWL domain or range (AGSC-05-26a). *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: so that a link whose target is not of the kind the key is meant for is flagged)* [AGSC-03-01]
- **AGSC-03-26** A `supersedes` target whose status is `stable`, authored or by default (AGSC-02-23), MUST be reported as the warning `AGSC-E316`, carried by the item that authors the `supersedes` and naming the target. A target that is `deprecated`, `retired` or `draft` raises nothing: the first two already say they are replaced, and a draft is on no published surface (AGSC-06-30). The warning changes nothing about either item: supersession stays orthogonal to `status` (AGSC-02-23), and the hiding step of composition is as before (AGSC-07-10). *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: so that an author who replaces an item is reminded to deprecate the old one)* [AGSC-03-01]

## 3.4 Inline links and wikilinks

- **AGSC-03-11** Inline Markdown links between items produce untyped graph edges `asc:mentions`. `mentions` is not a Link key and MUST NOT appear in frontmatter. A relative Markdown link or image whose target is **inside** the Bundle MUST resolve to an existing item, an existing asset under `content/assets/`, or an existing anchor of one of them; an unresolved internal target is **`AGSC-E310`** (error), and this is the check that the `links` value of AGSC-08-11's gate compiles to. Two resolution questions are settled here: a target **without a file extension** resolves — both `<slug>` and `<slug>.md` name the same item, and the extension-less form is the one wikilink normalisation produces — and a target containing `..` segments is resolved relative to the file that carries it, `AGSC-E902` only when what it resolves to escapes the Bundle root and `AGSC-E310` when it stays inside and does not exist (AGSC-01-35). A link to an external origin is never resolved at build time — it is checked only by `refresh` (AGSC-04-11) — and a reference reported as `AGSC-E507` during adoption (AGSC-02-95) is `AGSC-E310` on every subsequent build, since adoption is a one-time warning and the Bundle is thereafter authored. [AGSC-08-11]
- **AGSC-03-12** Wikilinks `[[target(#anchor)?(|alias)?]]` MAY appear in authored files and MUST be normalized by `lint --fix` to relative Markdown links `[alias](../<type-plural>/<slug>.md#anchor)`. `![[…]]` embeds MUST be converted to images or removed. Dendron's reversed `[[alias|note]]` order MUST NOT be assumed without an explicit import flag. The two outcomes of an embed are settled by its target: an embed whose target ends in `.avif`, `.gif`, `.jpeg`, `.jpg`, `.png`, `.svg` or `.webp` becomes an image whose text is the alias, or the target when there is no alias, and every other embed is removed. A wikilink with no alias takes its target slug as the link text. `lint --fix` leaves a wikilink whose target names no item of the Bundle as authored and reports the warning `AGSC-E506`, because rewriting it would point a relative link at a file that does not exist; `lint` without `--fix` does not report wikilinks at all: they are normalised, not judged. *(Amended 2026-10-10 for 1.0.0: the rule did not say which embeds become images, what text an alias-less wikilink takes, or what happens to a wikilink naming no item)* [design]
- **AGSC-03-13** Heading anchors MUST be computed as: NFC → ASCII lowercase → remove characters outside `[a-z0-9 -]` → spaces to `-` → collapse repeated `-` → **trim leading and trailing `-`**; an empty result becomes `section-<n>`, `<n>` being the 1-based document order of the heading among the headings whose anchor is empty. A duplicate anchor takes the suffix `-2`, then `-3`, … in document order, re-checking after each suffix and taking the next free one, so a suffixed anchor never collides with a naturally occurring anchor. Every anchor produced by this algorithm therefore matches `^[a-z0-9](?:[a-z0-9-]*[a-z0-9])?$` — no leading or trailing `-`, and never `--` — the `link_target` grammar of `schema/item.schema.json`, which AGSC-03-02 applies. *(Amended 2026-10-07 for 1.0.0: the grammar is named as the item schema's, which AGSC-03-02 applies; the sentence had pointed at AGSC-03-02 alone.)* [design]

## 3.6 Import mapping

- **AGSC-03-19** Foreign link names MUST be mapped on import, not added to the vocabulary: `refines` → `narrower`; `alternative-to`, `conflicts-with` → `excludes`; `composed-of` → `uses`; `mitigates` → `related`; combiner `oneOf` → pairwise `excludes`; `recommends` → `uses`. [design]
- **AGSC-03-20** The Mode-2 typed links are **defined at 1.0** as keys 10–14 (AGSC-03-01): `implements`, `verifies`, `covers`, `blocked-by`, `decided-by`. Foreign spellings MUST be mapped on import — `blockedBy` → `blocked-by`, `decidedBy` → `decided-by`, `tests` → `verifies`, `traces-to` → `covers` — and their targets MUST exist (`AGSC-E301`); they never affect a composition (AGSC-03-18, AGSC-07-10). [design]
- **AGSC-03-21** Links are the only stored relations. Embeddings, spreading activation, transclusion and bi-temporal edges MUST NOT be introduced. [design]

## 3.7 Domain links

- **AGSC-03-27** A node that declares a site vocabulary (AGSC-05-38) MAY state **domain links**: typed links whose type the site vocabulary defines. They are written under the front-matter key `domain_links`, an object whose member names are the local names of the object properties of the site vocabulary (resolved as AGSC-02-25 resolves `domain_type`: in the namespace of the item's context when it has one, otherwise in the vocabulary's own) and whose values are arrays of slugs or `<slug>#<anchor>`, resolved as AGSC-03-02 resolves them (an unresolved target is reported by that rule). A member name that is not an object property of the site vocabulary, a vocabulary property whose super-property is `skos:related`, `skos:broader` or `skos:narrower` used where the item or the target is a `cluster` (it would entail a `skos:Concept` typing for a `skos:Collection`, AGSC-05-20), and a member that authors the computed inverse of another property are each the error `AGSC-E317`; for a pair declared with `owl:inverseOf`, the computed property is the object of the `owl:inverseOf` statement as the file writes it, and where the file declares the pair in both directions it is the property whose IRI is greater in code-point order. If the vocabulary declares `owl:inverseOf` or `owl:SymmetricProperty` for a property, the inverse or symmetric edge is materialized as AGSC-03-04 and AGSC-03-05 do and is not authored. A domain link is not one of the fourteen keys: it is never checked by AGSC-03-23 to AGSC-03-26, never closes a `requires` cycle, never adds, removes or hides an item in a composition, whatever its super-property (AGSC-03-18, AGSC-07-10), and counts as an inbound reference for AGSC-03-10. The graph carries it as the triple `<item> <property IRI> <target>` (AGSC-05-39). A node that uses the key SHOULD declare `spec_version` `1.1.0` or later (AGSC-01-18). *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: for the optional domain layer; a node that declares no site vocabulary is unchanged)* [AGSC-05-38]
