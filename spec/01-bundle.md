# AGSC-01 — Bundle: files, folders, encoding, configuration

## 1.1 Layout

- **AGSC-01-01** A Bundle MUST be a directory tree containing `content/` and exactly one `agsc.config.json` at its root. One repository is one Bundle. [audit/D §1.1, D32(4)]
- **AGSC-01-02** Items MUST live at `content/<type-plural>/<slug>.md` where `<type-plural>` ∈ `concepts`, `episodes`, `procedures`, `lessons`, `clusters`, `gates`. [audit/D §1.1, G02]
- **AGSC-01-03** The `type` key in frontmatter is authoritative and MUST match the containing folder; a mismatch is an error (`AGSC-E205`). [audit/D §1.1]
- **AGSC-01-04** `content/index.md` is the Bundle root document. It MUST carry `spec_version`, `okf_version`, `title`, `description` and `base` (the IRI base of every item, AGSC-05-01; it MUST equal `site.base`; a mismatch is `AGSC-E204`), and it MUST NOT carry `type`; it is not an item and does not enter the graph as an item. [audit/D §1.1, OKF v0.2]
- **AGSC-01-05** `index.md` MAY exist in any folder (OKF reserved). `_index.md` and `README.md` MUST NOT be used as items. [research/12 §P rule 3]
- **AGSC-01-06** Non-knowledge site pages live in `site/*.md`, outside `content/`. They are rendered but MUST NOT appear in the graph, in `search.json` or in `llms.txt` item lists. [audit/D §1.1, G40]
- **AGSC-01-07** Diagram sources live at `content/diagrams/<slug>.diagram`. A compiled `.svg` MUST NOT be committed; it is produced into the build output. [audit/D §2.2, D20]
- **AGSC-01-08** `www/` (build output) and `dist/` (proposals, harnesses, gate verdicts) are generated. An implementation MUST NOT read them as input to a build. [audit/D §2.2, D47]
- **AGSC-01-09** A Harness MUST NOT be written under `content/`. [audit/D §1.1]

## 1.2 Slugs and identity

- **AGSC-01-10** A slug MUST match `^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$` and MUST NOT contain `--`. Length is 1–64 characters. [research/12 §P rule 2 as corrected; Agent Skills name rule]
- **AGSC-01-11** The slug is the file stem, the value of `id` when present, and the last path segment of the item IRI. Slugs MUST be unique across the whole Bundle regardless of folder (`AGSC-E206`). [research/12 §P rule 2, audit/D §1.1]
- **AGSC-01-12** A slug is permanent. A renamed or superseded item keeps its slug; the new item gets a new slug and the relationship is expressed with `supersedes` (§03). Reuse of a retired slug is an error. [PRD-018 ← R40]
- **AGSC-01-13** Language variants are `<slug>.<lang>.md` with `lang` a lowercase BCP 47 tag equal to the file's `lang` key, and they are **accepted at 1.0** (D53; the deferral of G27 is lifted). The unsuffixed file is the **primary** and owns the slug, the item IRI (AGSC-05-01) and the graph node; a variant shares that slug, is published at the route `/<type-plural>/<slug>/<lang>/` (AGSC-06-01) and is emitted in RDF as the language-tagged literals of AGSC-05-17, never as a second item. A variant whose primary is missing is `AGSC-E208`; a variant whose suffix and `lang` key disagree, or whose `lang` is not lowercase BCP 47, is `AGSC-E205`. `i18n.default` in `agsc.config.json` names the primary's language (default `en`). [research/12 §P rule 4, G27 ← D53]
- **AGSC-01-13a** (amends AGSC-01-13) A variant MUST share its primary's Link keys and `clusters[]`; divergence is warning `AGSC-E410`. The primary's page MUST carry `hreflang` alternates for every variant. Everything else about variants is AGSC-01-13. [PRD-055, D53, research/12 §7, V4-A A-36]

## 1.3 Encoding

- **AGSC-01-14** Every `.md`, `.json`, `.ttl` and `.diagram` file MUST be UTF-8 without BOM, MUST use LF line endings, MUST be NFC-normalized, and MUST end with exactly one LF (`AGSC-E108`). [research/12 §P rule 1, Art. XII]
- **AGSC-01-15** File discovery order MUST be a code-point sort of the repository-relative path, with `/` as the path separator in the sort key on every platform (a native `\` separator MUST be converted before comparison). Locale collation MUST NOT be used. [research/12 §P rule 24, D48(3)]
- **AGSC-01-16** An input file larger than 1 MiB MUST be refused with `AGSC-E904`. Archives MUST be refused entirely (`AGSC-E903`), and any path escaping the Bundle root MUST be refused with `AGSC-E902`. [PLAN §11 R7, research/17 §1.9]

## 1.4 Configuration

- **AGSC-01-17** A Bundle MUST have exactly one configuration file, `agsc.config.json`, validated against `schema/config.schema.json`. A second configuration file MUST NOT be introduced. [PRD-006 ← R44, D32(4)]
- **AGSC-01-18** Its keys are `spec_version`, `site{base,title,tagline,author,analytics_token}`, `bundle{id,license_prose,license_schema,operator}`, `ns{base,version}`, `releases{}`, `tags{allowed[]}`, `build{out,rdfxml,feed}`, `i18n{default}`, `lint{injection_patterns[]}`, `peers[]`, `run{enabled,allow[]}`, `channels[]{name,adapter,author,owner,publish,allow[],rate{per_hour}}`. `channels[].allow[]` is an OPTIONAL array of strings naming the sender identities an adapter accepts (an empty or absent array accepts every sender) and `channels[].rate{per_hour}` an OPTIONAL integer bounding the messages one channel may ingest per hour, both required by AGSC-01-30's ingest guard; they are the **only** keys added after the `1.0.0-rc.2` freeze (D61(3)). `site.analytics_token` is an edge-analytics token consumed only by the hosting platform; a build MUST NOT emit it into any artefact and MUST NOT load a third-party script for it (AGSC-06-05). `bundle.license_prose` and `bundle.license_schema` are SPDX or `LicenseRef-` identifiers, defaulting to `LicenseRef-AgenticSystemCore-Content-Use-1.0` and `CC0-1.0`; they supply the licence identifiers of AGSC-06-15, AGSC-01-26 and AGSC-07-16. `i18n.default` is OPTIONAL and defaults to `en` (AGSC-01-13/01-13a); `peers[]` is required by AGSC-10-12 (each entry a peer node's canonical well-known URL) and `run{enabled,allow[]}` is required by AGSC-09-94 (`enabled` default `false`). There is no `build.search` toggle: `search.json` is required unconditionally by AGSC-06-16, and a switch that could turn off a MUST would make the two rules unsatisfiable together (V2-06). Configuration is closed: an unknown key is `AGSC-E004`. The single exception is the `x-<vendor>-<key>` namespace of `docs/SPEC.md` §8(2) — matching `^x-[a-z0-9]+(-[a-z0-9]+)+$`, admitted by `config.schema.json`'s `patternProperties` at the top level and on each `channels[]` entry while `additionalProperties` stays `false` — which every conforming tool preserves verbatim, never interprets and never reports as `AGSC-E004` (D61(3); the frontmatter twin is AGSC-02-05a). `ns{base,version}` is present for forward compatibility only: AGSC-05-02 makes the vocabulary IRI a constant of this specification, so no conforming tool reads a value other than the default and a Bundle that omits the object is identical to one that spells it out (V5-3 S3-34). A Bundle that omits `bundle.license_prose` or `bundle.license_schema` takes `LicenseRef-AgenticSystemCore-Content-Use-1.0` and `CC0-1.0`; the values are echoed verbatim into `/legal/`, `content/index.md` `license` and every JSON-LD `schema:license`, and nothing else reads them (V5-3 S3-38). [audit/D §2.3, PRD-006]
- **AGSC-01-19** `build.out` MUST default to `www`; a trailing `/` is accepted and stripped. `site.base` MUST be an absolute `https:` URL — an origin, optionally with a path prefix, so that a node may be published under a sub-path — with or without a trailing slash (a trailing slash is stripped before IRIs are formed), and is the IRI base of every item (§05). The single exception is the development placeholder `http://localhost` or `http://localhost:<port>` (optionally with a trailing slash), which adoption writes (AGSC-02-94) and which lint MUST report as `AGSC-E506` — "set `site.base` before publishing" — until the owner replaces it. [D47, D41, D52(1)]
- **AGSC-01-20** `releases` is a boolean switchboard: an item carrying `release: <key>` is published only when `releases[<key>]` is `true`. An item with no `release` is always published. [PRD-021 ← R8]
- **AGSC-01-21** `tags.allowed` is the closed tag vocabulary; a tag outside it MUST be reported (`AGSC-E203`). When `tags` is absent from `agsc.config.json` there is no closed vocabulary and `AGSC-E203` is not raised for a tag; the 2–5 count warning of the §2.2 table still applies. [audit/D §1.2]
- **AGSC-01-25** `bundle.operator` is OPTIONAL and, when present, MUST be a `human:<id>` actor string (AGSC-02-07). It is the accountable operator of this Bundle and is the first source of `prov.operator` at adoption (AGSC-02-90). No other configuration key supplies an actor. [PRD-053 ← D48(5), D07]

## 1.5 Import tolerance

- **AGSC-01-22** Import of a foreign OKF v0.2 bundle MUST accept unknown `type` values (mapped to `concept` with a warning), unknown keys, missing optional fields, missing `index.md` and broken links. A broken internal link is a Gate failure for the Bundle's own build but MUST NOT reject an import. [research/12 §P rules 30, 31]
- **AGSC-01-23** Import MUST be deterministic and idempotent: re-running it over unchanged input MUST produce byte-identical output and MUST NOT create duplicate items. Colliding slugs MUST be suffixed `-2`, `-3`, … in discovery order. [PRD-021]
- **AGSC-01-24** Import MUST refuse a source record carrying a non-empty `bookRef` field (`AGSC-E405`). [PRD-021 ← W1/W11, Art. XIII]

## 1.6 Export

- **AGSC-01-26** `export --markdown` and `export --okf` MUST emit the lint-normalized Bundle itself — one `.md` file per item, frontmatter first, body bytes unchanged — and MUST be **lossless**: every authored frontmatter key, including unknown keys preserved under AGSC-02-05, MUST appear in the output. The result MUST open as a plain folder of Markdown in any editor or vault tool without a plugin. `--okf` additionally writes `content/index.md` with `okf_version` and the OKF-reserved `log.md`, whose content is one line `- <slug>: <modified, else date, else the empty string>` per item in slug order (an empty file when the Bundle has no item). Because these outputs are byte-preserving, the Content Use Terms travel **beside** them, not inside them: `index.md` carries `license` and the export root carries a `LICENSE-CONTENT` file (AGSC-01-29). [PRD-026 ← V2-26, V3-04, V3-26]
- **AGSC-01-26a** Beyond the five flags of AGSC-01-26/01-27 an implementation MAY ship **memory adapters** selected by `export --to <adapter>` / `import --from <adapter>` (the Basic Memory and GABBE-memory both-ways adapters of D39/D53 among them; Obsidian needs none, since AGSC-01-26's vault-openability clause already covers it). An adapter MUST be a single module discovered by directory convention (`src/interchange/adapters/*.js`) and never by a configuration key (D61(3)); MUST be lossless in both directions for every key it claims, with AGSC-01-23's idempotence applying to a round trip; MUST carry AGSC-01-29's header and terms on every prose-carrying output; MUST NOT emit an executable, a symlink or an `allowed-tools` declaration (AGSC-07-15); and MUST be listed with its claimed key set in `docs/IMPLEMENTERS-GUIDE.md`. Adapters are never required for conformance at any Level (AGSC-10-04). [PRD-026, D39, D53 ← V5-3 S3-18]
- **AGSC-01-27** `export --jsonld` output MUST be byte-identical to the `graph.jsonld` of the same build (AGSC-05-06, AGSC-04-04); `export --jsonl` MUST emit one JCS-canonical JSON object per LF-terminated line, one line per item, items in slug order, each line being exactly the per-item JSON-LD node of `pages/<slug>.jsonld`. Neither MAY invent a member that the graph does not carry; the licence travels as the JSON-LD `schema:license`/`schema:usageInfo` members the graph already carries (D39), never as a text header. [PRD-026, PRD-022 ← V2-26, V3-04, V3-26]
- **AGSC-01-28** `export --steer [--target <name>…]` MUST emit steer bundles derived **only** from NOW state and from `concept`, `procedure`, `gate` and `lesson` items — never from an Episode, a Proposal or the git log — so that the same Bundle always yields the same bytes (AGSC-04-01). `<name>` is drawn from this **closed** registry, and each target writes exactly the one path named here and nothing outside it:

  | target | path |
  |---|---|
  | `agents` | `AGENTS.md` |
  | `claude` | `CLAUDE.md` |
  | `cursor` | `.cursor/rules/agsc.mdc` |
  | `copilot` | `.github/copilot-instructions.md` |
  | `gemini` | `GEMINI.md` |
  | `codex` | `.codex/instructions.md` |
  | `gabbe` | `GABBE/agents/AGENTS.md` |
  | `kiro` | `.kiro/steering/agsc.md` |
  | `windsurf` | `.windsurf/rules/agsc.md` |
  | `cline` | `.clinerules/agsc.md` |
  | `aider` | `CONVENTIONS.md` |

  The default is `agents,claude`. Every target derives from the same source set, is byte-stable (AGSC-04-01) and carries AGSC-01-29's header and terms; no target writes outside its named path and no twelfth target exists at 1.x — a new one is a MINOR bump with a registry row and a vector, exactly as a new Link key is (SPEC §8). An item whose most recent content-branch commit carries a `Channel-Auto:` trailer MUST be **excluded** from every target's output until a human `verified[]` entry is added to it; that exclusion is what lets AGSC-08-26(b) admit `concept`, `episode` and `lesson` into the auto lane at all. [PRD-029, D35, D53 ← V2-26, V5-3 S3-17, S3-12]
- **AGSC-01-29** Every **agent-facing digest** — `export --steer` (AGSC-01-28) and any other export that re-narrates item prose rather than copying it — MUST carry the fixed provenance header of AGSC-06-15, MUST fence quoted item prose as ```` ```text agsc-content ````, and MUST embed the Content Use Terms identifier; a build that omits them MUST fail. The byte-preserving exports of AGSC-01-26/27 MUST NOT be fenced or prefixed — that would break their losslessness and their byte-identity with `graph.jsonld` — and carry the terms as AGSC-01-26/27 state (a `LICENSE-CONTENT` file plus `index.md` `license`; the JSON-LD licence members). Steer bundles are governed exactly like `llms.txt` (AGSC-06-15) and the Harness files (AGSC-07-14). [NFR-07, PRD-019 ← R39, ADR-001, V2-26, V3-04]

## 1.7 Channel ingest (added 2026-09-03, S01 Amendment 5)
- **AGSC-01-30** A **Channel adapter** (`channels/<name>/`) MUST expose `pull(since) → messages[]` and `render(message) → { path, frontmatter, body }` producing a conforming item (AGSC-02) under `content/<type-plural>/`; it MUST NOT write to the content branch directly — ingestion always yields a Proposal (AGSC-08-01..). The CI ingest job pushes the Proposal branch and opens the pull request with the ingest credential `CHANNEL_TOKEN_<name>`, a fine-grained token scoped to the **content repository** with `contents: write` and `pull-requests: write`, never `GITHUB_TOKEN` and never in a fork context. Forge fine-grained tokens are **not** ref-scoped — their permissions are repository-wide — so the branch **ruleset**, never the token, is what prevents a direct push to the content branch, and the ingest identity MUST NOT appear as a bypass actor on that ruleset (AGSC-08-26(f) gives the separate merge credential that MAY). `propose` itself still performs no network write (AGSC-08-04). The job MUST reject a message whose sender is absent from a non-empty `channels[].allow[]`, and MUST stop for the current hour once `channels[].rate{per_hour}` messages have been ingested (AGSC-01-18), recording the skipped messages by `sources[].id` for the next run. `render` MUST redact e-mail addresses and telephone numbers from the body (AGSC-08-16) and record the sender only in `sources[0]`. A channel MUST NOT have more than five open Proposals at once; the ingest job MUST stop opening pull requests at that bound and record the skipped messages by `sources[].id` for the next run (idempotence, AGSC-01-33). [PRD-043, PRD-056, D52(4), D61(2)/(3), V3-29, V3-32, V5-3 S3-11, S3-20]
- **AGSC-01-31** Each channel declares `publish: auto | hitl` (default `hitl`) in `agsc.config.json` (`channels[]`). In `hitl` the Proposal waits for the author's `verified[]`; in `auto` it MAY be merged only under AGSC-08-26, whose guard is verified against configuration and forge identity, never against self-declared frontmatter: the pull-request author MUST equal `channels[].author`, `prov.operator` MUST equal `channels[].owner`, and every ingested item MUST carry `prov.agent` (the adapter id) with `prov.origin: imported` — so the N9 lints run at `error` severity (AGSC-08-14) instead of warning. [PRD-056, AGSC-08-05, AGSC-08-26, N9, D52(4)]
- **AGSC-01-32** Optional AI correction in `auto` mode is limited to formatting/frontmatter/typo repair; it MUST NOT add claims, links or Sources, MUST run under the configured spend cap (NFR-11) and MUST record its spend by adding to the same Proposal one `episode` item carrying `usage{model, tokens_in, tokens_out, cost_usd, estimate}` (AGSC-02-14) and `prov.agent` = the adapter id — the same mechanism AGSC-09-14a requires of an LLM responder, and the only one AGSC-08-25's monthly rollup can see, since a Proposal has no file (AGSC-00-06) and the ledger has no `proposal` kind at 1.0 (AGSC-08-21). A correction whose spend cannot be recorded MUST NOT run. Without a key the adapter still works (lint-only). [PRD-056, D14 ← V5-3 S3-13]
- **AGSC-01-33** Ingested messages MUST be de-duplicated by a stable `source_id` kept in `sources[].id` (a member of the `source` object, AGSC-02-10); re-ingesting is a no-op (idempotent), and the original channel/message reference is the item's first Source. A channel message that has no web URL uses the resource form `urn:agsc:channel:<name>:<source_id>`, which the schema admits alongside `https?://`. [PRD-056, AGSC-02, V3-32]


> **rc.3 amendment (2026-09-16):** `agsc.config.json` gains the OPTIONAL objects `federation{}`, `chunks{}`, `contribute[]` and the key `visibility` (AGSC-11-01), each admitting `x-<vendor>-<key>`; these are the keys added at rc.3.
