# AGSC-01 — Bundle: files, folders, encoding, configuration

## 1.1 Layout

- **AGSC-01-01** A Bundle MUST be a directory tree containing `content/` and exactly one `agsc.config.json` at its root. One repository is one Bundle. An input file a verb requires and cannot open is `AGSC-E901`. [design]
- **AGSC-01-02** Items MUST live at `content/<type-plural>/<slug>.md` where `<type-plural>` ∈ `concepts`, `episodes`, `procedures`, `lessons`, `clusters`, `gates`. [design]
- **AGSC-01-03** The `type` key in frontmatter is authoritative and MUST match the containing folder; a mismatch is an error (`AGSC-E205`). [design]
- **AGSC-01-04** `content/index.md` is the Bundle root document. It MUST carry `spec_version`, `okf_version`, `title`, `description` and `base` (the IRI base of every item, AGSC-05-01; it MUST equal `site.base`, and a 1.0 writer forms every IRI from `site.base`), and it MUST NOT carry `type`; it is not an item and does not enter the graph as an item. A `type` key on the Bundle root is `AGSC-E205` — a file-placement violation, because the root is not an item — and `bundle.schema.json` refuses it. *(Amended 2026-10-12 for 1.0.0: a 1.0 writer forms every IRI from site.base; reporting a root base that differs from site.base as AGSC-E204 is planned for 1.1 (AGSC-00-20).)* *(Amended 2026-10-29 for 1.1.0: from 1.1 `lint`, `build` and `ci` report a root `base` that differs from `site.base` (compared after a trailing slash is stripped from both) as the warning `AGSC-E204`, naming the file; the warning changes no exit code and no emitted byte, because a writer still forms every IRI from `site.base`)* [OKF v0.2]
- **AGSC-01-05** `index.md` MAY exist in any folder (OKF reserved). `index.md`, `_index.md` and `README.md` MUST NOT be used as items: `content/index.md` is the Bundle root document (AGSC-01-04), and an `index.md` in any other folder is a note about that folder, as the other two names are. A reader MUST NOT read an `index.md`, a `README.md` or an `_index.md` in any folder under `content/` as an item — the Bundle root document apart, which it reads as the root — and SHOULD report each one it skips as the warning `AGSC-E506`. The three names are compared ASCII case-insensitively, because on a case-insensitive file system `Index.md` is `index.md`. *(Amended 2026-10-10 for 1.0.0: an `index.md` inside a type folder, which the first sentence permits, was read as an item and failed lint for want of `type` and `prov`; it is now a folder note like the other two names, and the comparison of the names is stated)* [design]
- **AGSC-01-06** Non-knowledge site pages live in `site/*.md`, outside `content/`. They are rendered but MUST NOT appear in the graph, in `search.json` or in `llms.txt` item lists. [design]
- **AGSC-01-07** Diagram sources live at `content/diagrams/<slug>.diagram`. A compiled `.svg` MUST NOT be committed; it is produced into the build output **as part of the item's page and not as a route of its own** (AGSC-02-13) — `.svg` names the compiled artefact, never a URL, so AGSC-06-01's "exactly this route set" stays exact. The `.diagram` **source grammar and the SVG bytes it compiles to are pinned from 1.1 by AGSC-01-42**; at 1.0 both were implementation-defined, and a writer that has not adopted AGSC-01-42 draws the same source differently without fault. Generated HTML stays outside cross-implementation identity (AGSC-04-24); the compiled SVG that a page inlines is the one part of a page whose bytes AGSC-01-42 pins. A picture whose bytes must be portable at 1.0 is an SVG **attachment** under AGSC-02-98, which is authored, hashed and served as itself. A `.svg` under `content/diagrams/` is `AGSC-E205`, a file-placement violation. *(Amended 2026-10-29 for 1.1.0: the grammar and the compiled bytes are pinned by the new rule AGSC-01-42; the sentence that made both implementation-defined at 1.x and called pinning a 1.1 candidate is replaced)* [design]
- **AGSC-01-08** `www/` (build output) and `dist/` (proposals, harnesses, gate verdicts and the forge enforcement artefacts of AGSC-08-12) are generated. An implementation MUST NOT read them as input to a build. [design]
- **AGSC-01-09** *(reserved: stated by AGSC-07-12, whose only legal location is dist/harness/, together with AGSC-01-08; the id is never reused, AGSC-00-16.)*

## 1.2 Slugs and identity

- **AGSC-01-10** A slug MUST match `^[a-z0-9]+(?:-[a-z0-9]+)*$` and be 1–64 Unicode code points long (`minLength`/`maxLength` in the schemas, AGSC-02-24) — a grammar that forbids a leading, trailing or doubled `-` by construction and compiles in RE2, Go and Rust. It is equivalent to `^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$` plus "MUST NOT contain `--`". Because a slug is lower-case ASCII, two item files never differ only in case, so the grammar alone keeps item paths apart on a case-insensitive file system; and because a slug is at most 64 characters, an item's path under the Bundle root is at most 86 characters (`content/procedures/`, the slug, `.md`). Three things no 1.0 rule refuses: a slug that Windows reserves as a device name, such as `con`, `prn`, `aux`, `nul`, `com1` or `lpt1`, which matches the grammar; two paths under `content/attachments/` or `content/assets/` that differ only in case; and the length of such a path, which only the grammar of AGSC-01-35 governs. From 1.1 AGSC-01-40 reports each of them as a warning; none is refused. *(Amended 2026-10-10 for 1.0.0: what the grammar settles on case-insensitive and length-limited file systems, and what it leaves open, is stated)* *(Amended 2026-10-29 for 1.1.0: the three cases, and two more, are reported as warnings by the new rule AGSC-01-40; the grammar and the refusals are unchanged)* [Agent Skills name rule]
- **AGSC-01-11** The slug is the file stem, the value of `id` when present, and the last path segment of the item IRI. Slugs MUST be unique across the whole Bundle regardless of folder (`AGSC-E206`). [design]
- **AGSC-01-12** A slug is permanent. A renamed or superseded item keeps its slug; the new item gets a new slug and the relationship is expressed with `supersedes` (§03). Reuse of a retired slug is an error, `AGSC-E206` — the slug's second use in the Bundle, since the retired item is still present (AGSC-11-22); a writer that has the git-log file of AGSC-08-20b SHOULD also report a slug that an earlier commit deleted, which is invisible without history. [PRD-018]
- **AGSC-01-13** Language variants are `<slug>.<lang>.md` with `lang` a BCP 47 tag — compared case-insensitively, the file suffix and every emitted tag being the lower-cased form (AGSC-05-31) — equal to the file's `lang` key, and they are **reserved to a later MINOR** (AGSC-00-20). At 1.0 a file named `<slug>.<lang>.md` — at 1.0 any file whose stem holds a `.`, whatever follows the first one — is a second use of its primary's slug, `AGSC-E206`, and no variant route is emitted. Such a file whose primary is absent — no file of the Bundle has the stem `<slug>` — has a stem that is not a slug (AGSC-01-10, AGSC-01-11), and a reader reports it as `AGSC-E204`, naming the file and the slug before the first dot, instead of reading it as that slug (`AGSC-E208` below is the code for that case once variants are defined). The MINOR that defines variants adds the route, the tags and the vectors and removes nothing. At 1.0 as at 1.1, an item with no `lang` key takes `i18n.default`, and `en` when that key is absent as well (AGSC-01-18); that is the language tag of its labels (AGSC-05-31). What follows is the definition reserved to that MINOR. The unsuffixed file is the **primary** and owns the slug, the item IRI (AGSC-05-01) and the graph node; a variant shares that slug, is published at the route `/<type-plural>/<slug>/<lang>/` (AGSC-06-01) and is emitted in RDF as the language-tagged literals of AGSC-05-17, never as a second item. A variant whose primary is missing is `AGSC-E208`; a variant whose suffix and `lang` key disagree, is `AGSC-E205`, while a `lang` that is not a **well-formed** BCP 47 tag is a schema pattern violation and takes `AGSC-E204` (precedence, §9.4) — case is not part of well-formedness: a tag is compared case-insensitively and emitted lower-cased, so `en-GB` is valid input and `en-gb` is what is emitted. `i18n.default` in `agsc.config.json` names the primary's language (default `en`). *(Amended 2026-10-10 for 1.0.0: a variant file whose primary is absent was read silently as its primary's slug, and the language of an item with no `lang` key was stated only for the 1.1 primary; both are now stated for 1.0)* *(Amended 2026-10-29 for 1.1.0: language variants move from 1.1 to a later MINOR; a 1.1 tool treats a variant file as a 1.0 tool does)* [design]
- **AGSC-01-13a** (qualifies AGSC-01-13) A variant MUST share its primary's Link keys and `clusters[]`; divergence is warning `AGSC-E410`. The primary's page MUST carry `hreflang` alternates for every variant. Everything else about variants is AGSC-01-13, and this rule is reserved to the same later MINOR with it. *(Amended 2026-10-29 for 1.1.0: reserved to a later MINOR, with AGSC-01-13)* [PRD-055]

## 1.3 Encoding

- **AGSC-01-14** Every `.md`, `.json`, `.ttl` and `.diagram` file MUST be UTF-8 without BOM, MUST use LF line endings, MUST be NFC-normalized, and MUST end with exactly one LF (`AGSC-E108`); a `.md` file MUST NOT contain U+0000 or any other C0 control character except U+0009 and U+000A, anywhere including the body, which is also `AGSC-E108` *(Rationale: an HTML renderer replaces a NUL in a body while `/chunks.jsonl` carries it to every agent, so two writers could differ)*. A frontmatter or configuration string — a value or a member name — that is not a sequence of Unicode scalar values (a lone surrogate, which a UTF-8 file can hold only as a YAML or JSON escape such as `\uD800`) is also `AGSC-E108`, reported by `lint`, `build` and `ci` with its file and key: no JSON artefact can carry it (AGSC-04-05), and a build that meets one writes nothing. *(Amended 2026-10-06 for 1.0.0: until `1.0.0-rc.6` such a string passed `lint` and failed `build` with `AGSC-E601` naming no file.)* The other text files a Bundle carries as input — `.env` (AGSC-01-37), the authored `.well-known/security.txt` (AGSC-06-36), `LICENSE-CONTENT` (AGSC-06-18) and an SVG attachment (AGSC-02-98) — carry none of the four suffixes, so the line-ending, byte-order-mark, NFC and final-LF requirements above do not bind them at 1.0: each follows its own format, and RFC 9116 §2.2, for one, admits CRLF line endings in `security.txt`. `PRIVACY.md` and the pages under `site/` are `.md` files and are bound. From 1.1 `lint`, `build` and `ci` report, as the warning `AGSC-E108`, a byte-order mark at the start of any of the four files named above (`.env`, `security.txt`, `LICENSE-CONTENT` and an SVG attachment), and text in any of them that is not NFC-normalised; their line endings and final line feed follow their own format and are not checked, and no file is refused. *(Amended 2026-10-10 for 1.0.0: the text files outside the four suffixes were not named)* *(Amended 2026-10-29 for 1.1.0: the byte-order-mark and NFC requirements are extended to the four other text files as warnings (AGSC-00-14); the line-ending and final-LF requirements stay out, because RFC 9116 admits CRLF in security.txt and an SVG attachment keeps its authored bytes)* [design]
- **AGSC-01-15** File discovery order MUST be a code-point sort of the repository-relative path, with `/` as the path separator in the sort key on every platform (a native `\` separator MUST be converted before comparison). Locale collation MUST NOT be used. [design]
- **AGSC-01-16** An input file larger than its applicable cap MUST be refused with `AGSC-E904` — `attachments{max_bytes}` for a file under `content/attachments/` (AGSC-01-34; default 1 MiB, maximum 10 MiB), 1 MiB for every other input file. Archives MUST be refused entirely (`AGSC-E903`), and any path escaping the Bundle root MUST be refused with `AGSC-E902`. [design]

## 1.4 Configuration

- **AGSC-01-17** A Bundle MUST have exactly one configuration file, `agsc.config.json`, validated against `schema/config.schema.json`. A second configuration file MUST NOT be introduced. That sentence binds this specification and its implementations, not a Bundle: a conforming tool reads its configuration from `agsc.config.json` and the environment of AGSC-01-37 and reads no other file of the Bundle as configuration, so another file a Bundle holds is no configuration fault. AGSC-01-01 reports a missing `agsc.config.json` as `AGSC-E901`, AGSC-01-18 an unknown or invalid key as `AGSC-E004`, and a value the schema refuses takes the code of §9.4 that names its fault. *(Amended 2026-10-10 for 1.0.0: the codes that report a configuration fault were not named)* [PRD-006]
- **AGSC-01-18** Its keys are `spec_version`, `site{base,title,tagline,author,analytics_token,tdm_crawlers[]}`, `bundle{id,license_prose,license_schema,operator}`, `ns{base,version}`, `releases{}`, `tags{allowed[]}`, `build{out}` (`rdfxml` reserved; `feed` reserved — no 1.0 rule pins the bytes of `/feed.xml`, so the switch has nothing to switch on: both names are recognised and rejected with `AGSC-E004` per AGSC-00-20), `i18n{default}`, `lint{injection_patterns[]}`, `peers[]`, `run{enabled,allow[]}`, `channels[]{name,adapter,author,owner,publish,allow[],rate{per_hour}}`, `budget{usd_month}` (AGSC-01-38), and — under AGSC-11-01 and AGSC-01-34 — `federation{hop_limit,fan_out,max_requests,redirect_limit,timeout_ms,max_bytes}` *(Amended 2026-10-07 for 1.0.0: `max_bytes`, the per-response cap of the bound table of AGSC-11-01, was missing from this list)*, `chunks{max_bytes}`, `contribute[]{mode,target,channel}`, `visibility`, `access` (AGSC-11-20, the credential page of a `restricted` node), `attachments{max_bytes}`, `surfaces[]{surface,target,version,access}` (AGSC-11-16, declaration-only surfaces) and `related[]{rel,href,type,profile,title}` (AGSC-06-35, related-system links). `channels[].author` is a **forge login**: 1–64 characters from `[A-Za-z0-9._-]`, beginning with a letter or digit (stated here once, because AGSC-01-36 refers to "the same grammar as `channels[].author`"; a forge with a narrower grammar is free to reject a wider value, and this specification encodes no one forge's rule). `channels[].allow[]` is an OPTIONAL array of strings naming the sender identities an adapter accepts (an empty or absent array accepts every sender) and `channels[].rate{per_hour}` an OPTIONAL integer bounding the messages one channel may ingest per hour, both required by AGSC-01-30's ingest guard; `agents[]` (AGSC-01-36) is a key as well; the environment file of AGSC-01-37 adds no key, it overrides them. `site.tdm_crawlers[]` is an OPTIONAL array of RFC 9309 product tokens, each matching `^[A-Za-z_-]+$` and compared case-insensitively, naming the crawlers whose operators state that they collect content in order to train a machine-learning model; AGSC-06-18 says what a writer does with it and when leaving it empty is a fault. `site.analytics_token` is an edge-analytics token consumed only by the hosting platform; a build MUST NOT emit it into any artefact and MUST NOT load a third-party script for it (AGSC-06-05). `bundle.license_prose` and `bundle.license_schema` are SPDX or `LicenseRef-` identifiers, defaulting to `LicenseRef-AgenticSystemCore-Content-Use-1.0` and `CC0-1.0`; they supply the licence identifiers of AGSC-06-15, AGSC-01-26 and AGSC-07-16. `i18n.default` is OPTIONAL and defaults to `en` (AGSC-01-13/01-13a); `peers[]` is required by AGSC-10-12 (each entry a peer node's canonical well-known URL) and `run{enabled,allow[]}` is required by AGSC-09-94 (`enabled` default `false`). There is no `build.search` toggle: `search.json` is required unconditionally by AGSC-06-16, and a switch that could turn off a MUST would make the two rules unsatisfiable together. Configuration is closed: an unknown key is `AGSC-E004`. The single exception is the `x-<vendor>-<key>` namespace of `docs/SPEC.md` §8(2) — matching `^x-[a-z0-9]+(-[a-z0-9]+)+$`, admitted by `config.schema.json`'s `patternProperties` at the top level and on each `channels[]` entry while `additionalProperties` stays `false` — which every conforming tool preserves verbatim, never interprets and never reports as `AGSC-E004` (the frontmatter twin is AGSC-02-05a). `ns{base,version}` is present for forward compatibility only: AGSC-05-02 makes the vocabulary IRI a constant of this specification, so no conforming tool reads a value other than the default and a Bundle that omits the object is identical to one that spells it out. A Bundle that omits `bundle.license_prose` or `bundle.license_schema` takes `LicenseRef-AgenticSystemCore-Content-Use-1.0` and `CC0-1.0`; the values are echoed verbatim into `/legal/`, `content/index.md` `license` and every JSON-LD `schema:license`, and nothing else reads them. *(Amended 2026-10-10 for 1.0.0: `access`, the key that names a restricted node's credential page for AGSC-11-20, was missing from this list and from the configuration schema.)* *(Amended 2026-10-29 for 1.1.0: the keys 1.1 adds, each OPTIONAL: `compose{brief}` — boolean, default `false`, whether `compose` also writes the brief (AGSC-07-25); `lint{min_sources}` — integer of at least 0, default `0` (AGSC-08-31); `discovery{ai_catalog}` — boolean, default `false`, whether the two catalogue files of AGSC-06-42 are written; `site{query_page}` — boolean, default `true`, whether the `/query/` page of AGSC-06-39 is written, so that `false` keeps the route set of 1.0; `site{security_policy}` — an absolute `https:` URL of the vulnerability-disclosure page that the `Policy` field of `security.txt` names (AGSC-06-36); `chunks{content_digest}` — boolean, default `false`, whether a chunk line carries the `content_digest` member (AGSC-06-29); `surfaces[]{binding}` — a string, default `JSONRPC`, the A2A `protocolBinding` of a `responder` entry (AGSC-06-34); `site{author_orcid}` — an ORCID iD of the form `0000-0000-0000-000X` for the `creator` of the Dataset block (AGSC-06-41); `bundle{creator{name,orcid}}` and `bundle{license_url}` — the `creator` and the versioned `license` address of that block, `license_url` an absolute `https:` URL of a specific version of the licence text; `contribute[]{repository,branch}` — `repository` an absolute `https:` URL of the repository that holds the source files and `branch` a ref name, default `HEAD` (AGSC-11-14); `peers[]` — an entry MAY be an object `{url, relationship, crosswalk}` in place of a string (AGSC-11-24); `ledger{actors}` — a map from a commit author's e-mail address to a `human:<id>` actor (AGSC-08-20a); `domain{vocabulary,shapes,questions,contexts[]}` — the domain layer (AGSC-01-41). A Bundle that uses one of them SHOULD declare a `spec_version` of 1.1.0 or later, and a 1.0 tool reports it as `AGSC-E004` (AGSC-00-15). A 1.1 tool reads these keys under any `spec_version` of MAJOR 1; the declaration is advice to readers and not a condition (AGSC-00-15). `rdfxml`, `feed` and `routing` stay reserved and stay `AGSC-E004` at 1.1)* [PRD-006]
- **AGSC-01-19** `build.out` MUST default to `www`, MUST be a relative path under the grammar of AGSC-01-35 (never `.`, `..` or absolute), and MUST NOT name `content/`, which a build never writes (AGSC-08-02), or `dist/`, which is generated (AGSC-01-08), or a path under either — its first segment compared ASCII case-insensitively, because on a case-insensitive file system `Content` is `content/` — and a value that does is `AGSC-E204` *(Amended 2026-10-06 for 1.0.0: the grammar alone admitted `content` and `dist`, and a build with `"out": "content"` wrote the whole site into the source tree)*; a trailing `/` is accepted and stripped. `site.base` MUST be an absolute `https:` URL that is an origin — scheme, host and optional port, with no path — with or without a trailing slash (a trailing slash is stripped before IRIs are formed), and is the IRI base of every item (§05). *(Amended 2026-10-02 for 1.0.0: the rule admitted a path prefix "so that a node may be published under a sub-path"; but the well-known address, `robots.txt`, `security.txt` and `tdmrep.json` have their meaning only at the root of an origin (RFC 8615 §3, RFC 9309 §2.3, RFC 9116 §3), and no build with a path prefix could succeed. At 1.0 a node occupies a whole origin; a path prefix is reserved to a later version, and the schema refuses one.)* It MUST carry no query and no fragment, and no path segment may be `.` or `..` (each of those breaks AGSC-05-01's IRI construction, and the schema refuses them). The single exception is the development placeholder `http://localhost` or `http://localhost:<port>` (optionally with a trailing slash), which adoption writes (AGSC-02-94) and which lint MUST report as `AGSC-E506` — "set `site.base` before publishing" — until the owner replaces it. [design]
- **AGSC-01-20** `releases` is a boolean switchboard: an item carrying `release: <key>` is published only when `releases[<key>]` is `true`. An item with no `release` is always published. [PRD-021]
- **AGSC-01-21** `tags.allowed` is the closed tag vocabulary; a tag outside it MUST be reported (`AGSC-E203`). When `tags` is absent from `agsc.config.json` there is no closed vocabulary and `AGSC-E203` is not raised for a tag; the 2–5 count of the §2.2 table is the warning `AGSC-E213` — a `tags` array with fewer than 2 or more than 5 values (the schema carries no `minItems`/`maxItems` for it, because the bound is a warning and not an error). [design]
- **AGSC-01-25** `bundle.operator` is OPTIONAL and, when present, MUST be a `human:<id>` actor string (AGSC-02-07). It is the accountable operator of this Bundle and is the first source of `prov.operator` at adoption (AGSC-02-90). No other configuration key supplies an actor. [PRD-053]

## 1.5 Import tolerance

- **AGSC-01-22** Import of a foreign OKF v0.2 bundle MUST accept unknown `type` values (mapped to `concept` with a warning), unknown keys, missing optional fields, missing `index.md` and broken links. A broken internal link is a Gate failure for the Bundle's own build but MUST NOT reject an import. **Tolerance has one limit and one record**. The limit: a source whose declared `spec_version` has a MAJOR the tool does not implement MUST be refused with `AGSC-E004`, before any file is written, unless the adapter offers its own `--allow-newer` flag and the caller passes it (AGSC-01-26a, AGSC-09-09) — reading another MAJOR is a guess, so the choice is the operator's and never the tool's, and the default is to stop. A source of the tool's MAJOR and a newer MINOR MUST be imported, with the warning `AGSC-E506` naming the newer version, and every construct the tool does not know is handled as AGSC-00-21 lists. The record: every item an import writes MUST carry `prov.source_version` (the source's content version) and `prov.source_hash` (the source's bundle hash), each omitted when the source publishes neither, so that an imported item names the exact state it was taken from (AGSC-08-01, AGSC-04-25). An import MUST NOT write executable content (AGSC-07-15) into the Bundle: a foreign record's scripts, executables, symlinks and tool pre-approvals (`allowed-tools`) MUST be dropped, and each dropped file or key MUST be reported as the warning `AGSC-E407`. From 1.1 every item an import writes from a source this node does not own — a source whose root document does not carry this Bundle's `base` — MUST be written with `status: draft`, whatever its licence and whatever status the source gave it, so that it is never published (AGSC-06-30) until a person changes the status, and each such item MUST be reported once as the warning `AGSC-E506` naming the item and the draft status. That includes a record of an established licence and a skill that carries a licence; before 1.1 only a record whose licence the importer could not establish as permitting publication was written as a draft. A peer's record that a local item must link to — a task on another node's board that a local task is `blocked-by`, for example — is imported as a read-only draft copy that names the peer IRI in an `x-<vendor>-<key>` member (AGSC-02-05a), and the local Link names the copy: a Link target is a local slug at 1.x (AGSC-03-02), and an IRI Link target is an item of a later MINOR (AGSC-00-20). An item mapped to `concept` that declares no `kind` is written with `kind: explainer`, the adoption default of AGSC-02-90, and the mapping is part of the `AGSC-E506` warning *(Rationale: a `concept` must carry `kind`, AGSC-02-12)*. *(Amended 2026-10-29 for 1.1.0: every foreign import arrives as a draft, a more cautious outcome of an existing MUST that no valid Bundle can fail (AGSC-00-14); the case imp-0004 is withdrawn for imp-0010 and imp-0002 for imp-0009; an IRI Link target stays a later item (AGSC-00-20))* [design]
- **AGSC-01-23** Import MUST be deterministic and idempotent: re-running it over unchanged input MUST produce byte-identical output and MUST NOT create duplicate items. Colliding slugs MUST be suffixed `-2`, `-3`, … in discovery order. A collision with an item the target Bundle **already holds** is not a slug collision and MUST NOT be suffixed — suffixing it would break this rule's own idempotence, because the second run would see both `<slug>` and `<slug>-2` taken and write `<slug>-3`. An import MUST NOT replace an existing item unless the operator asked for it: where any planned path exists with different content, the import MUST write nothing at all, MUST report `AGSC-E206` for every such path, and MUST exit non-zero; `--dry-run` reports the same. An adapter MAY offer an explicit flag of its own (AGSC-01-26a) that permits replacement, in which case every replaced path MUST be reported; a write is never permitted outside the Bundle root or through a link (AGSC-01-16, AGSC-01-35). A planned path whose bytes are already exactly what the import would write is unchanged, and is not a collision. *(The suffix clause is about the incoming set — a foreign corpus with two files that slugify alike.)* [PRD-021]
- **AGSC-01-24** *(reserved: stated by the first conjunct of AGSC-08-17, with the same code; the id is never reused, AGSC-00-16.)*

## 1.6 Export

- **AGSC-01-26** `export --markdown` and `export --okf` MUST emit the lint-normalized Bundle itself — one `.md` file per **published** item (AGSC-06-30), so that a byte-preserving export carries exactly what the node publishes, frontmatter first, body bytes unchanged (every other **published** surface of this format applies AGSC-06-30's projection too, so no published surface lets a draft item leave a node; the local tool server of AGSC-09-13 is not a published surface: it is the author's own tool over the author's Bundle, and it reads drafts) — and MUST be **lossless**: every authored frontmatter key, including unknown keys preserved under AGSC-02-05, MUST appear in the output. The result MUST open as a plain folder of Markdown in any editor or vault tool without a plugin. ## 1.7 Channel ingest
- **AGSC-01-30** A **Channel adapter** (`channels/<name>/`) MUST expose `pull(since) → messages[]` and `render(message) → { path, frontmatter, body }` producing a conforming item (AGSC-02) under `content/<type-plural>/`; it MUST NOT write to the content branch directly — ingestion always yields a Proposal (AGSC-08-01..). The CI ingest job pushes the Proposal branch and opens the pull request with the ingest credential `CHANNEL_TOKEN_<name>`, a fine-grained token scoped to the **content repository** with `contents: write` and `pull-requests: write`, never `GITHUB_TOKEN` and never in a fork context. Forge fine-grained tokens are **not** ref-scoped — their permissions are repository-wide — so the branch **ruleset**, never the token, is what prevents a direct push to the content branch, and the ingest identity MUST NOT appear as a bypass actor on that ruleset (AGSC-08-26(f) gives the separate merge credential that MAY). `propose` itself still performs no network write (AGSC-08-04). The job MUST reject a message whose sender is absent from a non-empty `channels[].allow[]`, reporting `AGSC-E203` (a value outside a closed operator list), and MUST stop for the current hour once `channels[].rate{per_hour}` messages have been ingested (AGSC-01-18), recording the skipped messages by `sources[].id` for the next run. `render` MUST redact e-mail addresses and telephone numbers from the body (AGSC-08-16) and record the sender only in `sources[0]`. A channel MUST NOT have more than five open Proposals at once; the ingest job MUST stop opening pull requests at that bound and record the skipped messages by `sources[].id` for the next run (idempotence, AGSC-01-33). *(Amended 2026-10-10 for 1.0.0: the rejection named no code)* [PRD-043, PRD-056]
- **AGSC-01-31** Each channel declares `publish: auto | hitl` (default `hitl`) in `agsc.config.json` (`channels[]`). In `hitl` the Proposal waits for the author's `verified[]`; in `auto` it MAY be merged only under AGSC-08-26, whose guard is verified against configuration and forge identity, never against self-declared frontmatter: the pull-request author MUST equal `channels[].author`, `prov.operator` MUST equal `channels[].owner`, and every ingested item MUST carry `prov.agent` (the adapter id) with `prov.origin: imported` — so the agent-safety lints of AGSC-08-13 run at `error` severity (AGSC-08-13) instead of warning. [PRD-056, AGSC-08-05, AGSC-08-26]
- **AGSC-01-32** Optional AI correction in `auto` mode is limited to formatting/frontmatter/typo repair; it MUST NOT add claims, links or Sources, MUST run under the configured spend cap (NFR-11) and MUST record its spend by adding to the same Proposal one `episode` item carrying `usage{model, tokens_in, tokens_out, cost_usd, estimate}` (AGSC-02-14) and `prov.agent` = the adapter id — the same mechanism AGSC-09-14a requires of an LLM responder, and the only one AGSC-08-25's monthly rollup can see, since a Proposal has no file (AGSC-00-06) and the ledger has no `proposal` kind at 1.0 (AGSC-08-21). A correction whose spend cannot be recorded MUST NOT run. Without a key the adapter still works (lint-only). [PRD-056]
- **AGSC-01-33** Ingested messages MUST be de-duplicated by a stable `source_id` kept in `sources[].id` (a member of the `source` object, AGSC-02-10); re-ingesting is a no-op (idempotent), and the original channel/message reference is the item's first Source. A channel message that has no web URL uses the resource form `urn:agsc:channel:<name>:<source_id>`, which the schema admits alongside `https?://`. [PRD-056]

- **AGSC-01-34** Attachments live under `content/attachments/<slug>/` and nowhere else; a file there that no item's `attachments[]` names is an orphan warning (`AGSC-E414`); an `attachments[]` entry whose file is absent, **or whose bytes do not match the SHA-256 recorded for it**, is `AGSC-E413` at build; the byte comparison — the served file against the SHA-256 in the served `pages/<slug>.jsonld` (AGSC-05-29) — is a `verify` check over a published node and reports `AGSC-E413` there. `agsc.config.json` gains the OPTIONAL `attachments{max_bytes}` (default 1048576, maximum 10485760, `x-` admitted, AGSC-11-01); a larger file is `AGSC-E904`. [AGSC-01-16]
- **AGSC-01-35** Every relative path a Bundle carries **as the value of a key** — `attachments[].file`, `diagram.file`, `build.out` — MUST be a sequence of `/`-separated segments in which **no segment is `..` or `.`**, which does not begin with `/`, does not contain a `\` or a `U+0000`, and which resolves inside the Bundle root; a violation is `AGSC-E902`. An **inline Markdown link or image target in a body** is held to the same rule except that it MAY contain `..` segments, because an item under `content/<type-plural>/` cannot otherwise reach `content/assets/` at all (AGSC-02-95, AGSC-03-11): it MUST NOT begin with `/`, MUST NOT contain a `\` or a `U+0000`, and the path it resolves to — relative to the file that carries it — MUST lie inside the Bundle root. **For a body reference the escape test wins over the segment test.** A body target that escapes the Bundle root is `AGSC-E902`; a body target inside the Bundle root that resolves to no item, asset or anchor is `AGSC-E310` (AGSC-03-11), never `AGSC-E902`. The schemas check only the cheap syntactic part (no leading `/`, no `\`, no NUL anywhere), because the segment rule cannot be expressed as a portable regular expression: a lookahead is valid in ECMAScript but uncompilable in RE2, Go and Rust, and the vectors promise ports in any language. This rule is the normative form of that segment test. *(Amended 2026-10-10 for 1.0.0: the prohibition on a leading `/` is written with the key word in capitals)* [AGSC-01-16]

## 1.8 Agent lane configuration

- **AGSC-01-36** `agents[]` is an OPTIONAL array of agent-lane declarations, each `{name, kind, author, operator, model, tasks[], types[], channel, schedule, budget_usd_month, max_new_items, max_claims, enabled}`: `name` a slug unique within the array; `kind` ∈ `llm|process`; `author` the forge identity under which the lane's Proposals are opened (the same grammar as `channels[].author`); `operator` the accountable human, `human:<id>` (AGSC-02-07); `model` a non-empty string, REQUIRED when `kind` is `llm`, absent otherwise; `tasks[]` a non-empty subset of `create`, `edit`, `update`, `review`, `summarize`, `translate`, `refresh`, `plan`, `claim`, `work`; `types[]` a non-empty subset of `concept`, `episode`, `lesson` (default all three — a `procedure`, `gate`, `cluster`, configuration, workflow or schema is never in an agent lane, AGSC-08-26(b)); `channel` the `name` of a `channels[]` entry whose `author` equals the agent's `author` and whose `publish` choice and guards therefore govern the lane's Proposals (AGSC-01-31, AGSC-08-26); `schedule` an OPTIONAL string the host's scheduler interprets and this specification does not; `budget_usd_month` an integer ≥ 0, REQUIRED when `kind` is `llm`, and the sum of `budget_usd_month` over the entries with `enabled: true` MUST NOT exceed the node's `budget.usd_month` (AGSC-01-38) — a configuration that does is invalid with `AGSC-E212`; `max_new_items` an integer ≥ 1, default `20`, the greatest number of items one Proposal of the lane may create (the bound on a runaway planner, AGSC-08-28(c)); `max_claims` an integer ≥ 1, default `1`, the greatest number of tasks the lane may hold in `TASK_STATE_WORKING` at once (the work-in-progress limit of AGSC-10-17); `enabled` a boolean, default `false`. Each object admits `x-<vendor>-<key>` keys; any other unknown key is `AGSC-E004`; an enum violation is `AGSC-E203`. The object declares the lane; its behaviour is AGSC-08-28…30. [PRD-063]
- **AGSC-01-37** **The environment file.** Every value of `agsc.config.json` that is a secret or host-specific is configurable from the environment, and the environment is configurable from a file: a conforming tool MUST read, before anything else, an OPTIONAL `.env` file in the Bundle root — UTF-8, one `NAME=value` per line, `#` comments, no quoting or interpolation, a later line winning over an earlier one — and MUST take from it only names matching `^AGSC_[A-Z0-9_]+$`, ignoring every other line; `AGSC_FEATURE_LLM_REVIEW` is read from the process environment only and never from `.env`, because no Bundle file may enable the review lane (AGSC-08-27) *(Amended 2026-10-02 for 1.0.0: the exception was not stated)*; a name already present in the process environment keeps its process value (the precedence of AGSC-09-09 becomes flags > process environment > `.env` > project configuration > user configuration). Every scalar key of AGSC-01-18 is addressable as `AGSC_` followed by its path in upper case with `_` between segments (`AGSC_BUDGET_USD_MONTH`, `AGSC_BUILD_OUT`, `AGSC_SITE_BASE`), and the named entries of `agents[]` and `channels[]` as `AGSC_AGENT_<NAME>_<KEY>` and `AGSC_CHANNEL_<NAME>_<KEY>` with the slug in upper case and `-` as `_` (`AGSC_AGENT_EDITOR_ENABLED=true`, `AGSC_AGENT_EDITOR_BUDGET_USD_MONTH=3`); a value is parsed by the schema type of the key it overrides (`true`/`false`, an integer, else a string) and a value that fails the schema is `AGSC-E201`…`E204` as if written in the file. Model credentials are environment-only — `AGSC_MODEL_API_KEY` and, for an OpenAI-compatible endpoint, `AGSC_MODEL_BASE_URL` — and MUST NOT be configuration keys, so that no Bundle file ever holds a secret (AGSC-08-15). `init` MUST write `.env` into `.gitignore` and MUST write `.env.example` listing every recognised name with an empty value; a tracked `.env` — one present in the content branch — is `AGSC-E403` (the secrets lint of AGSC-08-15) whatever it holds. The configuration input of the build function (AGSC-04-01) is the configuration **as resolved** after these overrides, and `ci` MUST print the names — never the values — of the overrides in effect, so that a reproduction can be set up from the log. [PRD-065, AGSC-09-09, NFR-11]
- **AGSC-01-38** **The node-wide spend cap.** `budget{usd_month}` is an integer ≥ 0, default `10`, the most a node may spend on model calls of every kind in one calendar month — agent lanes (AGSC-08-28), the review lane (AGSC-08-27), automatic correction (AGSC-01-32), a narrating responder (AGSC-09-14a) and anything else that records `usage` — summed over every Episode of the month (AGSC-08-25); the sum of the enabled agents' `budget_usd_month` MUST NOT exceed it (AGSC-01-36, `AGSC-E212`); when it is reached every model-calling path MUST stop for the month with the warning `AGSC-E510`, and a tool that cannot compute the month's spend MUST NOT call a model (the rule of AGSC-01-32). The reference node keeps the default (NFR-11); `AGSC_BUDGET_USD_MONTH` overrides it per AGSC-01-37. [PRD-065, NFR-11]

## 1.9 Additions of 1.1

- **AGSC-01-39** **SKOS import (adapter `skos`).** `import <file.ttl> --from skos` reads one RDF 1.1 Turtle file that holds a SKOS thesaurus (SKOS Reference, W3C Recommendation of 18 August 2009, <https://www.w3.org/TR/skos-reference/>) and writes items under AGSC-01-22 and AGSC-01-23; it is an adapter in the sense of AGSC-01-26a. Subjects are taken in the code-point order of their IRIs, and the mapping is this. **(a)** Each `skos:Concept` becomes a `concept` item with `kind: term`; its slug is the slug of its `title` by the rule of AGSC-02-91, suffixed `-2`, `-3`, … on a collision (AGSC-01-23). **(b)** `title` is the `skos:prefLabel` whose language tag equals `i18n.default` (compared case-insensitively), else the untagged one, else the one whose tag is least in code-point order (tags compared case-insensitively; two labels with one tag, the lexically least), clipped or replaced as AGSC-02-90 does; a concept with no `prefLabel` takes the last segment of its IRI as its title; every other `prefLabel` is dropped. **(c)** Each `skos:altLabel` is a value of `aliases[]`, without duplicates and without the title, in code-point order; a SKOS-XL label (`skosxl:prefLabel`, `skosxl:altLabel`) is read as its `skosxl:literalForm` and flattened the same way, and the label resource is dropped. **(d)** The `skos:definition` that is least in code-point order of its lexical form (ties broken by language tag) is the `description` when it has 40 to 200 code points; one whose object is not a concept of the file is dropped. **(f)** Each `skos:ConceptScheme`, `skos:Collection` and `skos:OrderedCollection` becomes a `cluster` item; a concept that is `skos:inScheme`, `skos:topConceptOf` or a `skos:member` of one carries its slug in `clusters[]`, in code-point order; a collection that is a `skos:member` of another becomes a cluster whose `broader` is that collection, and where it is a member of several collections the first in code-point order of the IRI of the collection is its `broader` and every other membership is dropped (AGSC-02-17). **(g)** Each `dcterms:source` whose object is an `http` or `https` IRI becomes a `sources[]` entry with that `resource`; any other object is dropped. **(h)** The concept's own IRI is kept in the member `x-skos-iri`, and a `dcterms:license` of its scheme in `x-skos-license`; both are preserved under AGSC-02-05a. **(i)** `prov` is written as AGSC-01-22 writes it, and every item is a `draft` (AGSC-01-22). **Dropped:** notation, every note property (`skos:note`, `skos:scopeNote`, `skos:historyNote`, `skos:editorialNote`, `skos:changeNote`, `skos:example`), the order of an ordered collection, the mapping properties (`skos:exactMatch`, `skos:closeMatch`, `skos:broadMatch`, `skos:narrowMatch`, `skos:relatedMatch`), and every statement about a class, an individual or a shape; - **AGSC-01-40** **Names and paths that only some file systems refuse.** From 1.1 `lint`, `build` and `ci` MUST report each of the following as the warning `AGSC-E423`, naming the file, and MUST NOT refuse the Bundle for it (AGSC-00-14): **(a)** a path segment of a file of the Bundle whose part before the first `.` equals, after ASCII lower-casing, one of the Windows device names `con`, `prn`, `aux`, `nul`, `com1` to `com9` and `lpt1` to `lpt9`, and the superscript forms `com¹`, `com²`, `com³`, `lpt¹`, `lpt²` and `lpt³` (a slug such as `con` matches the grammar of AGSC-01-10, and Windows treats `con.md` as the device); **(b)** two paths under `content/attachments/` or `content/assets/` that are equal after NFC and Unicode simple case folding, reported on each path of the group except the first in code-point order; **(c)** a file path relative to the Bundle root longer than 200 code points, which leaves room for the folder a Windows checkout sits in under the legacy limit of 260 characters; **(d)** a path segment that ends in a space or a period, or that contains one of `<`, `>`, `:`, `"`, `|`, `?` and `*`; **(e)** in any string of the files that `lint` reads (front-matter values and member names, body text and configuration), a Unicode noncharacter, which AGSC-04-05 reports as `AGSC-E423`. - **AGSC-01-41** **The domain layer: configuration.** `domain` is an OPTIONAL object of `agsc.config.json` with four OPTIONAL members. `vocabulary` is a relative path (AGSC-01-35) to a Turtle file holding the node's own classes and relations (AGSC-05-38). `shapes` is a relative path to a Turtle file of SHACL shapes (AGSC-05-41). `questions` is a relative path to a JSON file of the node's competency questions (AGSC-05-41). `contexts[]` is an array of `{cluster, namespace}`: `cluster` the slug of a cluster item, `namespace` an absolute `https:` IRI that ends in `#` or `/`; a cluster and a namespace each occur at most once (AGSC-08-32). - **AGSC-01-42** **The diagram source grammar and its compiled bytes.** A writer that compiles `content/diagrams/<slug>.diagram` (AGSC-01-07) MUST accept exactly the language below and, for a source it accepts, MUST produce exactly the bytes below, `<slug>` being the slug of the item that carries the diagram (AGSC-02-13). A source it does not accept yields no SVG and the finding `AGSC-E412`, the registered code of a diagram that cannot be compiled (AGSC-02-13, AGSC-02-98); a source longer than 1,048,576 code points is `AGSC-E904`.

  **Lines and tokens.** On each line everything from the first `#` to the end of the line is a comment — a `#` inside a quoted string starts one too — and the rest is trimmed of spaces; an empty result is skipped. A line is split into tokens at each U+0020 outside double quotes; a double quote toggles quoting and is dropped; an empty quoted string yields no token; there is no escape. The first token is the statement name, and every argument is one token, so that a text with a space in it is quoted. A *number* is a token that ECMAScript `Number()` converts to a finite value. A *flag* is a token equal to its name, looked for among all the tokens of the statement, so that a text argument equal to a flag name sets the flag too, which an author SHOULD avoid. In a `box` or `circle` label a `|` starts a new line of text.

  **Statements** — these twelve and no other; any other first token is `AGSC-E412`:

  | statement | arguments | flags |
  |---|---|---|
  | `canvas` | `W H`, both greater than 0; the default is 460 260 | — |
  | `label` | `TEXT`, not empty: the accessible name when the item gives none; the last one wins | — |
  | `box` | `ID X Y W H [TEXT]` | `acc` `dashed` |
  | `circle` | `ID CX CY R [TEXT]` | `acc` `dashed` |
  | `region` | `ID X Y W H [CAPTION]` | — |
  | `arrow` | `FROM TO` | `via=X,Y;X,Y…` `both` `dashed` `acc` `rel=KEY` |
  | `line` | `X1 Y1 X2 Y2` | `acc` `dashed` `thick` `rel=KEY` |
  | `path` | `D` | `arrow` `acc` `dashed` |
  | `text` | `X Y STRING` | `size=N` (default 11) `left` `right` `rel=KEY` |
  | `cross` | `X Y` | — |
  | `note` | `TEXT`, not empty; the last one wins | — |
  | `bar` | `X Y W` | `thick` |

  **Refusals**, each `AGSC-E412` naming the line: a duplicate `ID` among boxes, circles and regions; a box whose corners lie outside the canvas; an `arrow` naming an `ID` that no earlier statement defined; a `via` that is not a list of number pairs; two arrows whose resolved paths are equal, once a waypoint on the straight line is dropped and direction is ignored; `acc` on any number of statements other than one; `acc` together with `thick` on one statement, which would write `stroke-width` twice; two shapes other than regions whose rectangles overlap, an `ID` that begins with `_` being left out of the comparison; with a `note`, a shape other than a region whose lower edge lies below `height − 26`; a `rel=` value that is none of the fourteen Link keys of AGSC-03-01. A writer MAY also refuse a `text` or `note` that its own measure of text width finds too wide for the canvas, leaving 4 px for a `text` and 16 px either side for a `note`; that measure is not pinned, and the bytes of an accepted source are.

  **Numbers and escaping.** A number is written rounded to the nearest tenth as ECMAScript `Math.round(n * 10) / 10` computes it, `-0` as `0`, with one decimal place and a trailing `.0` dropped. Text is escaped by replacing `&`, `<`, `>` and `"` with `&amp;`, `&lt;`, `&gt;` and `&quot;`, and nothing else.

  **Elements.** Each statement adds to a *draw* list and a *text* list, both kept in source order. ACC is ` class="agsc-accent" stroke-width="2.2"` when `acc` is set; when `rel=KEY` is set as well the class value is `agsc-accent agsc-rel-KEY`, and when `rel` is set without `acc` the whole of ACC is ` class="agsc-rel-KEY"`. DASH(n m) is ` stroke-dasharray="n m"` when `dashed` is set. MARK is `url(#<slug>-arrow)`.

  | statement | draw element | text element |
  |---|---|---|
  | `box` | `<rect x y width height rx="6"` ACC, then `stroke-dasharray="5 3"` if dashed without `acc` and `"4 3"` if dashed with `acc`, then `/>` | each line of `TEXT`, centred at `x + w/2`, the block centred on `y + h/2 + 4`, font size 11 when the label has more than 22 UTF-16 code units and no `|`, else 12 |
  | `circle` | `<circle cx cy r` ACC DASH(4 3) `/>` | `TEXT`, size 11, at `cx`, `cy + 4`, lines as for a box |
  | `region` | `<rect x y width height rx="8" stroke-dasharray="6 4"/>` | `CAPTION` at `x + w/2`, `y − 8`, size 11 |
  | `arrow` | `<path d` as below, ` marker-end="MARK"`, ` marker-start="MARK"` if `both`, DASH(4 3), ACC, `/>` | — |
  | `line` | `<path d="Mx1 y1 Lx2 y2"` ACC DASH(6 5), ` stroke-width="5"` if `thick`, `/>` | — |
  | `path` | `<path d="D"` (escaped), ` marker-end="MARK"` if `arrow`, ACC DASH(4 3) `/>` | — |
  | `text` | — | `<text x y font-size="N"` then ` text-anchor="start"` for `left`, else ` text-anchor="end"` for `right`, then ` class="agsc-rel-KEY"` if `rel` is set, `>STRING</text>` |
  | `cross` | `<path d="M(x−8) (y−8) L(x+8) (y+8) M(x+8) (y−8) L(x−8) (y+8)" stroke-width="2"/>` | — |
  | `note` | — | `TEXT` at `width/2`, `height − 12`, size 11 |
  | `bar` | `<path d="Mx y L(x+w) y"` ` stroke-width="5"` if `thick`, `/>` | — |

  In text elements the line `i` of `n` lines at font size `s` stands at `y₀ − (n − 1)(s + 4)/2 + i(s + 4)`. A text element is written `<text x="…" y="…" font-size="s">…</text>`; for `box`, `circle`, `region` and `note` the attributes are exactly those three. An `arrow` runs between the rectangles of its two shapes (a circle's is its bounding square): without `via` the path is `M p1 L p2`, where `b1` and `b2` are the points at which the segment between the two centres leaves the first and enters the second rectangle (the segment is scaled by the smaller of half-width over |dx| and half-height over |dy|, a zero difference counting as unbounded), and `p1`, `p2` are `b1`, `b2` moved 4 px towards each other along the segment; with `via` the path is `M p1 L v1 L v2 … L p2`, `p1` being the point where the segment from the first centre to `v1` leaves the first rectangle and `p2` the point where the segment from the last waypoint to the second centre enters the second.

  **The document** is, with LF line ends and one LF at the end, `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H" role="img" aria-labelledby="<slug>-title <slug>-desc" font-family="system-ui, sans-serif" font-size="14">`, then the lines `  <title id="<slug>-title">LABEL</title>`, `  <desc id="<slug>-desc">DESC</desc>`, `  <defs><marker id="<slug>-arrow" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse"><path d="M0 0 L10 5 L0 10 z" fill="currentColor"/></marker></defs>`, `  <g fill="none" stroke="currentColor" stroke-width="1.5">`, the draw elements each on a line indented four spaces (one line of four spaces when there are none), `  </g>`, `  <g fill="currentColor" text-anchor="middle">`, the text elements likewise, `  </g>` and `</svg>`. LABEL is `diagram.alt` when the item gives one (AGSC-02-13), else the last `label` statement, else `<slug> diagram`; DESC is the `note` when there is one, else `LABEL. A line drawing; the highlighted element carries the accent.` Nothing in the output carries a colour, a `style`, a script or a `data:` address, so the SVG satisfies AGSC-02-98 by construction. The token `rel=KEY` is the hook for the graph view of AGSC-06-38: a class per relation, no colour. The cases `bundle-0018` (twelve statements, byte for byte) and `bundle-0019` (the `rel` token) pin the grammar and the bytes. *(Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: the diagram source grammar and its compiled bytes, which 1.0 left implementation-defined)* [PRD-013, AGSC-01-07, AGSC-02-13, AGSC-02-98]
