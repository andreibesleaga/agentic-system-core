# AGSC-01 — Bundle: files, folders, encoding, configuration

## 1.1 Layout

- **AGSC-01-01** A Bundle MUST be a directory tree containing `content/` and exactly one `agsc.config.json` at its root. One repository is one Bundle. [audit/D §1.1, D32(4)]
- **AGSC-01-02** Items MUST live at `content/<type-plural>/<slug>.md` where `<type-plural>` ∈ `concepts`, `episodes`, `procedures`, `lessons`, `clusters`, `gates`. [audit/D §1.1, G02]
- **AGSC-01-03** The `type` key in frontmatter is authoritative and MUST match the containing folder; a mismatch is an error (`AGSC-E205`). [audit/D §1.1]
- **AGSC-01-04** `content/index.md` is the Bundle root document. It MUST carry `spec_version`, `okf_version`, `title`, `description` and `base` (the IRI base of every item, AGSC-05-01; it MUST equal `site.base`; a mismatch is `AGSC-E204`), and it MUST NOT carry `type`; it is not an item and does not enter the graph as an item. [audit/D §1.1, OKF v0.2]
- **AGSC-01-05** `index.md` MAY exist in any folder (OKF reserved). `_index.md` and `README.md` MUST NOT be used as items. [research/12 §P rule 3]
- **AGSC-01-06** Non-knowledge site pages live in `site/*.md`, outside `content/`. They are rendered but MUST NOT appear in the graph, in `search.json` or in `llms.txt` item lists. [audit/D §1.1, G40]
- **AGSC-01-07** Diagram sources live at `content/diagrams/<slug>.diagram`. A compiled `.svg` MUST NOT be committed; it is produced into the build output. [audit/D §2.2, D20]
- **AGSC-01-08** `www/` (build output) and `dist/` (proposals, harnesses, gate verdicts) are generated. An implementation MUST NOT read them as input to a build. [audit/D §2.2, D47]
- **AGSC-01-09** *(retired at rc.3, 2026-09-17, V6-B minimality pass confirmed by D81: entailed by AGSC-07-12 (the only legal location is dist/harness/) with AGSC-01-08 (R19) — merged into AGSC-07-12; the id is reserved under AGSC-00-16 and never reused.)*

## 1.2 Slugs and identity

- **AGSC-01-10** A slug MUST match `^[a-z0-9]+(?:-[a-z0-9]+)*$` and be 1–64 Unicode code points long (`minLength`/`maxLength` in the schemas, AGSC-02-24) — a grammar that forbids a leading, trailing or doubled `-` by construction and compiles in RE2, Go and Rust (rc.3, DS-3, blocker B4). It is equivalent to the rc.2 wording `^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$` plus "MUST NOT contain `--`", which remains true. [research/12 §P rule 2 as corrected; Agent Skills name rule]
- **AGSC-01-11** The slug is the file stem, the value of `id` when present, and the last path segment of the item IRI. Slugs MUST be unique across the whole Bundle regardless of folder (`AGSC-E206`). [research/12 §P rule 2, audit/D §1.1]
- **AGSC-01-12** A slug is permanent. A renamed or superseded item keeps its slug; the new item gets a new slug and the relationship is expressed with `supersedes` (§03). Reuse of a retired slug is an error. [PRD-018 ← R40]
- **AGSC-01-13** Language variants are `<slug>.<lang>.md` with `lang` a BCP 47 tag — compared case-insensitively, the file suffix and every emitted tag being the lower-cased form (AGSC-05-31; AR2-33) — equal to the file's `lang` key, and they are **accepted at 1.0** (D53; the deferral of G27 is lifted). The unsuffixed file is the **primary** and owns the slug, the item IRI (AGSC-05-01) and the graph node; a variant shares that slug, is published at the route `/<type-plural>/<slug>/<lang>/` (AGSC-06-01) and is emitted in RDF as the language-tagged literals of AGSC-05-17, never as a second item. A variant whose primary is missing is `AGSC-E208`; a variant whose suffix and `lang` key disagree, is `AGSC-E205`, while a `lang` that is not lowercase BCP 47 is a schema pattern violation and takes `AGSC-E204` (precedence, §9.4 — V6-B U2). `i18n.default` in `agsc.config.json` names the primary's language (default `en`). [research/12 §P rule 4, G27 ← D53]
- **AGSC-01-13a** (amends AGSC-01-13) A variant MUST share its primary's Link keys and `clusters[]`; divergence is warning `AGSC-E410`. The primary's page MUST carry `hreflang` alternates for every variant. Everything else about variants is AGSC-01-13. [PRD-055, D53, research/12 §7, V4-A A-36]

## 1.3 Encoding

- **AGSC-01-14** Every `.md`, `.json`, `.ttl` and `.diagram` file MUST be UTF-8 without BOM, MUST use LF line endings, MUST be NFC-normalized, and MUST end with exactly one LF (`AGSC-E108`). [research/12 §P rule 1, Art. XII]
- **AGSC-01-15** File discovery order MUST be a code-point sort of the repository-relative path, with `/` as the path separator in the sort key on every platform (a native `\` separator MUST be converted before comparison). Locale collation MUST NOT be used. [research/12 §P rule 24, D48(3)]
- **AGSC-01-16** (amended at rc.3) An input file larger than its applicable cap MUST be refused with `AGSC-E904` — `attachments{max_bytes}` for a file under `content/attachments/` (AGSC-01-34; default 1 MiB, maximum 10 MiB), 1 MiB for every other input file. Archives MUST be refused entirely (`AGSC-E903`), and any path escaping the Bundle root MUST be refused with `AGSC-E902`. [PLAN §11 R7, research/17 §1.9]

## 1.4 Configuration

- **AGSC-01-17** A Bundle MUST have exactly one configuration file, `agsc.config.json`, validated against `schema/config.schema.json`. A second configuration file MUST NOT be introduced. [PRD-006 ← R44, D32(4)]
- **AGSC-01-18** Its keys are `spec_version`, `site{base,title,tagline,author,analytics_token}`, `bundle{id,license_prose,license_schema,operator}`, `ns{base,version}`, `releases{}`, `tags{allowed[]}`, `build{out,feed}` (`rdfxml` reserved, D82 Q21), `i18n{default}`, `lint{injection_patterns[]}`, `peers[]`, `run{enabled,allow[]}`, `channels[]{name,adapter,author,owner,publish,allow[],rate{per_hour}}`, `budget{usd_month}` (AGSC-01-38, rc.4), and — added at rc.3 under AGSC-11-01 and AGSC-01-34 — `federation{hop_limit,fan_out,max_requests,redirect_limit,timeout_ms}`, `chunks{max_bytes}`, `contribute[]{mode,target,channel}`, `visibility`, `attachments{max_bytes}`, `surfaces[]{surface,target,version,access}` (AGSC-11-16, declaration-only surfaces) and `related[]{rel,href,type,profile,title}` (AGSC-06-35, related-system links). `channels[].allow[]` is an OPTIONAL array of strings naming the sender identities an adapter accepts (an empty or absent array accepts every sender) and `channels[].rate{per_hour}` an OPTIONAL integer bounding the messages one channel may ingest per hour, both required by AGSC-01-30's ingest guard; they were the only keys added between the `1.0.0-rc.1` and `1.0.0-rc.2` freezes (D61(3)); the five rc.3 objects above are the only keys added since rc.2; `agents[]` (AGSC-01-36) and `budget{usd_month}` (AGSC-01-38) are the two keys added at rc.4; the environment file of AGSC-01-37 adds no key, it overrides them. `site.analytics_token` is an edge-analytics token consumed only by the hosting platform; a build MUST NOT emit it into any artefact and MUST NOT load a third-party script for it (AGSC-06-05). `bundle.license_prose` and `bundle.license_schema` are SPDX or `LicenseRef-` identifiers, defaulting to `LicenseRef-AgenticSystemCore-Content-Use-1.0` and `CC0-1.0`; they supply the licence identifiers of AGSC-06-15, AGSC-01-26 and AGSC-07-16. `i18n.default` is OPTIONAL and defaults to `en` (AGSC-01-13/01-13a); `peers[]` is required by AGSC-10-12 (each entry a peer node's canonical well-known URL) and `run{enabled,allow[]}` is required by AGSC-09-94 (`enabled` default `false`). There is no `build.search` toggle: `search.json` is required unconditionally by AGSC-06-16, and a switch that could turn off a MUST would make the two rules unsatisfiable together (V2-06). Configuration is closed: an unknown key is `AGSC-E004`. The single exception is the `x-<vendor>-<key>` namespace of `docs/SPEC.md` §8(2) — matching `^x-[a-z0-9]+(-[a-z0-9]+)+$`, admitted by `config.schema.json`'s `patternProperties` at the top level and on each `channels[]` entry while `additionalProperties` stays `false` — which every conforming tool preserves verbatim, never interprets and never reports as `AGSC-E004` (D61(3); the frontmatter twin is AGSC-02-05a). `ns{base,version}` is present for forward compatibility only: AGSC-05-02 makes the vocabulary IRI a constant of this specification, so no conforming tool reads a value other than the default and a Bundle that omits the object is identical to one that spells it out (V5-3 S3-34). A Bundle that omits `bundle.license_prose` or `bundle.license_schema` takes `LicenseRef-AgenticSystemCore-Content-Use-1.0` and `CC0-1.0`; the values are echoed verbatim into `/legal/`, `content/index.md` `license` and every JSON-LD `schema:license`, and nothing else reads them (V5-3 S3-38). [audit/D §2.3, PRD-006]
- **AGSC-01-19** `build.out` MUST default to `www`, MUST be a relative path under the grammar of AGSC-01-35 (never `.`, `..` or absolute — AR2-30); a trailing `/` is accepted and stripped. `site.base` MUST be an absolute `https:` URL — an origin, optionally with a path prefix, so that a node may be published under a sub-path — with or without a trailing slash (a trailing slash is stripped before IRIs are formed), and is the IRI base of every item (§05). The single exception is the development placeholder `http://localhost` or `http://localhost:<port>` (optionally with a trailing slash), which adoption writes (AGSC-02-94) and which lint MUST report as `AGSC-E506` — "set `site.base` before publishing" — until the owner replaces it. [D47, D41, D52(1)]
- **AGSC-01-20** `releases` is a boolean switchboard: an item carrying `release: <key>` is published only when `releases[<key>]` is `true`. An item with no `release` is always published. [PRD-021 ← R8]
- **AGSC-01-21** `tags.allowed` is the closed tag vocabulary; a tag outside it MUST be reported (`AGSC-E203`). When `tags` is absent from `agsc.config.json` there is no closed vocabulary and `AGSC-E203` is not raised for a tag; the 2–5 count warning of the §2.2 table still applies. [audit/D §1.2]
- **AGSC-01-25** `bundle.operator` is OPTIONAL and, when present, MUST be a `human:<id>` actor string (AGSC-02-07). It is the accountable operator of this Bundle and is the first source of `prov.operator` at adoption (AGSC-02-90). No other configuration key supplies an actor. [PRD-053 ← D48(5), D07]

## 1.5 Import tolerance

- **AGSC-01-22** Import of a foreign OKF v0.2 bundle MUST accept unknown `type` values (mapped to `concept` with a warning), unknown keys, missing optional fields, missing `index.md` and broken links. A broken internal link is a Gate failure for the Bundle's own build but MUST NOT reject an import. [research/12 §P rules 30, 31]
- **AGSC-01-23** Import MUST be deterministic and idempotent: re-running it over unchanged input MUST produce byte-identical output and MUST NOT create duplicate items. Colliding slugs MUST be suffixed `-2`, `-3`, … in discovery order. [PRD-021]
- **AGSC-01-24** *(retired at rc.3, 2026-09-17, V6-B minimality pass confirmed by D81: the first conjunct of AGSC-08-17 verbatim, same code (R7) — merged into AGSC-08-17; the id is reserved under AGSC-00-16 and never reused.)*

## 1.6 Export

- **AGSC-01-26** `export --markdown` and `export --okf` MUST emit the lint-normalized Bundle itself — one `.md` file per item, frontmatter first, body bytes unchanged — and MUST be **lossless**: every authored frontmatter key, including unknown keys preserved under AGSC-02-05, MUST appear in the output. The result MUST open as a plain folder of Markdown in any editor or vault tool without a plugin. `--okf` additionally writes `content/index.md` with `okf_version` and the OKF-reserved `log.md`, whose content is one line `- <slug>: <modified, else date, else the empty string>` per item in slug order (an empty file when the Bundle has no item). Because these outputs are byte-preserving, the Content Use Terms travel **beside** them, not inside them: `index.md` carries `license` and the export root carries a `LICENSE-CONTENT` file (AGSC-01-29). [PRD-026 ← V2-26, V3-04, V3-26]
- **AGSC-01-26a** Beyond the five flags of AGSC-01-26/01-27 an implementation MAY ship **memory adapters** selected by `export --to <adapter>` / `import --from <adapter>` (the Basic Memory and GABBE-memory both-ways adapters of D39/D53 among them; Obsidian needs none, since AGSC-01-26's vault-openability clause already covers it). An adapter MUST be a single module discovered by directory convention (in the reference implementation, `src/interchange/adapters/`; informative, VB-30) and never by a configuration key (D61(3)); MUST be lossless in both directions for every key it claims, with AGSC-01-23's idempotence applying to a round trip; MUST carry AGSC-01-29's header and terms on every prose-carrying output; MUST NOT emit an executable, a symlink or an `allowed-tools` declaration (AGSC-07-15); and MUST be listed with its claimed key set in `docs/IMPLEMENTERS-GUIDE.md`. Adapters are never required for conformance at any Level (AGSC-10-04). [PRD-026, D39, D53 ← V5-3 S3-18]
- **AGSC-01-27** `export --jsonld` output MUST be byte-identical to the `graph.jsonld` of the same build (AGSC-05-06, AGSC-04-04); `export --jsonl` MUST emit one JCS-canonical JSON object per LF-terminated line, one line per item, items in slug order, each line being exactly the per-item JSON-LD node of `pages/<slug>.jsonld`. Neither MAY invent a member that the graph does not carry; the licence travels as the JSON-LD `schema:license`/`schema:usageInfo` members the graph already carries (D39), never as a text header. [PRD-026, PRD-022 ← V2-26, V3-04, V3-26]
- **AGSC-01-28** `export --steer [--target <name>…]` MUST emit steer bundles derived **only** from NOW state and from `concept`, `procedure`, `gate` and `lesson` items — never from an Episode, a Proposal or the git log — so that the same Bundle always yields the same bytes (AGSC-04-01). `<name>` is drawn from this **closed** registry, and each target writes exactly the one path named here and nothing outside it:

  | target | path |
  |---|---|
  | `agents` | `AGENTS.md` |
  | `claude` | `CLAUDE.md` |
  | `cursor` | `.cursor/rules/agsc.mdc` |
  | `copilot` | `.github/copilot-instructions.md` |
  | `gemini` | `GEMINI.md` |
  | `codex` | `.codex/instructions.md` |
  | `gabbe` | `GABBE/agents/AGENTS.md` |
  | `kiro` | `.kiro/steering/agsc.md` |
  | `windsurf` | `.windsurf/rules/agsc.md` |
  | `cline` | `.clinerules/agsc.md` |
  | `aider` | `CONVENTIONS.md` |

  The default is `agents,claude`. Every target derives from the same source set, is byte-stable (AGSC-04-01) and carries AGSC-01-29's header and terms; no target writes outside its named path and no twelfth target exists at 1.x — a new one is a MINOR bump with a registry row and a vector, exactly as a new Link key is (SPEC §8). An item whose most recent content-branch commit carries a `Channel-Auto:` trailer MUST be **excluded** from every target's output until a human `verified[]` entry is added to it; that exclusion is what lets AGSC-08-26(b) admit `concept`, `episode` and `lesson` into the auto lane at all. [PRD-029, D35, D53 ← V2-26, V5-3 S3-17, S3-12]
- **AGSC-01-29** Every **agent-facing digest** — `export --steer` (AGSC-01-28), `AGENTS.md` and every `SKILL.md` of a Harness (AGSC-07-12; formerly AGSC-07-14), and any other export that re-narrates item prose rather than copying it — MUST carry the fixed provenance header of AGSC-06-15, MUST fence quoted item prose as ```` ```text agsc-content ````, and MUST embed the Content Use Terms identifier; a build that omits them MUST fail. The byte-preserving exports of AGSC-01-26/27 MUST NOT be fenced or prefixed — that would break their losslessness and their byte-identity with `graph.jsonld` — and carry the terms as AGSC-01-26/27 state (a `LICENSE-CONTENT` file plus `index.md` `license`; the JSON-LD licence members). Steer bundles are governed exactly like `llms.txt` (AGSC-06-15) and the Harness files (formerly AGSC-07-14). [NFR-07, PRD-019 ← R39, ADR-001, V2-26, V3-04]

## 1.7 Channel ingest (added 2026-09-03, S01 Amendment 5)
- **AGSC-01-30** A **Channel adapter** (`channels/<name>/`) MUST expose `pull(since) → messages[]` and `render(message) → { path, frontmatter, body }` producing a conforming item (AGSC-02) under `content/<type-plural>/`; it MUST NOT write to the content branch directly — ingestion always yields a Proposal (AGSC-08-01..). The CI ingest job pushes the Proposal branch and opens the pull request with the ingest credential `CHANNEL_TOKEN_<name>`, a fine-grained token scoped to the **content repository** with `contents: write` and `pull-requests: write`, never `GITHUB_TOKEN` and never in a fork context. Forge fine-grained tokens are **not** ref-scoped — their permissions are repository-wide — so the branch **ruleset**, never the token, is what prevents a direct push to the content branch, and the ingest identity MUST NOT appear as a bypass actor on that ruleset (AGSC-08-26(f) gives the separate merge credential that MAY). `propose` itself still performs no network write (AGSC-08-04). The job MUST reject a message whose sender is absent from a non-empty `channels[].allow[]`, and MUST stop for the current hour once `channels[].rate{per_hour}` messages have been ingested (AGSC-01-18), recording the skipped messages by `sources[].id` for the next run. `render` MUST redact e-mail addresses and telephone numbers from the body (AGSC-08-16) and record the sender only in `sources[0]`. A channel MUST NOT have more than five open Proposals at once; the ingest job MUST stop opening pull requests at that bound and record the skipped messages by `sources[].id` for the next run (idempotence, AGSC-01-33). [PRD-043, PRD-056, D52(4), D61(2)/(3), V3-29, V3-32, V5-3 S3-11, S3-20]
- **AGSC-01-31** Each channel declares `publish: auto | hitl` (default `hitl`) in `agsc.config.json` (`channels[]`). In `hitl` the Proposal waits for the author's `verified[]`; in `auto` it MAY be merged only under AGSC-08-26, whose guard is verified against configuration and forge identity, never against self-declared frontmatter: the pull-request author MUST equal `channels[].author`, `prov.operator` MUST equal `channels[].owner`, and every ingested item MUST carry `prov.agent` (the adapter id) with `prov.origin: imported` — so the N9 lints run at `error` severity (AGSC-08-13) instead of warning. [PRD-056, AGSC-08-05, AGSC-08-26, N9, D52(4)]
- **AGSC-01-32** Optional AI correction in `auto` mode is limited to formatting/frontmatter/typo repair; it MUST NOT add claims, links or Sources, MUST run under the configured spend cap (NFR-11) and MUST record its spend by adding to the same Proposal one `episode` item carrying `usage{model, tokens_in, tokens_out, cost_usd, estimate}` (AGSC-02-14) and `prov.agent` = the adapter id — the same mechanism AGSC-09-14a requires of an LLM responder, and the only one AGSC-08-25's monthly rollup can see, since a Proposal has no file (AGSC-00-06) and the ledger has no `proposal` kind at 1.0 (AGSC-08-21). A correction whose spend cannot be recorded MUST NOT run. Without a key the adapter still works (lint-only). [PRD-056, D14 ← V5-3 S3-13]
- **AGSC-01-33** Ingested messages MUST be de-duplicated by a stable `source_id` kept in `sources[].id` (a member of the `source` object, AGSC-02-10); re-ingesting is a no-op (idempotent), and the original channel/message reference is the item's first Source. A channel message that has no web URL uses the resource form `urn:agsc:channel:<name>:<source_id>`, which the schema admits alongside `https?://`. [PRD-056, AGSC-02, V3-32]


> **rc.3 amendment (2026-09-16, folded into AGSC-01-18 on 2026-09-16):** `agsc.config.json` gains the OPTIONAL objects `federation{}`, `chunks{}`, `contribute[]`, `attachments{}` and the key `visibility` (AGSC-11-01, AGSC-01-34), each object admitting `x-<vendor>-<key>`; these five are the keys added at rc.3.


- **AGSC-01-34** (added at rc.3) Attachments live under `content/attachments/<slug>/` and nowhere else; a file there that no item's `attachments[]` names is an orphan warning (`AGSC-E414`); an `attachments[]` entry whose file is absent, or is `AGSC-E413` at build; the byte comparison — the served file against the SHA-256 in the served `pages/<slug>.jsonld` (AGSC-05-29) — is a `verify` check over a published node and reports `AGSC-E413` there (V7-14). `agsc.config.json` gains the OPTIONAL `attachments{max_bytes}` (default 1048576, maximum 10485760, `x-` admitted, AGSC-11-01); a larger file is `AGSC-E904`. [D67 Q64, AGSC-01-16]
- **AGSC-01-35** (added at rc.3) Every relative path a Bundle carries — `attachments[].file`, `diagram.file`, `build.out`, an inline Markdown link or image target — MUST be a sequence of `/`-separated segments in which **no segment is `..` or `.`**, which does not begin with `/`, does not contain a `\` or a `U+0000`, and which resolves inside the Bundle root; a violation is `AGSC-E902`. The schemas check only the cheap syntactic part (no leading `/`, no `\`, no NUL anywhere), because the segment rule cannot be expressed as a portable regular expression: a lookahead is valid in ECMAScript but uncompilable in RE2, Go and Rust, and the vectors promise ports in any language (V6-B portability). This rule is the normative form of what the lookahead used to encode. [D72 portability, AGSC-01-16]

## 1.8 Agent lane configuration (added at rc.4, 2026-09-17 — D87, R66)

- **AGSC-01-36** `agents[]` is an OPTIONAL array of agent-lane declarations, each `{name, kind, author, operator, model, tasks[], types[], channel, schedule, budget_usd_month, enabled}`: `name` a slug unique within the array; `kind` ∈ `llm|process`; `author` the forge identity under which the lane's Proposals are opened (the same grammar as `channels[].author`); `operator` the accountable human, `human:<id>` (AGSC-02-07); `model` a non-empty string, REQUIRED when `kind` is `llm`, absent otherwise; `tasks[]` a non-empty subset of `create`, `edit`, `update`, `review`, `summarize`, `translate`, `refresh`, `plan`, `claim`, `work`; `types[]` a non-empty subset of `concept`, `episode`, `lesson` (default all three — a `procedure`, `gate`, `cluster`, configuration, workflow or schema is never in an agent lane, AGSC-08-26(b)); `channel` the `name` of a `channels[]` entry whose `author` equals the agent's `author` and whose `publish` choice and guards therefore govern the lane's Proposals (AGSC-01-31, AGSC-08-26); `schedule` an OPTIONAL string the host's scheduler interprets and this specification does not; `budget_usd_month` an integer ≥ 0, REQUIRED when `kind` is `llm`, and the sum of `budget_usd_month` over the entries with `enabled: true` MUST NOT exceed the node's `budget.usd_month` (AGSC-01-38) — a configuration that does is invalid with `AGSC-E212`; `max_new_items` an integer ≥ 1, default `20`, the greatest number of items one Proposal of the lane may create (the bound on a runaway planner, AGSC-08-28(c)); `max_claims` an integer ≥ 1, default `1`, the greatest number of tasks the lane may hold in `TASK_STATE_WORKING` at once (the work-in-progress limit of AGSC-10-17); `enabled` a boolean, default `false`. Each object admits `x-<vendor>-<key>` keys; any other unknown key is `AGSC-E004`; an enum violation is `AGSC-E203`. The object declares the lane; its behaviour is AGSC-08-28…30. [R66, D87, PRD-063]
- **AGSC-01-37** (added at rc.4, D88) **The environment file.** Every value of `agsc.config.json` that is a secret or host-specific is configurable from the environment, and the environment is configurable from a file: a conforming tool MUST read, before anything else, an OPTIONAL `.env` file in the Bundle root — UTF-8, one `NAME=value` per line, `#` comments, no quoting or interpolation, a later line winning over an earlier one — and MUST take from it only names matching `^AGSC_[A-Z0-9_]+$`, ignoring every other line; a name already present in the process environment keeps its process value (the precedence of AGSC-09-09 becomes flags > process environment > `.env` > project configuration > user configuration). Every scalar key of AGSC-01-18 is addressable as `AGSC_` followed by its path in upper case with `_` between segments (`AGSC_BUDGET_USD_MONTH`, `AGSC_BUILD_OUT`, `AGSC_SITE_BASE`), and the named entries of `agents[]` and `channels[]` as `AGSC_AGENT_<NAME>_<KEY>` and `AGSC_CHANNEL_<NAME>_<KEY>` with the slug in upper case and `-` as `_` (`AGSC_AGENT_EDITOR_ENABLED=true`, `AGSC_AGENT_EDITOR_BUDGET_USD_MONTH=3`); a value is parsed by the schema type of the key it overrides (`true`/`false`, an integer, else a string) and a value that fails the schema is `AGSC-E201`…`E204` as if written in the file. Model credentials are environment-only — `AGSC_MODEL_API_KEY` and, for an OpenAI-compatible endpoint, `AGSC_MODEL_BASE_URL` — and MUST NOT be configuration keys, so that no Bundle file ever holds a secret (AGSC-08-15). `init` MUST write `.env` into `.gitignore` and MUST write `.env.example` listing every recognised name with an empty value; a tracked `.env` — one present in the content branch — is `AGSC-E403` (the secrets lint of AGSC-08-15) whatever it holds. The configuration input of the build function (AGSC-04-01) is the configuration **as resolved** after these overrides, and `ci` MUST print the names — never the values — of the overrides in effect, so that a reproduction can be set up from the log. [R69, D88, PRD-065, AGSC-09-09, NFR-11]
- **AGSC-01-38** (added at rc.4, D88) **The node-wide spend cap.** `budget{usd_month}` is an integer ≥ 0, default `10`, the most a node may spend on model calls of every kind in one calendar month — agent lanes (AGSC-08-28), the review lane (AGSC-08-27), automatic correction (AGSC-01-32), a narrating responder (AGSC-09-14a) and anything else that records `usage` — summed over every Episode of the month (AGSC-08-25); the sum of the enabled agents' `budget_usd_month` MUST NOT exceed it (AGSC-01-36, `AGSC-E212`); when it is reached every model-calling path MUST stop for the month with the warning `AGSC-E510`, and a tool that cannot compute the month's spend MUST NOT call a model (the rule of AGSC-01-32). The reference node keeps the default (NFR-11); `AGSC_BUDGET_USD_MONTH` overrides it per AGSC-01-37. [R70, D88, PRD-065, NFR-11]
