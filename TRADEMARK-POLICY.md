# Using the name

**In one paragraph.** AgenticSystemCore is a trademark used since 1 September
2026; it is not registered. It belongs to Andrei N. Besleaga. You may use the
name freely to refer to this project, to say truthfully that your software works
with it, and to say that your implementation conforms to a numbered version of
the specification. Please do not use it as part of your own product's name,
company name, domain name or logo, and please do not use it in a way that
suggests this project sponsors, approves or vouches for you. If you are unsure,
ask.

## What you may do, without asking

- **Refer to the project.** "Built on AgenticSystemCore", "compatible with
  AgenticSystemCore", "an AgenticSystemCore node", "imports AgenticSystemCore
  bundles". Ordinary, truthful reference is always allowed.
- **State conformance**, in the exact form
  [`docs/CONFORMANCE-STATEMENTS.md`](docs/CONFORMANCE-STATEMENTS.md) sets out,
  when your implementation passes the conformance vectors for that version and
  level.
- **Use the name in the title of an article, a talk, a tutorial or a paper**
  about the project.
- **Use the name in a package name that is clearly a plugin or an adapter**,
  where the name comes after your own, for example `yourname-agsc-adapter`.
- **Quote the specification**, with attribution, under the licences already
  published.

## Saying that you conform

Say it in exactly this form, and only when it is true for the version and the
level you name:

> «Your implementation» «version» conforms to AgenticSystemCore «spec version»,
> Level «n». It passed «passed» of «total» conformance vectors on «date».

The conformance vectors are how this name keeps its meaning: an implementation
that passes them is entitled to say so, in these words, without asking; one
that does not pass them may not use the name to describe itself as conforming.

## The attribution line

Where you use the name in documentation, a page footer or a package
description, add once:

> AgenticSystemCore™ is a trademark of Andrei N. Besleaga, used here to refer
> to the project; this work is not sponsored by, approved by or connected with it.

## What needs a conversation first

Please ask before you:

- use the name, or a name confusingly close to it, as the name of your own
  product, service, company, organisation or domain — including forms such as
  "AgenticSystemCore Pro", "AgenticSystemCore Cloud" or
  "AgenticSystemCore Enterprise";
- use the name in a logo, a badge or an icon of your own design;
- use the name in a way that states or implies that this project sponsors,
  certifies, approves or is responsible for what you offer;
- use the name for a paid certification, audit or accreditation service;
- use the name in a fork's own branding, rather than saying that your fork is
  derived from this project.

Asking is not a formality designed to say no. The reason for the line is that
a reader must always be able to tell what comes from this project and what does
not, and a small project has no way to do that except by keeping the name
attached to one thing.

## What is not allowed

- Using the name, or a name confusingly close to it, as or inside the name of
  your own product, package (other than the adapter form above), company,
  organisation, domain name or social-media handle.
- Using it so that people may think this project sponsors, certifies, approves
  or is responsible for what you offer.
- Saying "conforms", "compatible" or "certified" without the version, the level
  and the passing vectors — or at all, if the vectors do not pass.
- Registering the name, or a confusingly similar name, as a trademark,
  company name or domain name anywhere.

## What this policy does not do

- It does not restrict the software licence, the vocabulary licence or your
  right to fork. Those are separate and unaffected.
- It does not claim ownership of the ordinary words "agentic", "system" or
  "core", separately or in ordinary descriptive use.
- It does not claim ownership of the names implementers write into code: the
  well-known path name, the link relation, the profile address, the vocabulary
  namespace and the package names. Those are technical identifiers and this
  policy says nothing about them.
- It does not claim ownership of the general terms used to describe the ideas
  in the specification. Those are deliberately ordinary and are meant to be
  used by anyone.
- It makes no claim of registration anywhere, and no registration symbol
  appears in any of this project's material.

## Forks

You may fork this project. Please rename the fork. A fork that keeps the name
makes it impossible for a reader to tell whose rules a given file follows,
which is the one thing this policy exists to prevent. Saying "derived from
AgenticSystemCore, by «your name»" is welcome and accurate.

name is used and why you think it is confusing. This is also the route for

and it may be withdrawn if the use becomes misleading. Nothing in this file is
