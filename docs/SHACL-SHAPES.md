# SHACL shapes of the graph

**Who this is for:** a developer or a data engineer who wants to check the RDF graph of a node with a standard shapes language, and a maintainer who changes the schema, the relation table or the SKOS rules. **Read after:** [PROTOCOLS.md](https://github.com/andreibesleaga/agentic-system-core/blob/main/docs/PROTOCOLS.md) (where the outside standards are used) and `src/knowledge/README.md` (how the graph is built).

## Summary

`schema/item-shapes.ttl` holds [SHACL](https://www.w3.org/TR/shacl/) shapes for the RDF graph that a build writes (`graph.nq`, `graph.ttl`) and for the SKOS view of `export --skos` (`skos.ttl`). The file is generated by `tools/gen-shapes` from three sources and is never edited by hand (AGSC-05-24):

| Source | What it gives the shapes |
|---|---|
| `schema/item.schema.json` and the table of AGSC-05-26 in `spec/05-graph.md` | for each key the table maps to a datatype property: the datatype, at most one value, the closed list of the schema as `sh:in`, and `sh:minCount 1` for a key that a type of item requires (`kind` of a concept, `severity` of a lesson, `outcome` of an episode, `level` of a gate) |
| the relation table of AGSC-03-01 in `spec/03-links.md` | the Expected target kinds column as one warning for each key that names a kind (AGSC-03-25, `AGSC-E315`); the Self-link column as one warning for an item that lists itself (AGSC-03-23, `AGSC-E313`) and one error shape for each cycle (`requires` AGSC-03-07, `broader` and `narrower` AGSC-03-08) |
| the SKOS rules AGSC-05-17 to AGSC-05-21 | a concept is in the scheme and has one `skos:prefLabel` for each language tag; a concept has no `skos:member`; a collection has no `skos:broader`, `skos:narrower` or `skos:related` and is never the object of one; a concept or cluster has a definition (`AGSC-E408`); no Link points at a resource the graph does not define (`AGSC-E301`); an item has an inbound edge (`AGSC-E305`) |

The shapes are **informative**. The engine's own checks (`agsc lint`, `ci`) are the normative ones and nothing here runs at build, so a build needs no SHACL library and `npm audit` is unchanged. A shape with severity `sh:Warning` stands for a warning of `agsc lint`; every other shape stands for an error. Overlapping labels (AGSC-05-21) need Unicode case folding, which SPARQL does not have, so that check stays with the lint.

## Run the generator

```bash
node tools/gen-shapes            # writes schema/item-shapes.ttl
node tools/gen-shapes --check    # exit 1 when the committed file is not what the sources give
node tools/gen-shapes --json     # the AGSC-09-11 envelope, verb "gen-shapes"
```

The tool imports nothing from `src/` (AGSC-09-90). It shares the table and schema readers and the command line with `tools/gen-dc-profile`, its sibling; both ship in the package.

## Run the shapes (the development lane)

Running shapes needs a SHACL engine. This package ships none. The lane uses [pySHACL](https://github.com/RDFLib/pySHACL) in a scratch Python environment outside the repository, at an exact version:

```bash
python3 -m venv /tmp/shacl-env && /tmp/shacl-env/bin/pip install pyshacl==0.40.2
AGSC_SHACL_PYTHON=/tmp/shacl-env/bin/python node --test tests/tools/gen-shapes-lane.test.js
```

The test builds the six Bundles of the repository that have a configuration (the fixtures `minimal` and `with-assets` and the demonstration modes 2 to 5), exports the SKOS view of each, runs the shapes over the three graphs of each Bundle, and then runs the shapes over one negative graph for each shape that can report (`tests/shapes/negative/<shape>.ttl`, see its README). Without the variable the test is skipped. The checks that need no SHACL engine always run: the file is current, it is valid Turtle, every shape is named, every shape has its negative graph, and the shapes follow the sources (`tests/tools/gen-shapes.test.js`).

To look at a result by hand, load `schema/item-shapes.ttl` as the shapes graph and a built `graph.nq` as the data graph. A result names its source shape by IRI in the namespace `https://w3id.org/agentic-system-core/shapes#` (prefix `ascs:`); the IRI is a label for reports and is not dereferenceable. Every shape has a message that names the rule.

Two details of the lane are worth knowing before you read a result. A simple literal and an `xsd:string` literal are the same literal in RDF 1.1, but rdflib 7 keeps them apart and `graph.nq` writes the datatype where `graph.ttl` does not, so the lane turns every simple literal into an `xsd:string` literal before it validates. And SHACL reports a warning as a result, so "conforms" is false for a graph with a warning; the lane reads the severity of each result.

## What the lane has run

This is the one place that may say what has been validated by SHACL, and it says only what the lane ran. Run of 31 October 2026, pySHACL 0.40.2 (the newest release on PyPI that day; 0.40.1 had been measured on 1 October) with rdflib 7.6.0, over SHACL 1.0 and SPARQL 1.1:

- 18 graphs (the three views of six Bundles): 0 violations; 2 warnings, both the orphan check on `https://project.example/gates/merge-gate/` of the project demonstration, which `agsc lint` reports for the same item as `AGSC-E305`;
- 49 negative graphs, one for each shape that can report: each gives a result of its own shape, with the severity the shape declares.

Nothing else is claimed. A node that wants the same statement for its own graph runs the lane on it.

## Which versions of the standards

The shapes use SHACL 1.0 Core and SHACL-SPARQL (W3C Recommendation, 20 July 2017) and SPARQL 1.1. No clause that SHACL-SPARQL forbids is used (`VALUES`, `MINUS`, `SERVICE`), and none of the terms of SHACL 1.2, RDF 1.2 or SPARQL 1.2, which were drafts or candidate recommendations on 29 October 2026. A test fails if one appears.

These shapes are the engine's own. The shapes a node writes for itself, its invariants, are a different file, hand-written, and are governed by AGSC-05-41 and AGSC-09-20; they are not this lane.

## Changing the shapes

Change the source, not the file: the schema, the relation table in the specification, or the generator for the SKOS rules. Then run `node tools/gen-shapes`, add the negative graph for any new shape, and run the lane. `node tools/gen-shapes --check` is part of the test suite, so a stale file fails the build.
