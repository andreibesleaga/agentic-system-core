# SPEC — AgenticSystemCore (index of the specification)

**`spec_version: "1.0.0-rc.6"`**. This file indexes the normative material; it is not itself normative. The specification is `spec/00`–`spec/11` (numbered MUST/SHOULD rules with stable, never-reused ids `AGSC-<section>-<nn>`, some reserved: a reserved id carries no requirement and is never reused), `schema/{item,bundle,config}.schema.json`, `ontology/agsc.ttl` (classes, object properties and datatype properties — every property emitted by AGSC-05-26…28) and `tests/vectors/**` (required, optional and withdrawn cases, plus the error-code registry of §9.4). **Every count** — rules, active and reserved, error codes registered and used, vectors by level, ontology terms, populated vector areas — **is derived by `node tools/count-artifacts --json` and is deliberately not typed here** *(Rationale: this file sits inside the archived, tagged set, and a count typed here could be falsified by a later tag.)* Together they *are* the system: the Node engine is one conforming implementation, and behaviour observable only in it is a defect (NFR-02).

## 1. Sections

Every rule ends with a trace bracket that names what the rule serves: a requirement id of `docs/PRD.md` (`PRD-nnn`, `NFR-nn`, `ADR-nnn`), an external standard, or a related rule; a bracket that reads `[design]` marks a rule settled in the design review with no single listed requirement.

## 2. Versioning

SemVer 2.0.0. **MAJOR**: a file valid under the previous MAJOR may fail. **MINOR**: new optional keys, enum values or vectors. **PATCH**: clarifications and vectors conforming implementations already pass. Readers accept any Bundle of the same MAJOR, tolerate unknown keys and unknown link keys, and never reject a file for them. Released spec sections, context files and vectors are immutable; ontology terms are deprecated, never deleted (AGSC-00-14…17).

## 3. Conformance classes

Conformance is claimed by **Level** per `spec/10-implementation-profiles.md` — Level 0 Publisher (static files from any CMS/wiki), 1 Reader, 2 Writer/Exporter, 3 Full engine; the three classes below map to Levels 1–3.

**Reader** = Level 1, **Writer** = Level 2, **Full engine** = Level 3; the authoritative per-Level rule and vector-area sets are AGSC-10-02…05 and are not restated here. What a claim states — the implementation, the Level, the full `spec_version`, the cases run and passed, the Unicode version, the deployment profile, the declared surfaces and the checker used — is listed once, in AGSC-09-01.

## 5. Standardization surface

Three artefacts are this project's to standardize, and no more. The **Internet-Draft** covers only the *discovery layer*: the `knowledge-linkset` well-known URI (RFC 8615), the registered `describedby` discovery link (registered by W3C POWDER; RFC 6892 registers its inverse `describes`; no relation is requested) and this specification's extension relations inside the link set (RFC 8288 §2.1.2 URIs under w3id, so no IRI ever depends on the site domain; AGSC-06-10, AGSC-06-25), and an RFC 9264 link-set representation identified by a Profile URI (RFC 7284), presented as complementary to VoID and RFC 9727. **`spec/00`–`11` plus `tests/vectors/`** are the *format standard* — and the definition of the system itself: any language must be able to reimplement AgenticSystemCore from them alone. **`ontology/agsc.ttl` plus the JSON-LD context**, published at `https://w3id.org/agentic-system-core/ns#`, are the *vocabulary standard*. Everything else in §4 is conformance to work other people own. The `tools/` validators (PRD-054, AGSC-09-90…92) are the executable proof of §4's own rule that anything without an executable test is a claim, not conformance — which is why they import nothing from `src/`.

## 6. Spec decisions made here

1. Error codes: the single format is `AGSC-E<nnn>`, hundreds digit = area block; the registry is `spec/09-conformance.md` §9.4 and no other format (`AGSC-<AREA>-<nnn>`, `AGSC-DET-nnn`) exists anywhere.
2. No `asc:Item` superclass — "Item" is a term of the spec only (OntoClean); the ontology keeps its classes. Its two item-reachability edges (`asc:source`, `asc:review`) therefore carry no `rdfs:domain`, exactly like `asc:uses`/`asc:excludes`/`asc:contradicts` (AGSC-05-26a).
3. The well-known file is a conformant RFC 9264 link set — `linkset` is its sole member; integrity rides on the links as RFC 9530 `digest` and `agsc-*` extension target attributes, and no vendor media type exists.
4. Extension relations use the hash form `…/rel#<name>`, matching the `ns#` namespace (the hash form was chosen over a slash form).
5. The three JSON Schemas are published by the namespace document site at their `$id` URLs, `https://agenticsystemcore.com/ns/schema/{bundle,config,item}.schema.json` (AGSC-06-01); w3id stays vocabulary-only, so no registration gates them.
6. Vectors are pretty-printed with JCS *member order* rather than JCS bytes, so a reviewer can read them (AGSC-09-06).
7. The `--json` envelope is named `agsc.diagnostics.v1`; findings also appear as stderr JSON lines.
8. **Language variants are reserved to 1.1** (AGSC-01-13, 01-13a, AGSC-00-20): at 1.0 a file named `<slug>.<lang>.md` is a second use of its primary's slug, `AGSC-E206`, and no variant route is emitted; the 1.1 definition — a variant sharing the primary's slug and IRI, served at `/<type-plural>/<slug>/<lang>/` and emitted as language-tagged literals, a variant without a primary being `AGSC-E208` — is stated in AGSC-01-13.
9. `lint --fix` normalizations are enumerated and idempotent, and never reorder authored arrays.
10. Configuration is closed (`additionalProperties: false`); item frontmatter stays open (OKF tolerance). This is the only asymmetry.

11. **The ledger is derived, not appended.** `build`/`ci` recompute `ledger.jsonl` from git history into `www/` and the release assets; nothing is committed by CI, so the no-bot-commit rule (PRD-042) and a persisted ledger do not contradict, and neither an append race nor a partial write can occur. `verify --ledger` also compares the recomputed head to the `agsc-ledger-head` target attribute of the `…/rel#ledger` link in the well-known file, which is what catches a truncated tail (AGSC-08-20, 08-23).
12. **One combiner order, everywhere:** closure → `supersedes` hiding → `excludes` mutex → warnings. Hiding is "any item a result member supersedes" (AGSC-07-05; the reserved AGSC-03-17 points there), a surviving item whose `requires` target was hidden is `AGSC-E802` (AGSC-07-05a, never a silent drop), closure is breadth-first with the first-discovered path recorded, and `selection[]` is the surviving set in code-point order — so the verdict is a function of the selection *set*.
13. **One ordering per artefact.** JSON member names, `search.json` tokens included, sort by UTF-16 code units (AGSC-04-05); files and N-Quads sort by code point with `/` as the path separator on every platform; `findings[]` sorts by `(file, line, col, code)`.
14. **The tokenizer is normative** — NFC → ASCII-lower-case → split outside `[a-z0-9]` and Unicode letters/digits → drop tokens shorter than 2 → no stemming (AGSC-06-23) — because `search.json` must be byte-reproducible across ports.
15. **`prov.operator` is `human:<id>` only** (for accountability), which makes the DCO-Plus `Assisted-by:` trailer always satisfiable and completes its ABNF; adoption takes the operator from `bundle.operator`, else a normalized git `user.email` local part, else `human:unknown` with a warning, and normalizes filenames, titles and slug collisions so that `init` on bare Markdown is a total function (AGSC-01-25, 02-07, 02-90…92, 08-06).
16. **Reviews and Proposals have IRIs.** A Review is `<item-IRI>#review-<n>` with `asc:verifiedBy`/`asc:verifiedAt` datatype properties instead of `prov:wasAssociatedWith` (an actor string is not an IRI); a Proposal is its forge PR URL; `asc:verifiedOn` is `xsd:dateTime`, since `xsd:date` is outside the OWL 2 datatype map; `harness.jsonld` is declared a JSON document, not an RDF export, so its `@id`-less nodes are not blank nodes.
17. **The stated invariants are enforceable.** Cluster depth > 3 is `AGSC-E307` and a second `broader` is `AGSC-E308` (with `maxItems: 1` in the schema); anchors trim hyphens, empty becomes `section-<n>`, duplicates take the next free `-2`, `-3`, …; vectors are pretty-printed under AGSC-09-06 only (AGSC-04-04 does not list them) and a superseded vector is republished `withdrawn`; `AGSC-E203` takes precedence over `AGSC-E201`; `AGSC-E603` exits 2; `SOURCE_DATE_EPOCH` defaults to 0 with `AGSC-E606` when there is no git history; `deprecated → stable` is legal with a warning.

18. **`AGSC-06-01` is the normative route set** and supersedes PRD-011's route list, which is illustrative; the route-snapshot fixture of PRD-011 is generated from AGSC-06-01. Its 1.x additions over that list — `/tags/<tag>/`, `/changelog/`, `/robots.txt`, `/.well-known/tdmrep.json`, `/pages/*`, `/episodes/`, `/gates/`, `/procedures/`, `/ledger.jsonl`, `/.well-known/security.txt` — are recorded here rather than left to inference. `/feed.xml` is not a 1.0 route, because no 1.0 rule pins a feed's bytes (AGSC-06-01, AGSC-00-20's 1.1 list).
19. **Export is specified** (`spec/01` §1.6, AGSC-01-26…29): Markdown/OKF export is lossless and vault-openable, `--jsonld` is byte-identical to `graph.jsonld`, `--steer` derives only from NOW and Concept/Procedure/Gate/Lesson items, and every prose-carrying export embeds the Content Use Terms — the steer bundles are governed exactly like `llms.txt`.
20. **`graph.ttl` is reproducible from `spec/` alone** (AGSC-05-26…28): every `asc:` property has one named frontmatter source, and a term with no emitting rule does not ship — there is no `asc:verdict`, since a verdict lives in the forge.
21. **The drop-in path passes its own gate**: `description` is schema-optional everywhere and lint-required on concept/cluster as `AGSC-E408`; AGSC-02-93 relocates adopted files to `content/concepts/<slug>.md` with the original path in `aliases[]`; `adopt/` vectors prove it.

22. **Adoption reaches a green `ci`**: `config.schema.json` and `bundle.schema.json` accept a trailing slash and the development placeholder `http://localhost[:port]/`; `AGSC-02-94` synthesizes only schema-valid values (`build.out: "www/"`, an index title through the AGSC-02-90 title rule, a ≥40-character description); `adopt-0007` proves that `init`, the publisher's security contact (AGSC-06-36) and `ci` exit 0 on a bare folder, warnings only, and `adopt-0008` that `ci` refuses the folder with `AGSC-E901` until that file exists (amended for 1.0.0; `adopt-0006`, which claimed a green `ci` immediately after `init`, is withdrawn).
23. **The derived ledger is byte-reproducible** (`AGSC-08-20a`): the first-parent chain oldest-first from the git-log file, `kind` = `release`/`merge`/`commit` by tag, parent count or `Proposal:` trailer, `actor` from `Signed-off-by`, `ref` the full sha, `ts` the committer time — then exactly **one** trailing `build` entry from `SOURCE_DATE_EPOCH` and the `content/` tree hash, so local and CI builds of one history agree. Genesis `prev` is 64 zeros; an empty history yields the build entry alone; a shallow clone is `AGSC-E703`, exit 2. Vectors `ledger-0005`/`ledger-0003`.
24. **Level 0 is attainable** (`AGSC-06-08a`): a Level-0 link set is the same document with every `digest`/`agsc-*` attribute omitted; Levels ≥2 require them. Vector `disc-0004`.
25. **The `auto` channel merge is a configured, revocable, single exception**: it is **`AGSC-08-26`**, and `AGSC-08-02` and `AGSC-08-08` name the exception; the guard is checked against configuration and forge identity — never self-declared frontmatter — with the agent-safety lints at `error` severity, the channel owner's separate merge credential `CHANNEL_MERGE_TOKEN_<name>` in `review.yml`'s `auto-merge` job (never the ingest job's `CHANNEL_TOKEN_<name>`), and a `Channel-Auto:` trailer feeding the ledger's `mode`.

## 8. Frozen v1.0 — forward compatibility
The schema (`schema/*.json`), ontology (`ontology/agsc.ttl`, `owl:versionIRI …/ns/1.0.0-draft.1` until the spec reaches `1.0.0`), protocol (`/.well-known/knowledge-linkset` = an RFC 9264 link set with RFC 9530 `digest` target attributes under `application/linkset+json` + the RFC 7284 Profile URI; relations incl. `peer`) and `spec/00–11` are **complete for v1.0** at `spec_version 1.0.0` (this file states the current release candidate, `1.0.0-rc.6`). Forward-compatibility mechanisms, fixed now: (1) **registered Link keys** — the fourteen keys (nine core + five Mode-2) are closed at 1.x; new keys arrive only via a minor `spec_version` bump with a registry entry and vectors; (2) **`x-` frontmatter namespace** — any `x-<vendor>-<key>` is preserved verbatim by every conforming tool and never interpreted (AGSC-02 tolerance); the same `x-<vendor>-<key>` namespace is also open in `agsc.config.json` — `config.schema.json` admits `^x-[a-z0-9]+(-[a-z0-9]+)+$` through `patternProperties` at the top level and on each `channels[]` entry while `additionalProperties` stays `false` (AGSC-01-18, the frontmatter twin being AGSC-02-05a) — so a v2 hosted adapter registers itself under `x-<vendor>-*` or `channels[].x-<vendor>-*` and no new configuration key is needed. **BCP 178 (RFC 6648) advises against `X-`-style prefixes and recommends a registry instead** — §3: implementers "SHOULD NOT prefix their parameter names with 'X-' or similar constructs"; §4: designers "MUST NOT stipulate that a parameter with an 'X-' prefix or similar constructs needs to be understood as unstandardized" (read 2026-09-19). This specification keeps the `x-<vendor>-<key>` namespace deliberately: at 1.x there is no registry operator and no registration procedure, and the alternative — an unprefixed vendor key inside a closed object — collides with the next MINOR. A registry for extension keys is the 1.1 replacement (AGSC-00-20), at which point `x-` becomes the deprecated form. `build.feed` and `build.rdfxml` are reserved names, rejected with `AGSC-E004` (AGSC-01-18); (3) **SemVer** (AGSC-00-14) — PATCH = clarified text or added cases that conforming implementations already pass; MINOR = added optional keys, enumeration values, Link semantics or cases; MAJOR = a valid file may fail (none planned); readers accept any 1.x Bundle except a configuration key their version does not know (AGSC-00-15); (4) **Levels** (spec/10) let implementations conform incrementally; (5) **error-code registry** is append-only. The Internet-Draft is written against this frozen spec; a v2 change is admissible only for a discovered gap and is itself a registered minor bump.

**What `1.0.0-rc.6` contains.** Besides the core of `spec/00`–`10`: `spec/11-boundary.md` — cross-origin access, federation in eight parts (F1, F2, F4–F9), the plugin contract, visibility and dynamic hooks, retirement and tombstones; the agent lane of §8.6 (AGSC-08-28…30, with `--dry-run`) and the node-wide cap `budget{usd_month}` (AGSC-01-38) metered by AGSC-08-25; Mode 5 — the live board of §10.6 (AGSC-10-16…18), discoverable through `…/rel#boards` (AGSC-06-10, AGSC-10-13); the compatibility and plugin section §0.6 — what a 1.x reader does with a construct it does not know (AGSC-00-21), the round trip (AGSC-00-22), a tool originating only what its version specifies (AGSC-00-23), the closed list of eight plugin kinds (AGSC-00-24) and the three names reserved to 1.1 (AGSC-00-25); the content version of §4.9 (AGSC-04-25), one derived, human-readable name for the state a build published; the bytes of the `--zip` archive (AGSC-07-13a); the content of `/.well-known/security.txt` (AGSC-06-36); the crawler list `site.tdm_crawlers[]` of the robots dialect (AGSC-06-18); and the declared scope by version (AGSC-00-20), which names what becomes normative at 1.1 — among it language variants (AGSC-01-13), SHACL shape generation, an extension-key registry and `/feed.xml`. Determinism is pinned for the machine artefacts: `-0` is written as `0` (AGSC-04-05), NFC precedes canonicalization, member names are NFC before sorting, the vectors are generated against Unicode **16.0.0**, a combining sequence is bounded at 256 marks (`AGSC-E607`), no schema pattern uses a lookahead, and every length bound counts code points. The Content Use Terms text is `LICENSE-CONTENT`, and AGSC-06-18 pins it — the identifier `LicenseRef-AgenticSystemCore-Content-Use-1.0` names the bytes of `LICENSE-CONTENT` whose SHA-256 is `b2e8da62e6a41886296d2d2358fb4642cc7418e806eb4a29ada12b588ac32857`; a distribution shipping different text MUST use a different identifier. A released vector is never edited: one that no longer states the rules is republished `withdrawn` and MAY carry `superseded_by` (AGSC-09-04).
