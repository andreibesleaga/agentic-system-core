# SPEC — AgenticSystemCore (index of the specification)

**`spec_version: "1.0.0-rc.6"`** (rc.3, rc.4 and rc.5 are frozen at their tags; rc.6 was drafted on 2026-09-22 and applies the items recorded against the frozen text since the rc.5 tag). This file indexes the normative material; it is not itself normative. The specification is `spec/00`–`spec/11` (numbered MUST/SHOULD rules with stable, never-reused ids `AGSC-<section>-<nn>`, some retired-and-reserved after the rc.3 minimality pass), `schema/{item,bundle,config}.schema.json`, `ontology/agsc.ttl` (classes, object properties and datatype properties — every property emitted by AGSC-05-26…28) and `tests/vectors/**` (required, optional and withdrawn cases, plus the error-code registry of §9.4). **Every count** — rules, active and reserved, error codes registered and used, vectors by level, ontology terms, populated vector areas — **is derived by `node tools/count-artifacts --json` and is deliberately not typed here** *(amended at rc.5: the header carried hard numbers and a "tracks the working tree" clause, while this file sits inside the archived, tagged set whose SHA-256 the paper prints — a typed count there can be falsified by the next tag, and one was)*. *(Historical: the rc.2 freeze of 2026-09-04 recorded 270 rules, 44 terms and 56 vectors.)* Together they *are* the system: the Node engine is one conforming implementation, and behaviour observable only in it is a defect (NFR-02).

## 2. Versioning

SemVer 2.0.0. **MAJOR**: a file valid under the previous MAJOR may fail. **MINOR**: new optional keys, enum values or vectors. **PATCH**: clarifications and vectors conforming implementations already pass. Readers accept any Bundle of the same MAJOR, tolerate unknown keys and unknown link keys, and never reject a file for them. Released spec sections, context files and vectors are immutable; ontology terms are deprecated, never deleted (AGSC-00-14…17).

## 3. Conformance classes

> **Amendment 2026-09-02 (PRD-055):** conformance is claimed by **Level** per `spec/10-implementation-profiles.md` — Level 0 Publisher (static files from any CMS/wiki), 1 Reader, 2 Writer/Exporter, 3 Full engine; the three classes below map to Levels 1–3.

**Reader** = Level 1, **Writer** = Level 2, **Full engine** = Level 3; the authoritative per-Level rule and vector-area sets are AGSC-10-02…05 and are not restated here. A claim names the class, the `spec_version` MAJOR.MINOR and the vector set passed (AGSC-00-09…13).

## 5. Standardization surface

Three artefacts are ours to standardize, and no more. The **Internet-Draft** covers only the *discovery layer*: the `knowledge-linkset` well-known URI (RFC 8615), the registered `describedby` discovery link (registered by W3C POWDER; RFC 6892 registers its inverse `describes`; no relation is requested) and our extension relations inside the link set (RFC 8288 §2.1.2 URIs under w3id, so no IRI ever depends on the site domain; AGSC-06-10, AGSC-06-25), and an RFC 9264 link-set representation identified by a Profile URI (RFC 7284), presented as complementary to VoID and RFC 9727. **`spec/00`–`11` plus `tests/vectors/`** are the *format standard* — and the definition of the system itself: any language must be able to reimplement AgenticSystemCore from them alone. **`ontology/agsc.ttl` plus the JSON-LD context**, published at `https://w3id.org/agentic-system-core/ns#`, are the *vocabulary standard*. Everything else in §4 is conformance to work other people own. The `tools/` validators (PRD-054, AGSC-09-90…92) are the executable proof of §4's own rule that anything without an executable test is a claim, not conformance — which is why they import nothing from `src/`.

## 6. Spec decisions made here

1. Error codes: the single format is `AGSC-E<nnn>`, hundreds digit = area block; the registry is `spec/09-conformance.md` §9.4 and no other format (`AGSC-<AREA>-<nnn>`, `AGSC-DET-nnn`) exists anywhere — the plan and the diagrams were corrected to match.
2. No `asc:Item` superclass — "Item" is a term of the spec only (OntoClean); the ontology keeps its classes (12 at rc.4). Its two item-reachability edges (`asc:source`, `asc:review`) therefore carry no `rdfs:domain`, exactly like `asc:uses`/`asc:excludes`/`asc:contradicts` (AGSC-05-26a).
3. The well-known file is a conformant RFC 9264 link set — `linkset` is its sole member; integrity rides on the links as RFC 9530 `digest` and `agsc-*` extension target attributes, and no vendor media type exists.
4. Extension relations use the hash form `…/rel#<name>`, matching the `ns#` namespace (the hash form was chosen over a slash form).
5. The three JSON Schemas are published by the namespace document site at their `$id` URLs, `https://agenticsystemcore.com/ns/schema/{bundle,config,item}.schema.json` (AGSC-06-01); w3id stays vocabulary-only, so no registration gates them.
6. Vectors are pretty-printed with JCS *member order* rather than JCS bytes, so a reviewer can read them (AGSC-09-06).
7. The `--json` envelope is named `agsc.diagnostics.v1`; findings also appear as stderr JSON lines (the plan left the shape open).
8. **Language variants are accepted at 1.0**: `<slug>.<lang>.md` shares the primary's slug and IRI, is served at `/<type-plural>/<slug>/<lang>/` and is emitted as language-tagged literals; a variant without a primary is `AGSC-E208` (AGSC-01-13, 01-13a).
9. `lint --fix` normalizations are enumerated and idempotent, and never reorder authored arrays.
10. Configuration is closed (`additionalProperties: false`); item frontmatter stays open (OKF tolerance). This is the only asymmetry.

*Decisions 11–17 were added 2026-09-02, resolving the 34 findings of a mathematical and algorithmic verification.*

11. **The ledger is derived, not appended.** `build`/`ci` recompute `ledger.jsonl` from git history into `www/` and the release assets; nothing is committed by CI, so the no-bot-commit rule (PRD-042) and a persisted ledger no longer contradict, and neither an append race nor a partial write can occur. `verify --ledger` also compares the recomputed head to the `agsc-ledger-head` target attribute of the `…/rel#ledger` link in the well-known file, which is what catches a truncated tail (AGSC-08-20, 08-23).
12. **One combiner order, everywhere:** closure → `supersedes` hiding → `excludes` mutex → warnings. Hiding is "any item a result member supersedes" (AGSC-07-05 wins over the old reachability wording of the retired AGSC-03-17), a surviving item whose `requires` target was hidden is `AGSC-E802` (AGSC-07-05a, never a silent drop), closure is breadth-first with the first-discovered path recorded, and `selection[]` is the surviving set in code-point order — so the verdict is a function of the selection *set*.
13. **One ordering per artefact.** JSON member names, `search.json` tokens included, sort by UTF-16 code units (AGSC-04-05); files and N-Quads sort by code point with `/` as the path separator on every platform; `findings[]` sorts by `(file, line, col, code)`. The old "search tokens by code point" wording was the system's only two-order artefact.
14. **The tokenizer is normative** — NFC → ASCII-lower-case → split outside `[a-z0-9]` and Unicode letters/digits → drop tokens shorter than 2 → no stemming (AGSC-06-23) — because `search.json` must be byte-reproducible across ports.
15. **`prov.operator` is `human:<id>` only** (for accountability), which makes the DCO-Plus `Assisted-by:` trailer always satisfiable and completes its ABNF; adoption takes the operator from `bundle.operator`, else a normalized git `user.email` local part, else `human:unknown` with a warning, and normalizes filenames, titles and slug collisions so that `init` on bare Markdown is a total function (AGSC-01-25, 02-07, 02-90…92, 08-06).
16. **Reviews and Proposals have IRIs.** A Review is `<item-IRI>#review-<n>` with `asc:verifiedBy`/`asc:verifiedAt` datatype properties instead of `prov:wasAssociatedWith` (an actor string is not an IRI); a Proposal is its forge PR URL; `asc:verifiedOn` is `xsd:dateTime`, since `xsd:date` is outside the OWL 2 datatype map; `harness.jsonld` is declared a JSON document, not an RDF export, so its `@id`-less nodes are not blank nodes.
17. **The stated invariants are now enforceable.** Cluster depth > 3 is `AGSC-E307` and a second `broader` is `AGSC-E308` (with `maxItems: 1` in the schema); anchors trim hyphens, empty becomes `section-<n>`, duplicates take the next free `-2`, `-3`, …; vectors are pretty-printed under AGSC-09-06 only (AGSC-04-04 no longer lists them) and a superseded vector is republished `withdrawn`; `AGSC-E203` takes precedence over `AGSC-E201`; `AGSC-E603` exits 2; `SOURCE_DATE_EPOCH` defaults to 0 with `AGSC-E606` when there is no git history; `deprecated → stable` is legal with a warning.

*Decisions 18–21 were added 2026-09-02 from a system-of-systems review.*

18. **`AGSC-06-01` is the normative route set** and supersedes PRD-011's route list, which is illustrative; the route-snapshot fixture of PRD-011 is generated from AGSC-06-01. Its 1.x additions over that list — `/tags/<tag>/`, `/changelog/`, `/robots.txt`, `/.well-known/tdmrep.json`, `/pages/*`, `/episodes/`, `/gates/`, `/procedures/`, `/ledger.jsonl`, `/.well-known/security.txt` — are recorded here rather than left to inference. (`/feed.xml` was on that list until rc.5 and was removed, because no 1.0 rule pins a feed's bytes — see AGSC-06-01 and AGSC-00-20's 1.1 list.)
19. **Export is specified** (`spec/01` §1.6, AGSC-01-26…29): Markdown/OKF export is lossless and vault-openable, `--jsonld` is byte-identical to `graph.jsonld`, `--steer` derives only from NOW and Concept/Procedure/Gate/Lesson items, and every prose-carrying export embeds the Content Use Terms — the steer bundles are governed exactly like `llms.txt`.
20. **`graph.ttl` is reproducible from `spec/` alone** (AGSC-05-26…28): every `asc:` property has one named frontmatter source, and a term with no emitting rule does not ship — `asc:verdict` was deleted, since a verdict lives in the forge.
21. **The drop-in path passes its own gate**: `description` is schema-optional everywhere and lint-required on concept/cluster as `AGSC-E408`; AGSC-02-93 relocates adopted files to `content/concepts/<slug>.md` with the original path in `aliases[]`; `adopt/` vectors prove it.

*Decisions 22–25 were added 2026-09-03 from a re-verification after the fixes.*

22. **Adoption reaches a green `ci`**: `config.schema.json` and `bundle.schema.json` accept a trailing slash and the development placeholder `http://localhost[:port]/`; `AGSC-02-94` synthesizes only schema-valid values (`build.out: "www/"`, an index title through the AGSC-02-90 title rule, a ≥40-character description); `adopt-0004` proves `init` → `ci` exits 0 on a bare folder, warnings only.
23. **The derived ledger is byte-reproducible** (`AGSC-08-20a`): the first-parent chain oldest-first from the git-log file, `kind` = `release`/`merge`/`commit` by tag, parent count or `Proposal:` trailer, `actor` from `Signed-off-by`, `ref` the full sha, `ts` the committer time — then exactly **one** trailing `build` entry from `SOURCE_DATE_EPOCH` and the `content/` tree hash, so local and CI builds of one history agree. Genesis `prev` is 64 zeros; an empty history yields the build entry alone; a shallow clone is `AGSC-E703`, exit 2. Vectors `ledger-0005`/`ledger-0003`.
24. **Level 0 is attainable** (`AGSC-06-08a`): a Level-0 link set is the same document with every `digest`/`agsc-*` attribute omitted; Levels ≥2 require them. Vector `disc-0004`.
25. **The `auto` channel merge is a configured, revocable, single exception**: the duplicate `AGSC-08-25` is renumbered **`AGSC-08-26`**; `AGSC-08-02` and `AGSC-08-08` name the exception; the guard is checked against configuration and forge identity — never self-declared frontmatter — with the agent-safety lints at `error` severity, the channel owner's `CHANNEL_TOKEN_<name>` in `review.yml`'s `auto-merge` job, and a `Channel-Auto:` trailer feeding the ledger's `mode`.

## 8. Frozen v1.0 — forward compatibility (2026-09-03)
The schema (`schema/*.json`), ontology (`ontology/agsc.ttl`, `owl:versionIRI …/ns/1.0.0-draft.1` until the spec reaches `1.0.0`), protocol (`/.well-known/knowledge-linkset` = an RFC 9264 link set with RFC 9530 `digest` target attributes under `application/linkset+json` + the RFC 7284 Profile URI; relations incl. `peer`) and `spec/00–11` are **complete for v1.0** at `spec_version 1.0.0` (this file tracks the current release candidate, `1.0.0-rc.6`, until the first tagged release; rc.3, rc.4 and rc.5 stay frozen at their own tags, and rc.6 amends the text of rules whose ids are permanent and adds one rule — it retires and renumbers nothing). Forward-compatibility mechanisms, fixed now: (1) **registered Link keys** — the fourteen keys (nine core + five Mode-2) are closed at 1.x; new keys arrive only via a minor `spec_version` bump with a registry entry and vectors; (2) **`x-` frontmatter namespace** — any `x-<vendor>-<key>` is preserved verbatim by every conforming tool and never interpreted (AGSC-02 tolerance); since rc.2 the same `x-<vendor>-<key>` namespace is also open in `agsc.config.json` — `config.schema.json` admits `^x-[a-z0-9]+(-[a-z0-9]+)+$` through `patternProperties` at the top level and on each `channels[]` entry while `additionalProperties` stays `false` (AGSC-01-18, the frontmatter twin being AGSC-02-05a) — so a v2 hosted adapter registers itself under `x-<vendor>-*` or `channels[].x-<vendor>-*` and no new configuration key is needed. **BCP 178 (RFC 6648) advises against `X-`-style prefixes and recommends a registry instead** — §3: implementers "SHOULD NOT prefix their parameter names with 'X-' or similar constructs"; §4: designers "MUST NOT stipulate that a parameter with an 'X-' prefix or similar constructs needs to be understood as unstandardized" (read 2026-09-19). This specification keeps the `x-<vendor>-<key>` namespace deliberately: at 1.x there is no registry operator and no registration procedure, and the alternative — an unprefixed vendor key inside a closed object — collides with the next MINOR. A registry for extension keys is the 1.1 replacement (AGSC-00-20), at which point `x-` becomes the deprecated form. (Added at rc.5: the tradeoff was taken and never written down, and it is the first thing a W3C CG or an ISE reviewer of the *format* will raise.) The only keys added at rc.2 were `channels[].allow[]` and `channels[].rate{per_hour}`; rc.3 adds `federation{}`, `chunks{}`, `contribute[]`, `visibility` and `attachments{}` (AGSC-01-18, AGSC-11-01, AGSC-01-34); rc.4 adds `agents[]` and `budget{usd_month}`; rc.5 adds `federation.max_bytes` and **removes `build.feed`**, which becomes a reserved name rejected with `AGSC-E004` beside `build.rdfxml` (the one change of rc.5 that makes a previously valid configuration invalid); (3) **SemVer** — patch = editorial, minor = additive rules/keys/routes, major = breaking (none planned); readers MUST accept any 1.x Bundle; (4) **Levels** (spec/10) let implementations conform incrementally; (5) **error-code registry** is append-only. The Internet-Draft is written against this frozen spec; a v2 change is admissible only for a discovered gap and is itself a registered minor bump.
